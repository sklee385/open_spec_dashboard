# 같은 대화로 업무 진행하기

1. 개발 화면 `http://127.0.0.1:13001`에서 프로젝트를 선택한다. 아이디어를 열고 변경 이름을 입력해 업무를 시작하거나 기존 변경 카드를 연다.
2. 대화에 요구사항을 입력한다. ‘AI와 계획 작성·수정’은 제품 코드 구현 없이 OpenSpec 문서를 작성한다. 확인 질문은 선택지나 자유 입력으로 답한다. 실행 승인은 요구사항 답변과 별도 카드에서 처리한다.
3. 문서 탭에서 제안서·설계·명세·작업 목록을 읽고 직접 수정·저장하거나 AI에 수정 의견을 보낸다. AI 요청에는 현재 문서 경로와 저장 버전이 함께 전달된다.
4. 최신 문서를 확인한 뒤 ‘최신 문서 검토 완료’, ‘구현 시작’을 누른다. 구현 중 추가 메시지는 같은 대화의 대기열에 들어간다. 중단 요청은 실제 중단 확인 후 후속 실행을 허용한다.
5. 코드·실행·검증 탭에서 변경 전후 파일과 검증 명령·출력을 확인한다. 실행 파일과 인자를 따로 등록한다. 인자는 한 줄에 하나씩 입력한다. 명령은 프로젝트 폴더에서 셸 해석 없이 실행된다.
6. 결과에 질문·수정 의견을 보내고 다시 검증한다. 파일이나 검증 명령이 바뀌면 이전 통과는 과거 결과로 표시된다. 작업·질문·문서 검토·최신 필수 검증이 모두 준비되면 ‘결과 확인·완료’로 최종 확인한다.
7. 완료 후 추가 문답은 ‘다시 문답·수정’을 누른다. ‘OpenSpec 보관’은 CLI 실행 결과와 실제 변경 폴더 이동을 확인한다. 보관 문서와 같은 업무 이력은 보관 카드에서도 읽을 수 있다.

## 문서와 초안 보호

아이디어를 업무로 전환하면 원본 아이디어 제목을 유지한 카드가 ‘초안’ 열에 표시된다. 제안서·설계·명세·작업 목록이 아직 없더라도 업무를 숨기지 않는다. 이후 Todo·In Progress·Done으로 이동해도 같은 업무 ID와 카드 접근을 유지하며, 보관한 업무는 보관 보기를 켜서 확인한다. 제목과 OpenSpec 변경 이름 모두 검색할 수 있다.

미저장 상태에서는 문서 이동 시 저장·폐기·취소를 선택한다. AI 요청 전에도 먼저 저장한다. 초안은 브라우저의 업무·문서별 로컬 저장소에 보존된다. 새로고침 후 다시 불러온다.

AI나 다른 편집기가 먼저 저장했다면 충돌 화면에서 최신 문서와 내 초안을 비교한다. 최신 내용을 사용하거나, 편집기에서 초안을 조정한 뒤 ‘최신 버전에 내 초안 재적용’을 선택한다. 재적용 중 다른 저장이 발생하면 다시 충돌 처리한다.

구현 뒤 계획이 수정되면 재검토가 필요하다. ‘AI와 계획 작성·수정’으로 문서 문답을 이어가고 최신 문서를 검토한 뒤 구현을 다시 시작한다. 작업 체크박스만 완료로 바꾸는 경우에는 검토를 무효화하지 않는다.

## OpenSpec 정보

OpenSpec 탭의 산출물·의존성, 다음 작성 지침, 워크플로, 기준 명세 목록, 변경 명세, 요구사항 차이, 문서 검증, 관계 진단, 프로젝트 관계는 실제 설치 CLI 결과를 표시한다. 작성 지침에는 `proposal`, `design`, `specs`, `tasks`, `apply`, `archive` 등을 입력한다. 미지원·실패 결과는 오류와 stderr로 표시한다.

문서 검증은 코드 테스트와 별개다. 오류 내용을 같은 대화에 붙여 수정 요청을 이어갈 수 있다. 보관으로 기준 명세를 반영한 뒤 보드의 명세 보기에서 결과를 확인한다.

## 재연결과 복구

- 새로고침 시 마지막 업무와 저장 초안을 복원한다. 실시간 연결이 끊기면 재연결 상태를 표시하고 주기 조회로 보완한다.
- 서버 재시작 후 저장한 `threadId`로 대화를 재개한다. 복원 실패 시 ID를 보존하며 새 대화를 자동 생성하지 않는다.
- 대화 생성 결과가 불명확하고 ID가 없다면 자동 재시작하지 않는다. Codex의 기존 대화 기록을 대조한 뒤 관리자가 복구해야 한다.
- 연결 종료로 무효가 된 질문은 만료 표시와 함께 남는다. ‘같은 대화로 답변 복구’는 새 요청 ID에 답을 잘못 보내지 않고 기존 대화의 후속 메시지로 답변을 전달한다. 문서에 반영한 뒤 다시 검토한다.
- 답변 이력의 ‘문서 변경 감지’는 파일 해시 변경의 증거다. 요구사항이 올바르게 반영됐는지는 문서를 직접 검토한다. 문서 변경이 없으면 ‘반영 확인 필요’로 표시한다.
- 검증 도중 서버가 종료되면 해당 실행은 중단 상태이며 통과로 사용하지 않는다. 같은 업무에서 다시 실행한다.

## 백업과 기존 설치본으로 복귀

서버를 중지한 뒤 `config.local.json`, `.data/work.sqlite` 및 남아 있는 `work.sqlite-wal`·`work.sqlite-shm`, 각 프로젝트의 `openspec/`와 변경 코드를 함께 백업한다. SQLite를 사용 중일 때 DB 파일 하나만 복사하지 않는다. 설정과 DB를 같은 시점의 백업으로 복원한다.

새 앱은 13001/13002, 기존 설치본은 13000을 사용한다. 새 앱에 문제가 있으면 해당 프로세스를 중지하고 13000으로 돌아갈 수 있다. AI가 작성한 코드·문서는 자동으로 되돌리지 않으며 변경 내용을 검토한다. `.data/e2e/`와 `session-demo` 소스는 별도 검증용 자료다.

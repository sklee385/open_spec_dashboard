# 같은 대화로 업무 진행하기

## 소스 등록과 프로그램 설정

헤더의 **소스 관리**를 열어 등록된 OpenSpec 소스의 이름과 경로를 확인한다. 모바일에서는 **메뉴 → 소스 관리**로 연다. 이름과 OpenSpec 디렉터리 경로를 입력해 **소스 추가**를 누르면 즉시 저장된다. 조회 실패 시 **다시 시도**로 복구하고, 존재하지 않는 경로는 등록되지 않았다는 안내를 확인한다.

소스의 **등록 해제**는 관리 목록에서만 제거하며 원본 폴더와 파일은 삭제하지 않는다. 현재 선택한 소스를 해제하면 필터가 **전체 프로젝트**로 돌아가고 소스 선택 목록과 보드·명세·아이디어가 갱신된다. 다른 소스를 변경하면 현재 선택은 유지된다.

**설정**에는 AI 도구 선택·등록 등 프로그램 설정이 있다. 소스 등록은 **소스 관리**, 프로젝트 파일 편집과 Git 작업은 **소스·Git**에서 진행한다. 소스 관리 창은 키보드로 탐색하고 Escape로 닫을 수 있으며 닫은 뒤 진입점으로 초점이 돌아간다.

## 변경 파일 확인과 원본 반영

‘결과’ 탭에서 업무별 변경 파일 목록을 열면 추가·수정·삭제 상태와 전후 줄 번호, 바뀐 줄, 문맥 펼치기 및 전체 코드 보기를 확인한다. ‘현재 변경’은 이 업무 전용 폴더의 현재 상태이며 ‘완료 당시 변경’은 완료 시 보존한 결과다. 완료 후 다른 작업으로 원본이 바뀌거나 업무가 보관되어도 과거 결과는 바뀌지 않는다.

구현·재개·검증은 원본과 분리된 업무 전용 공간에서 수행한다. 실행 전 이미 존재하던 변경은 기준에 포함되어 새 업무 변경으로 나오지 않는다. 필수 검증을 통과한 결과를 확인하고 **원본에 반영**을 별도로 요청한다. 원본의 같은 경로가 다른 작업으로 바뀌었으면 충돌로 표시하며 자동 덮어쓰지 않는다. 충돌을 해결한 뒤 다시 요청한다. 반영 도중 중단되면 같은 동작으로 저널에 따라 복구한다. 원본 반영 성공 후 업무 완료를 별도로 확인한다. 완료 버튼은 자동 반영하지 않는다.

과거 업무에 격리 기준이 없으면 ‘업무별 변경 기록이 없습니다’로 표시한다. 이는 변경 파일이 0개라는 뜻이 아니다. 기존 진행 업무의 ‘업무 전용 공간으로 전환’은 전환 시점부터 새 기준을 만든다. 이전 변경의 작성 주체를 추정하지 않는다. 완료 결과가 없는 과거 완료 업무는 현재 파일로 소급 복원하지 않는다.

바이너리, 200,000바이트 이상 파일은 변경 상태와 텍스트 비교 불가 이유를 표시한다. 빈 파일과 파일 부재는 구분한다. 심볼릭 링크, `.git`, `.data`, `.reference`, `.tools`, `.logs`, `.idea-trash`, `node_modules`, `dist`, `.nuxt`, `.output`, `*.tsbuildinfo`는 수집에서 제외한다. `tasks.md` 체크박스만 바뀐 경우 변경 목록에서는 제외하지만 해당 업무의 진행 상태는 원본 반영 시 함께 전달한다.

## 실행 명령 (Volta 권한 오류 방지)

서버 시작은 `./scripts/start.ps1`, npm은 `./scripts/npm.ps1`, Node는 `./scripts/node.ps1`을 사용한다. 프로젝트의 `.tools/node-runtime` 실행 파일을 직접 사용하므로 시스템 Volta 폴더 쓰기 권한이 필요 없다. 이미 실행 중인 서버는 시작 스크립트가 유지한다.

웹 서버(13002)와 대화·AI 실행을 소유하는 상주 세션 서버(13003)를 독립 실행한다. 평소 코드 수정 후에는 `./scripts/restart.ps1 -Service backend`로 웹 서버만 재시작한다. 브라우저는 자동 재연결하며 실행 중인 Codex와 질문·승인 요청은 세션 서버에서 유지된다. 세션 서버의 코드 자체를 바꾸었다면 업무가 멈춘 뒤 `./scripts/restart.ps1 -Service session`으로 반영한다. 실행·답변·승인 대기가 있으면 이 명령은 종료를 보류한다.

세션 서버까지 종료됐다면 기존 대화 ID로 연결만 자동 복구한다. ID 조회가 실패하더라도 검증한 원본 대화 파일이 있으면 같은 기록을 재개한다. 중단된 명령·메시지는 자동 재전송하지 않는다. 작성 중인 대화·질문 답변도 업무별 브라우저 저장소에 보존한다.

다른 PC에서 런타임을 준비하려면 설치된 Node 배포 폴더를 `./scripts/setup-runtime.ps1 -NodeDirectory <폴더>`로 지정한다. 원본은 읽기만 하고 Node/npm을 프로젝트 안으로 복사한다. `.tools`는 Git에 포함하지 않는다. 백엔드의 Codex 자식 프로세스와 기본 검증 명령도 이 런타임을 우선 사용한다. 실행 중인 Codex 프로세스는 기존 환경을 유지하므로 새 설정은 백엔드 재시작 뒤 새 Codex 연결부터 적용된다.

1. 개발 화면 `http://127.0.0.1:13001`에서 프로젝트를 선택한다. 아이디어를 열고 변경 이름을 입력해 업무를 시작하거나 기존 변경 카드를 연다.
2. 대화에 요구사항을 입력한다. ‘AI와 계획 작성·수정’은 제품 코드 구현 없이 OpenSpec 문서를 작성한다. 확인 질문은 선택지나 자유 입력으로 답한다. 실행 승인은 요구사항 답변과 별도 카드에서 처리한다.
3. 문서 탭에서 제안서·설계·명세·작업 목록을 읽고 직접 수정·저장하거나 AI에 수정 의견을 보낸다. AI 요청에는 현재 문서 경로와 저장 버전이 함께 전달된다.
4. 최신 문서를 확인한 뒤 ‘최신 문서 검토 완료’, ‘구현 시작’을 누른다. 구현 중 추가 메시지는 같은 대화의 대기열에 들어간다. 중단 요청은 실제 중단 확인 후 후속 실행을 허용한다.
5. 코드·실행·검증 탭에서 변경 전후 파일과 검증 명령·출력을 확인한다. 실행 파일과 인자를 따로 등록한다. 인자는 한 줄에 하나씩 입력한다. 명령은 프로젝트 폴더에서 셸 해석 없이 실행된다.
6. 결과에 질문·수정 의견을 보내고 다시 검증한다. 파일이나 검증 명령이 바뀌면 이전 통과는 과거 결과로 표시된다. 작업·질문·문서 검토·최신 필수 검증이 모두 준비되면 ‘결과 확인·완료’로 최종 확인한다.
7. 완료 후 추가 문답은 ‘다시 문답·수정’을 누른다. ‘OpenSpec 보관’은 CLI 실행 결과와 실제 변경 폴더 이동을 확인한다. 보관 문서와 같은 업무 이력은 보관 카드에서도 읽을 수 있다.

## 문서와 초안 보호

업무 화면의 **문서 선택**에는 계획 문서와 함께, 파일이 있을 경우 `verification.md`도 표시됩니다. 선택하면 검증 기록의 원문과 미리보기를 볼 수 있습니다. 이 보조 문서의 작성·수정은 계획 검토 버전에 포함되지 않지만 실제 파일 변경에 대한 실행 검증 최신성은 별도로 판정합니다. 완료 시 기록도 저장되어 이후 원본·작업 공간 폴더가 이동해도 열 수 있습니다.

아이디어를 업무로 전환하면 원본 아이디어 제목을 유지한 카드가 ‘초안’ 열에 표시된다. 제안서·설계·명세·작업 목록이 아직 없더라도 업무를 숨기지 않는다. 이후 Todo·In Progress·Done으로 이동해도 같은 업무 ID와 카드 접근을 유지하며, 보관한 업무는 보관 보기를 켜서 확인한다. 제목과 OpenSpec 변경 이름 모두 검색할 수 있다.

미저장 상태에서는 문서 이동 시 저장·폐기·취소를 선택한다. AI 요청 전에도 먼저 저장한다. 초안은 브라우저의 업무·문서별 로컬 저장소에 보존된다. 새로고침 후 다시 불러온다.

AI나 다른 편집기가 먼저 저장했다면 충돌 화면에서 최신 문서와 내 초안을 비교한다. 최신 내용을 사용하거나, 편집기에서 초안을 조정한 뒤 ‘최신 버전에 내 초안 재적용’을 선택한다. 재적용 중 다른 저장이 발생하면 다시 충돌 처리한다.

구현 뒤 계획이 수정되면 재검토가 필요하다. ‘AI와 계획 작성·수정’으로 문서 문답을 이어가고 최신 문서를 검토한 뒤 구현을 다시 시작한다. 작업 체크박스만 완료로 바꾸는 경우에는 검토를 무효화하지 않는다.

## 수정된 코드 확인

‘코드·실행·검증’의 변경 파일을 펼치면 수정된 구간만 먼저 표시한다. 초록색 `+`는 추가, 빨간색 `−`는 삭제이며 좌우 줄 번호로 변경 전·후 위치를 확인한다. 앞뒤 3줄은 문맥으로 표시하고 긴 동일 구간은 ‘변경 없는 줄 펼치기’로 확인한다. 전체 파일은 ‘전체 변경 전·후 코드 보기’를 펼치면 볼 수 있다. 파일은 구현 시작 시 저장한 기준 내용과 현재 내용을 비교한다.

텍스트를 저장하지 않은 큰 파일·바이너리는 비교 불가로 표시한다. 계산 제한을 넘는 큰 차이는 안내 후 전체 코드 보기를 제공한다. 변경 표시만으로 코드 검증이나 완료를 처리하지 않는다.

## OpenSpec 정보

OpenSpec 탭의 산출물·의존성, 다음 작성 지침, 워크플로, 기준 명세 목록, 변경 명세, 요구사항 차이, 문서 검증, 관계 진단, 프로젝트 관계는 실제 설치 CLI 결과를 표시한다. 작성 지침에는 `proposal`, `design`, `specs`, `tasks`, `apply`, `archive` 등을 입력한다. 미지원·실패 결과는 오류와 stderr로 표시한다.

문서 검증은 코드 테스트와 별개다. 오류 내용을 같은 대화에 붙여 수정 요청을 이어갈 수 있다. 보관으로 기준 명세를 반영한 뒤 보드의 명세 보기에서 결과를 확인한다.

## 재연결과 복구

- 화면 너비가 800px 이하면 ‘대화·질문’과 ‘문서·결과’ 탭으로 영역을 전환한다. 문서·결과 안에서 문서, 코드·실행·검증, OpenSpec을 선택한다. 탭 이동은 같은 업무를 유지하며 미저장 문서를 폐기하지 않는다.
- 새로고침하거나 업무를 다시 열면 마지막 문서와 선택한 영역·자료 탭을 복원한다. 문서 초안과 저장 기준 버전도 함께 복원한다. 마지막 문서가 삭제되었으면 현재 업무의 첫 문서를 연다. 브라우저 저장소를 지우거나 다른 브라우저를 사용하면 화면 선택과 미저장 초안은 복원되지 않는다.
- 새로고침 시 마지막 업무와 저장 초안을 복원한다. 실시간 연결이 끊기면 재연결 상태를 표시하고 주기 조회로 보완한다.
- 실시간 연결이 복구되면 새 이벤트가 없어도 업무 상태를 다시 조회한다. 이 조회는 미저장 문서를 덮어쓰거나 구현을 새로 시작하지 않는다.
- 서버 재시작 후 저장한 `threadId`로 대화를 재개한다. 복원 실패 시 ID를 보존하며 새 대화를 자동 생성하지 않는다.
- 대화 생성 결과가 불명확하고 ID가 없다면 자동 재시작하지 않는다. Codex의 기존 대화 기록을 대조한 뒤 관리자가 복구해야 한다.
- 연결 종료로 무효가 된 질문은 만료 표시와 함께 남는다. ‘같은 대화로 답변 복구’는 새 요청 ID에 답을 잘못 보내지 않고 기존 대화의 후속 메시지로 답변을 전달한다. 문서에 반영한 뒤 다시 검토한다.
- 답변 이력의 ‘문서 변경 감지’는 파일 해시 변경의 증거다. 요구사항이 올바르게 반영됐는지는 문서를 직접 검토한다. 문서 변경이 없으면 ‘반영 확인 필요’로 표시한다.
- 검증 도중 서버가 종료되면 해당 실행은 중단 상태이며 통과로 사용하지 않는다. 같은 업무에서 다시 실행한다.

## 백업과 기존 설치본으로 복귀

서버를 중지한 뒤 `config.local.json`, `.data/work.sqlite` 및 남아 있는 `work.sqlite-wal`·`work.sqlite-shm`, 각 프로젝트의 `openspec/`와 변경 코드를 함께 백업한다. SQLite를 사용 중일 때 DB 파일 하나만 복사하지 않는다. 설정과 DB를 같은 시점의 백업으로 복원한다.

새 앱은 13001/13002, 기존 설치본은 13000을 사용한다. 새 앱에 문제가 있으면 해당 프로세스를 중지하고 13000으로 돌아갈 수 있다. AI가 작성한 코드·문서는 자동으로 되돌리지 않으며 변경 내용을 검토한다. `.data/e2e/`와 `session-demo` 소스는 별도 검증용 자료다.
# 질문·승인 알림

Windows 프로그램에서 받은 알림은 **프로그램 안의 해당 업무·질문**을 연다. 최소화·트레이 상태면 기존 창을 복원하고, 완전히 종료했다면 이미 받은 알림 클릭으로 앱을 실행한다. 입력 중인 문서·메시지·답변은 보존하며 자동으로 답변하거나 승인하지 않는다. 앱과 소유 서버를 모두 종료한 동안에는 새 알림이 오지 않는다.

프로그램에서는 브라우저 주소를 설정하지 않는다. 프로그램 전용 알림 등록이 실패하면 알림 설정에 비활성과 오류가 표시된다. 손상된 설정은 켜기·끄기를 명시적으로 저장해 복구할 수 있다. 다음의 주소·Edge 설명은 웹 모드에 해당한다. 이전에 받은 Edge 알림은 그대로이며 프로그램 전환을 이유로 다시 발행하지 않는다.

보드와 업무 화면의 종 모양 버튼에서 모든 프로젝트의 대기 요청을 확인할 수 있다. 숫자는 미응답 요청 수이며, 한 요청 안의 여러 질문은 한 건으로 계산한다. 답변·승인 전송 중이거나 처리·만료된 요청은 다음 갱신에서 목록에서 빠진다. 연결 오류가 표시되면 목록은 마지막으로 확인한 상태다.

Windows 알림은 **최초 제품 시작부터 켜짐**이며 세션 서버가 현재 사용자 전용 제품 등록을 준비한다. 브라우저 권한을 묻지 않는다. 종 모양 버튼에서 켜기·끄기와 로컬 대시보드 주소를 수정한다. 저장한 꺼짐은 서버·Edge 재시작 후에도 유지한다. 설정상 켜짐과 실제 활성 상태를 구분하고 등록·설정·전송 오류를 표시한다. Windows 설정의 시스템 → 알림에서 OpenSpecBoard 알림·소리를 확인한다.

화면 내 알림이나 Windows 알림을 클릭하면 해당 업무의 대화 탭에서 요청에 포커스가 이동한다. 다른 업무로 옮기기 전 문서·메시지·답변 초안을 브라우저에 보존한다. 저장 실패나 프로젝트 제거로 이동할 수 없으면 기존 화면을 유지하므로 원인을 해결한 뒤 다시 클릭한다. 이미 처리·만료된 요청은 현재 상태와 기존 복구 경로를 안내한다. 클릭은 답변·승인·문서 검토 완료·구현 시작을 수행하지 않는다.

같은 Windows 로그인 사용자 세션의 서버가 실행 중이면 **Edge 완전 종료 중에도** 알림과 기본 알림음 한 번을 요청한다. 최초 즉시, 처리 완료 후 5초마다 감지한다. Windows 알림 차단·방해 금지·음소거·오디오 설정은 변경하지 않는다. OS 제출 성공은 실제 표시·소리 확인을 뜻하지 않는다. 로그아웃·PC 종료·서버 종료 중 전달, 부팅 자동 실행, 다른 기기 전송, 반복 독촉은 제공하지 않는다.

같은 업무·질문은 서버에 기록하여 **한 번만 시도**한다. 명확한 실패·결과 불명에도 자동 재전송하지 않는다. 서버 재시작·끄기 후 다시 켜기·브라우저 데이터 삭제로 기록을 초기화하지 않는다. 최초 활성화 때 미발행 기존 대기 요청은 알릴 수 있다. IndexedDB 실패는 화면 내 일시 안내에만 영향을 준다.

최초 주소는 `OPENSPEC_DASHBOARD_URL`, 미지정 시 `http://127.0.0.1:13001/`이다. 이후 `DATA_DIR/notifications.json`의 주소가 우선한다. 포트 변경 시 실제 대시보드 주소를 명시적으로 저장한다. HTTP(S)의 `localhost`, `127.0.0.1`, `[::1]`만 허용하며 사용자 정보·쿼리·프래그먼트는 거부한다. 접속한 브라우저 주소로 자동 덮어쓰지 않는다. 주소 오류는 유효 주소 저장으로 복구한다. 사용 의도까지 손상된 파일은 백업한 뒤 `enabled`와 `dashboardUrl`을 함께 복구해야 한다.

토스트 클릭은 `microsoft-edge:`로 `/?workId=...&questionId=...`를 열며 도우미 종료 후 알림 센터에서도 같은 링크를 사용한다. 최근 업무 복원보다 링크를 먼저 처리하고 최신 업무·질문 조회 후 이동한다. 성공하면 알림 인자만 제거한다. 삭제된 대상·잘못된 링크는 오류로 표시하며 다른 업무를 대신 열지 않는다. 웹 서버가 꺼졌으면 서버를 시작한 뒤 알림 센터에서 다시 클릭한다.

등록은 현재 사용자의 `OpenSpecBoard.Notifications` AUMID와 시작 메뉴 `OpenSpecBoard Notifications.lnk`만 사용한다. 관리자 권한·다른 앱 ID·Windows 정책 변경은 사용하지 않는다. **끄고 Windows 등록 해제**는 제품 소유 바로가기·HKCU 등록만 제거하며 업무·질문 기록은 유지한다. 다시 켜면 등록을 재확인한다. 이미 제출한 알림의 취소는 보장하지 않는다.

운영 반영은 모든 업무 실행·답변·승인 대기가 해소된 뒤 `./scripts/restart.ps1 -Service session`으로 명시적으로 수행한다. 작업 중인 세션 서버를 웹 서버와 함께 재시작하지 않는다.
# 사용자 검토 진행

업무 화면에서 **AI와 계획 작성·수정** 옆의 **사용자 검토 진행**을 누르면 최신 계획 문서의 사용자 검토 항목을 같은 AI 대화에서 순서대로 확인합니다. AI는 구조화 질문으로 한 항목씩 묻고, 답변을 관련 문서에 반영한 다음 다음 항목을 질문하도록 지시받습니다. 이전 대화에서 해결한 내용과 중복 항목은 함께 정리합니다.

문서 초안을 수정했다면 먼저 저장하거나 초안을 정리한 뒤 시작하세요. 실행·응답 대기·연결 복구 중이거나 구조화 질문을 지원하지 않는 도구에서는 시작할 수 없습니다. 남은 질문이 있으면 먼저 답변하세요. 검토 항목이 없으면 **AI와 계획 작성·수정**으로 검토할 내용을 문서에 정리하세요.

문답이 끝나도 **최신 문서 검토 완료**와 **구현 시작**은 자동으로 실행되지 않습니다. 사용자가 수정된 문서를 확인한 뒤 별도로 진행합니다.
# 프로젝트 소스와 Git

상단 **소스·Git**에서 프로젝트 파일을 확인·편집하고 생성·이동·삭제, 스테이징·커밋·커밋 내용 조회와 원격 동기화를 진행한다. 업무·AI·검증 화면으로 이동하고 다시 돌아올 수 있다. pull은 fast-forward만 허용하며 이력이 분기하면 외부 Git 도구에서 정리한 뒤 새로고침한다. 자동 merge·rebase·stash·reset은 하지 않는다.

기존 merge/rebase나 미병합 인덱스가 있으면 상태·파일은 볼 수 있지만 모든 Git 변경은 차단한다. 앱의 계속·중단 기능은 제공하지 않으며 외부에서 해결 또는 중단한 뒤 새로고침한다. 일반 파일 편집·생성·이동·삭제는 기존 보호 규칙 아래 유지한다. 과거 작업 기록과 결과 불확실 작업의 실제 상태 확인도 유지한다. 파일 보호·표시 한도·실행 복구·인증 준비는 [프로젝트 작업 공간 안내](PROJECT-WORKSPACE.md)를 참고한다.

## 연결 오류와 업무 복구

업무 화면에 복구 안내가 나오면 ‘업무 복구’를 누르세요. 기존 프로젝트에서 진행하던 업무도 원래 단계와 같은 대화로 복구합니다. 성공하면 오류 안내가 사라지고 ‘같은 대화로 복구했습니다’가 표시됩니다. 문서와 작성 중인 대화·문서 초안은 유지되며 이 동작만으로 구현을 시작하지 않습니다.

다른 Codex가 대화를 사용 중이면 해당 Codex에서 대화를 닫은 뒤 다시 누르세요. 업무 전용 폴더·식별 정보가 없거나 다르면 기존 백업에서 해당 폴더를 복원해야 하며, 이때 복구 버튼은 비활성화됩니다. 대화 ID가 없으면 기존 업무 기록을 먼저 확인하세요. 앱은 식별 파일을 새로 만들거나 새 대화를 자동 생성하지 않습니다. ‘최신 문서 재검토’ 안내는 실제 문서 변경에 대한 별도 안내이므로 복구만으로 해제되지 않습니다.

복구 전에 대기열에 있던 지시는 자동 실행하지 않고 확인 필요 상태로 보존합니다. 문서와 실제 실행 기록을 확인한 뒤 필요한 지시만 다시 보내세요.

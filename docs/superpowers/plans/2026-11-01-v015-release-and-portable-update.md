# OpenSpecBoard 정식 배포와 지정 portable 업데이트 Implementation Plan

> **For agentic workers:** 같은 C 사본/대화에서 승인된 범위만 진행한다. 하위 에이전트를 만들지 않는다. 사용자 데이터·인증값을 로그/공개 Git에 기록하지 않는다.

**Goal:** 검증 제품119dc7a/기록2ffc3fe 기반 변경을 새 정식 버전으로 공개하고 사용자가 지정한0.1.3 portable만 백업 후 업데이트하여 버전과 데이터 보존을 확인한다.

**Architecture:** 기존v0.1.14 및 모든 태그/릴리스를 보존한다. 현재 비어 있는0.1.15를 시작 버전으로 사용하고 실패한 태그가 생기면 이동/덮어쓰기 대신 다음 비어 있는 정수 버전으로 진행한다. release 브랜치에서 CI 전체 검사/정식 정책 패키지를 확인하고 태그 배포 CI가 검증한 필수5개 asset만 게시한다. 대상과 프로필의 전체 백업 및 WAL/SHM 일관성·롤백 근거를 확보한 뒤 대상 앱의 다운로드/교체/재실행만 확인한다.

**Tech Stack:** 프로젝트 Node24.15.0/npm, Electron45, GitHub Actions/기존 인증 gh, SQLite, portable-github updater.

## 승인과 경계

- 사용자는 공개 정식 배포/필수 CI 전체 검사와 바탕화면 자동 업데이트 바로가기가 가리키는 portable의 백업·업데이트 질문에 동의했다. 별도 설치본·다른 앱/서비스·OS 종료/재시작, 광범위 kill, 보안/권한/인증 설정 변경은 포함하지 않는다.
- 원본D의 runtime/소유권/safe.directory와 별도a16fa882를 변경하거나 통합하지 않는다. 새 자격 증명/약관/보호 환경·PR 승인이 필요하면 우회하지 않고 구체적으로 보고한다.
- C 제품 계보는 origin/main 및v0.1.14를 포함하고a16fa88는 조상이 아니다. 변경257개 경로의 로컬 데이터/설정/개인 key 경로 검사는0개였다. 게시 직전 내용·현재 원격을 재확인한다.
- 로컬 Git 자격 증명을 메모리에서 같은 GitHub API 호출에만 재사용한다. 토큰을 파일/명령 인자/로그에 쓰거나 인증 설정을 변경하지 않는다.

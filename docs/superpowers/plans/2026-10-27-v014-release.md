# OpenSpecBoard v0.1.4 Release Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to execute each release gate with recorded evidence. The user has explicitly authorized committing and pushing all developed changes and publishing this release.

**Goal:** 현재 개발된 기능 전체를 소스 저장소와 Windows 설치형·무설치형 v0.1.4 릴리스에 반영한다.

**Architecture:** 현재 작업 폴더의 추적·미추적 제품 코드를 모두 커밋하되 `.data`, `.tools`, `.logs`, 로컬 설정·자격 증명은 제외한다. 기존 앱과 분리된 스테이징·출력 경로에서 설치형과 ZIP을 검증하고, 소스 커밋·태그·업데이트 메타데이터가 일치하는 새 GitHub 릴리스를 게시한다.

**Tech Stack:** Node 24.15.0, TypeScript/Vite, Electron 45.0.0, electron-builder 26.18.0, Playwright 1.64.1, GitHub CLI.

## 실행 순서

1. GitHub 최신 공개 버전과 origin/main을 확인한다. 최신 v0.1.3을 덮어쓰지 않고 v0.1.4를 사용한다.
2. 루트 package/lock 버전을 0.1.4로 맞추고 Windows CI의 프로젝트 런타임·Chromium·가드 준비를 테스트 전에 추가한다. 기존 CI 임시 경로 fixture를 실경로로 정규화하고 파일별 프로세스를 분리하는 Vitest forks/단일 worker를 기본 검사에 적용한다.
3. 프런트엔드·백엔드·데스크톱 전체 검사와 빌드, OpenSpec 기본 명세 검증을 실행한다. 단일 검사 실패를 숨기지 않고 제품 오류와 실행 환경 제한을 구분한다.
4. 전체 커밋 후보를 검사해 로컬 데이터·토큰·임시 바이너리가 포함되지 않았는지 확인한다. 한국어 커밋 메시지로 전체 구현과 배포 준비를 커밋한다.
5. `.tools/desktop-stage-v014`와 `.tools/desktop-dist-v014`에 개인용 업데이트가 활성화된 설치형을 만들고 전용 ZIP·portable.json을 같은 출력에 모은다. NSIS EXE·blockmap·latest.yml·ZIP·portable.json 5개, 버전·SHA-512·SHA-256·빌드 코드·Chromium/가드를 검사한다. 별도 테스트 프로필로 실제 패키지의 기동·인증·종료 검사를 수행한다.
6. origin/main이 여전히 현재 소스의 조상인지 확인하고 강제 푸시 없이 개발 브랜치와 main, v0.1.4 태그를 올린다. 같은 버전 태그·릴리스가 이미 있으면 덮어쓰지 않고 실제 상태를 먼저 확인한다.
7. 태그가 검증 소스 커밋을 가리키는지 확인한 뒤 새 초안 릴리스에 5개 파일을 업로드한다. 원격 크기·해시를 검사하고 공개·latest 지정 후 익명 공개 다운로드의 해시와 업데이트 메타데이터를 재확인한다.

현재 사용자의 실행 중 앱 교체·세션 서버 재시작은 릴리스 게시와 분리한다. 배포 파일과 업데이트 피드를 제공하고 기존 업무·데이터를 유지한다.

# Codex 네이티브 권한 검토 연결

사용자 요청: 웹 업무 공간의 실행 권한 검토에 Codex의 ‘나 대신 승인’을 사용한다.

설계: 설치된 Codex app-server의 실험 API `approvalsReviewer: auto_review`를 새 대화·복구·각 후속 실행에 명시한다. 기존 workspace-write 샌드박스와 on-request 정책을 유지한다. 자체 무조건 승인이나 별도 AI 검토기를 만들지 않는다. Codex가 사용자에게 전달하는 승인 요청은 기존 개별 승인 경로로 처리한다.

오류와 기록: 기존 오류·복구 경로와 동일 대화 ID를 보존한다. 자동 검토 이벤트는 기존 영구 이벤트 저장소에 저장되며 실행 기록에서 한국어 제목으로 확인한다. 문서 검토·구현 시작·완료 승인은 별도 사용자 결정이다.

검증: 시작·복구·후속 실행 RPC의 reviewer 및 승인 정책을 테스트한다. 기존 질문·수동 승인·재시작 복구 회귀 테스트와 양쪽 빌드를 실행한다. 실제 Codex 연결에서는 별도 임시 대화를 사용해 설정 수락 여부를 확인하며 실제 업무의 요청을 임의 승인하지 않는다.

반영: 승인 대기 중인 실행은 중단 확인 후 서버를 교체한다. 대기 요청을 소급 승인하지 않는다. 기존 대화는 사용자의 후속 지시로 같은 ID에서 재개한다.

검증 결과: 수정 전 계약 테스트 2개 실패를 확인하고 수정 후 Codex 통합 테스트 14개가 통과했다. 프런트엔드 21개 테스트와 전체 빌드가 통과했다. 실제 Codex 임시 대화 응답에서 `approvalsReviewer=auto_review`, `approvalPolicy=on-request`, `sandbox=workspaceWrite`를 확인했다. 이 확인은 설정 수락 검증이며 실제 위험 작업의 AI 심사 실행 검증은 아니다. 실제 업무를 중단 확인 후 백엔드를 교체했으며 원래 threadId와 문서가 보존됐다.

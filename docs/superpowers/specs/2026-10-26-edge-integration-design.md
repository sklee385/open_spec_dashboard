# OpenSpecBoard Edge 연결 설계안

상태: 사용자 승인 후 구현 진행. 전용 확장·로컬 브리지·새 Codex 업무 도구·연결 UI를 구현했다. 실제 Edge 설치와 화면 검증은 사용자가 진행하며, 실행 중 세션 서버는 재시작하지 않는다.

## 목표와 현재 구조

OpenSpecBoard 안의 Codex 업무가 사용자가 연결한 Microsoft Edge 탭을 읽고 조작할 수 있게 한다. 기존 대화 ID와 질문·승인 처리를 유지하고, 연결되지 않았을 때는 연결 방법과 상태를 보여 준다.

현재 `backend/src/codex/client.ts`는 별도의 `codex app-server`를 실행한다. `codex.service.ts`의 직접 등록 도구와 요청 처리는 `ask_user`만 지원한다. 데스크톱 앱에서 이 대화에 제공하는 브라우저 연결을 OpenSpecBoard에 전달하는 구현은 없다. 전역 플러그인이 제공하는 도구와 이 직접 등록 도구는 구분한다.

공식 ChatGPT 브라우저 확장 안내에는 Edge 지원과 데스크톱 앱 연결 절차가 있다. 이 확장을 타사 app-server에 직접 연결하는 공개 절차는 이번 조사에서 확인하지 못했다. 공식 확장의 내부 통신이나 인증을 재사용한다고 가정하지 않는다.

## 접근 방식 비교

1. **OpenSpecBoard 전용 Edge 확장과 로컬 연결: 제안 방식.** 기존 Edge의 선택한 탭을 대상으로 브라우저 확장 API를 사용한다. 별도 확장의 최초 수동 설치·연결이 필요하지만 OpenSpecBoard가 연결과 도구 실행을 직접 관리할 수 있다.
2. **공식 ChatGPT Edge 확장 사용.** 데스크톱 Codex 대화에서는 사용할 수 있지만 OpenSpecBoard의 별도 app-server에 직접 연결하는 공개 경로가 확인되지 않았다. 이번 기능 구현의 기반으로 삼지 않는다.
3. **Edge 원격 디버깅 또는 별도 브라우저 MCP.** 기존 브라우저 MCP를 추가하지 않는 지침과 정상 프로필 사용 요구를 고려해 선택하지 않는다.

## 사용 흐름

1. OpenSpecBoard 설정에 Edge 연결 영역을 제공한다. 미설치·미연결·연결됨·탭 선택 필요·재연결 필요를 구분한다.
2. 사용자가 제공된 확장 폴더를 Edge에 직접 설치한다. 초기 버전은 개발용 압축 해제 확장이며 자동 설치나 스토어 게시를 수행하지 않는다.
3. OpenSpecBoard가 일회성 연결 코드를 발급하고, 사용자가 확장 화면에서 코드와 로컬 연결 주소를 입력한다.
4. 사용자가 Edge의 특정 탭에서 확장 버튼으로 해당 탭을 현재 업무에 연결한다. 이후 다른 탭으로 초점이 바뀌어도 업무 대상 탭은 바뀌지 않는다.
5. Codex가 연결된 탭의 화면 정보를 읽고 클릭·입력·스크롤·화면 캡처를 요청한다. 모든 작업은 현재 업무와 연결된 탭에만 전달한다.
6. 사용자는 언제든 연결을 해제할 수 있다. 탭 종료·다른 사이트 이동·서비스 재시작 시 상태를 갱신하고 필요하면 다시 연결하도록 한다.

## 구성과 실행 경계

- `edge-extension/`: Manifest V3 확장, 연결 화면, 서비스 워커, 탭 내 DOM 관찰·조작 코드. 임의 JavaScript 실행 도구는 제공하지 않는다.
- `backend/src/browser/`: loopback 전용 연결 서비스, 일회성 코드 교환, 업무·탭 연결, 명령 검증·전달·응답·시간 제한 관리.
- 설정과 업무 화면: 연결 상태, 확장 설치 안내, 대상 탭 표시, 연결 해제 동작.
- Codex 연동: 명시적인 Edge 도구를 등록하고 `item/tool/call`에서 질문 도구와 분리해 처리한다. 도구 결과는 텍스트 관찰 또는 이미지로 반환한다.
- 기존 업무의 같은 threadId 재개 시 도구 구성을 바꿀 수 있는지는 설치된 app-server의 실제 계약으로 격리 검증한다. 지원되지 않는 경우 기존 대화를 자동 교체하지 않고 새 업무에서만 연결을 지원하며 기존 업무에는 제한을 안내한다.
- 로컬 연결 서비스는 세션 서버가 소유한다. 웹 게이트웨이 재시작으로 브라우저 연결을 끊지 않는다. 웹 개발 환경과 데스크톱 앱의 다른 프로필은 별도로 연결한다.

## 최초 지원 범위

- 현재 연결된 탭의 URL·제목·본문·조작 가능한 요소·관찰 ID 읽기.
- 관찰 ID에 연결된 요소 클릭, 일반 입력란 값 입력, 스크롤, 현재 보이는 탭의 화면 캡처.
- 사용자가 선택한 탭과 현재 사이트에 한정한다. `activeTab`의 허용 기간이 끝나면 자동으로 다른 사이트 권한을 요구하지 않는다.
- 탭 이동 후 DOM이 바뀌면 이전 요소 ID를 폐기한다. 이전 관찰을 사용한 입력은 거절하고 새 관찰을 요구한다.
- 초기 범위에서 파일 업로드, 다운로드 관리, 인증 정보·쿠키 추출, 비밀번호 입력, 임의 스크립트, 전체 탭 제어는 제외한다.
- 캡처는 연결한 탭이 활성 탭일 때만 수행한다. 다른 탭이 활성화돼 있으면 잘못된 탭을 캡처하지 않고 대상 탭 선택이 필요하다고 안내한다.

## 연결 관리

브라우저 전체 접근 대신 사용자가 연결한 탭을 대상으로 한다. 연결 코드에는 짧은 유효 기간과 1회 사용 제한을 두고 서버가 발급한 연결 식별자로 명령을 인증한다. 페이지 스크립트는 로컬 제어 요청을 직접 보낼 수 없다. 연결 해제 시 해당 업무의 실행 권한을 폐기한다. 브라우저 문서는 검토 자료로만 다루며 권한 승인이나 사용자 지시로 취급하지 않는다.

확장 설치와 최초 탭 연결은 사용자가 직접 수행한다. 민감한 동작에 대한 기존 승인 정책을 브라우저 연결 승인 하나로 대체하지 않는다.

## 오류와 검증

- 포트 사용 중, 연결 코드 만료, 다른 업무의 탭 요청, 응답 시간 초과, 탭 닫힘, 사이트 이동, 오래된 요소 ID, 연결 해제를 테스트한다.
- 질문·승인 대기 중인 기존 업무와 새 Edge 요청의 상태가 혼동되지 않는지 검증한다.
- 모의 확장으로 앱 연결부터 도구 요청·응답까지 API 통합 테스트를 수행한다. 확장 코드와 앱의 빌드 및 패키지 포함 여부를 확인한다.
- 실제 Edge 최초 설치·탭 연결·읽기·클릭·입력·캡처는 사용자가 진행하도록 확인 항목과 시험용 화면을 제공한다. 자동 테스트를 실제 Edge 검증으로 보고하지 않는다.
- 제품 세션 서버 변경은 모든 실행·질문·승인·대기 메시지가 해소된 뒤 명시적으로 반영한다.

## 설계 자체 검토

공식 확장 재사용과 전용 확장 구현을 구분했다. 기존 업무 호환은 실제 계약 검증을 조건으로 두고, 기존 대화 자동 교체를 금지했다. 첫 버전의 사이트·탭 범위, 캡처 조건, 설치 주체와 실제 검증 주체를 명시했다. 현재 상태를 구현 완료나 실제 연결 성공으로 표시하지 않는다.

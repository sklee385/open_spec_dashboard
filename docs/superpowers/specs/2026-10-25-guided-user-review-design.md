# 사용자 검토 진행

## 목적

업무 화면의 `AI와 계획 작성·수정` 바로 옆에 `사용자 검토 진행` 버튼을 제공한다. 사용자가 버튼을 누르면 현재 업무의 같은 AI 대화에서 사용자 검토 항목을 한 번에 하나씩 질문한다.

## 동작

- 서버에서 최신 계획 문서의 `[review:confirm]`, `[review:assumption]`, `[review:decision]`, `[review:choice]` 항목을 다시 읽는다. 선택한 문서뿐 아니라 해당 업무의 전체 계획 문서를 대상으로 한다.
- 기존 추출 순서인 proposal.md, design.md, tasks.md, specs 내 문서 순서와 각 문서의 줄 순서를 따른다.
- 각 질문에 원본 문서와 검토할 내용, 현재 순번과 전체 개수를 안내한다. 같은 의미의 항목이 있으면 답변을 관련 문서에 함께 반영하고 중복 질문을 피한다.
- AI는 기존 구조화 질문 도구로 한 항목만 묻고 답변을 기다린다. 답변을 관련 문서에 반영한 뒤 다음 항목을 질문한다. 모호한 답변은 현재 항목에서 추가 확인한다.
- 같은 대화에 남아 있는 검토 답변을 참고해 이미 해결된 내용을 불필요하게 다시 묻지 않는다.
- 모든 항목을 확인하면 결정 내용과 남은 사항을 요약한다. 이 동작은 `최신 문서 검토 완료`나 구현 시작을 자동 처리하지 않는다.
- 제품 코드는 수정하지 않고 계획 단계에서 문서와 문답만 진행한다.
- 미저장 문서 초안이 있으면 기존 저장·이동 보호 흐름을 적용해 저장 여부를 먼저 결정하게 한다.

## 예외 처리

- 검토 항목이 없으면 안내하고 AI 실행을 시작하지 않는다. 문서 읽기가 실패하면 오류를 안내하고 재시도할 수 있게 한다.
- 실행 중이거나 질문·승인 응답 대기 중이면 새 검토를 중복 시작하지 않는다.
- 완료·보관된 업무, 연결 복구가 필요한 업무는 먼저 기존 열기·복구 동작을 거친다.
- 구조화 질문을 지원하지 않는 외부 AI 도구는 버튼을 비활성화하고 이유를 표시한다.
- 항목 내용은 검토 자료로 전달하고, 질문 순서·문서 수정 범위·구현 금지 지침과 구분한다.

## 구현 범위

- 기존 업무 action API에 사용자 검토 시작 동작을 추가하고 서버에서 최신 항목 조회와 실행 조건을 검증한다.
- 기존 AI 도구의 같은 대화 전송, 구조화 질문, 답변 반영 흐름을 재사용한다. 별도 대화를 생성하지 않는다.
- 업무 화면 버튼, 한국어·영어 문구 및 로딩·오류 처리를 추가한다.
- 항목별 승인 상태나 별도의 자동 구현 기능은 추가하지 않는다. 질문 순서와 답변 반영은 AI 대화 지침으로 수행한다.

## 검증

- 버튼 위치와 시작 요청, 미저장 초안 보호, 중복 시작 차단을 프런트엔드 테스트로 확인한다.
- 서버에서 최신 항목과 문서 순서, 한 번에 한 질문 지침, 같은 대화 및 계획 단계 유지, 항목 없음·읽기 실패·지원하지 않는 도구 처리를 테스트한다.
- Codex 앱 내장 브라우저에서 버튼과 질문 화면을 확인한다. 실제 사용자 업무에 임의의 답변을 제출하지 않는다.

긴 검토 자료가 메시지 제한을 넘으면 항목 수와 전체 원문 조회 지침을 전달한다. AI는 현재 업무의 변경 폴더에서 모든 계획 문서를 같은 순서로 읽어 항목을 생략하지 않고 진행한다.

상태: 사용자 승인 후 구현 완료. 서버·화면 관련 테스트 93건과 양쪽 빌드 통과. Codex 앱 내장 브라우저에서 버튼 위치와 활성 상태 확인.

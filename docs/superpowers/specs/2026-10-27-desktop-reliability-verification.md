# v0.1.8 데스크톱 안정성 검증

## 구현 및 검토

Windows 기본 소프트웨어 렌더링, 손상 설정 기본값, 네이티브 화면 장애 안내, 사용자 선택에 따른 화면만 재로드, 실제 화면 준비 후 무설치 성공 보고, 과거 기록을 보존하는 업데이트 유휴 판정을 구현했다. 렌더러 sandbox와 기존 업무·질문·승인 차단은 유지한다.

독립 검토에서 미저장 입력의 unload 거부가 명시적 복구까지 막는 문제와 React 준비 전 smoke DOM 조회 경쟁이 발견됐다. 복구 재로드 동안만 unload를 허용하고 finally로 보호를 복원했으며, 충돌 전과 충돌 후의 소유 프레임 준비 IPC를 각각 시간 제한으로 기다리도록 수정했다. 최종 검토에서 중요한 잔여 문제는 발견되지 않았다.

## 로컬 검사

- 데스크톱 전체 Node 검사: 155개 통과.
- 프런트엔드 전체 Vitest 검사: 42개 파일, 248개 통과.
- 백엔드 전체 첫 실행: 284개 통과, 12개 실패, 기존 2개 건너뜀. 실패는 프로그램 전용 브라우저·Job 가드 검사 4개 파일에 한정됐다. 동일한 4개 파일을 일반 샌드박스 제한 밖에서 재실행하여 25개 모두 통과했다. 제품 코드나 시스템 ACL은 변경하지 않았다.
- 데스크톱 인증·잠금·처리 중 요청 검사와 과거 기록 예외 회귀 검사를 함께 재실행: 2개 파일, 11개 통과. 기존 인증·변경 요청 잠금 검사는 보존했다.
- 프런트엔드 및 백엔드 빌드 통과. Vite의 기존 청크 크기 경고는 남아 있다.

## 실제 패키지 검사

별도 `.tools/desktop-stage-v017`, `.tools/desktop-dist-v017`에서 개인용 업데이트가 활성화된 Windows x64 패키지를 만들었다. 작업 폴더의 AppContainer ACL 때문에 Electron이 실행을 거부하여 기존 `--copy-to-temp` 기능으로 새 임시 폴더에 복사했다. sandbox 비활성화나 ACL 변경 없이 격리된 새 프로필에서 다음 명령을 통과했다.

```powershell
./scripts/node.ps1 scripts/desktop-smoke.cjs .tools/desktop-dist-v017/win-unpacked/OpenSpecBoard.exe --copy-to-temp --security --personal-update --renderer-recovery
```

실제 렌더러 권한 격리, 소유 메인 프레임 IPC, 업데이트 활성 상태, 렌더러 강제 충돌 후 재로드와 새 준비 응답, 대화 서버 PID 유지, 유휴 API, 정상 종료 및 백업을 확인했다. 실제 네이티브 확인 버튼은 격리 검사에서 선택 대역으로 처리하며 일반 앱에서는 사용자에게 안내한다. CI에도 같은 실제 패키지 충돌 복구 검사를 추가했다. 사용 중인 설치 앱과 13003 세션 서버는 배포 검증으로 종료하거나 교체하지 않았다.

정식 게시 및 원격 산출물 검증은 태그 배포 파이프라인 결과로 별도 확인한다.

## v0.1.7 원격 검사와 v0.1.8 후속 배포

v0.1.7 실행 `40480245706`은 데스크톱 155개·프런트엔드 248개 및 백엔드 305개를 통과했지만 기존 외부 CLI 오류 구분 검사 1개가 5초 poll 안에 완료되지 않아 게시하지 않았다. 제품의 Windows 자식 정리는 최대 10초, fixture CLI 자체 제한은 10초인데 테스트 대기는 5초여서 정리 완료 전에 실행 중 상태를 관찰할 수 있었다. 개별 실패 poll을 25초로, 4가지 모드를 포함한 전체 테스트 예산을 90초로 맞추고 모드를 실패 메시지에 표시한다. 실제 실패 상태·오류 코드·비밀 stderr 미저장 단언과 제품의 기한은 변경하지 않는다. 수정 전후 해당 7개 검사를 별도로 실행하여 통과했다. 기존 v0.1.7 태그는 보존하고 배포 버전을 v0.1.8로 올린다.

v0.1.8 실행 `40481584509` 첫 시도에서는 외부 CLI 검사를 포함한 303개가 통과했지만 기존 `browser-startup.test.ts`의 작업 프로세스가 비정상 종료되어 나머지 3개 결과 없이 Vitest가 실패했다. 같은 8개 검사는 직전 원격 실행과 로컬 재검사에서 모두 통과했다. 제품 코드나 테스트 단언을 추가로 바꾸지 않고 실패한 작업을 한 번 재실행했으며, 두 번째 시도에서 전체 검사와 앱 빌드가 통과했다. 게시 전에 실제 패키지 복구 검사와 산출물 검증도 계속 확인한다.

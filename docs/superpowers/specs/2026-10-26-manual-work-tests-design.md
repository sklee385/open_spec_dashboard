# 작업 테스트와 전체 테스트

사용자가 승인한 개발 검증 축소 방안을 두 버튼으로 구현한다.

- 작업 테스트: 업무 전용 변경 파일과 관련된 Vitest 테스트만 실행한다. 루트와 npm workspace의 Vitest 스크립트를 탐지한다. 테스트 파일 변경은 해당 파일을 직접 실행한다. 설정·의존성 변경은 관련 패키지 테스트 전체로 확대한다. 미지원 프로젝트는 작업 전용 검증 명령을 등록한다.
- 전체 테스트: 기존 verificationCommands의 모든 명령을 순차 실행한다. 기본값은 기존 package.json의 test/test:run, typecheck, build, lint이다.
- 공통: 실행 중 중복 시작 금지, 첫 실패·중단 시 남은 명령 중지, 항목별 출력·종료 코드·소요 시간 보존, 현재 변경과 다른 과거 결과 표시, 실패 결과로 같은 AI 대화에 수정 요청 준비.
- 결과 화면은 두 범위와 미검증·재검증 필요 상태를 구분한다. 작업 테스트 결과는 전체 검증 통과를 대체하지 않는다. 기존 완료·반영 조건은 유지한다.
- AI 공통 지침: 개발 중에는 변경 관련 최소 검증만 수행하고 전체 검증을 반복하지 않는다. 단순 문구·스타일 수정에 구현을 복제하는 테스트를 추가하지 않는다. 사용자의 명시적 전체 검증 요청은 수행한다. 미실행 항목은 테스트 대기로 보고한다.
- TEST 버튼은 실행 API를 호출하며 사용자가 직접 화면을 확인한 것으로 기록하지 않는다. 세션 서버를 작업 중 재시작하지 않는다.

기존 미커밋 변경은 보존하고 이번 변경만 Git 인덱스에 반영한다. 검증은 관련 테스트와 타입 검사, Codex 내장 브라우저에서 수행한다.

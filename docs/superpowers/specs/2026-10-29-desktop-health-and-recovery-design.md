# 전체 상태 점검과 안전한 장애 복구 설계

사용자는 2026-10-29 대화에서 전체 점검, 종료 차단 사유, 장애 기록, 초안 복구, 업무별 중단·복구, 안전 모드, 강제 종료와 커밋·배포를 승인했다. 앞선 대화의 위험 검토와 제안 범위를 구현한다.

## 동작 원칙

전체 점검은 읽기 전용이다. 저장된 업무 상태와 실제 실행을 별도로 표시하며 정상·실행 중·불일치·확인 불가로 구분한다. 무응답이나 출력 지연만으로 실행을 종료하거나 잠금을 지우지 않는다. 사용자 선택 후에도 복구 직전에 같은 업무의 최신 실행 소유 상태를 다시 검사한다. 기존 대화·문서·질문·승인은 자동 처리하거나 재실행하지 않는다.

## 상태 판정과 업무별 복구

업무별 실행 등록부에서 연결 작업, AI 턴, 외부 CLI, 브라우저·일반 검증을 구분한다. 연결 손실은 해당 실행에 영향을 받은 업무만 복구 필요로 바꾸며 이미 완료된 업무는 바꾸지 않는다. 실제 실행이 없는 복구 필요 업무는 실행 중과 구분하여 정상 종료를 막지 않도록 한다. 실제 질문·승인·전송 대기와 처리 중 변경 요청은 상세 사유로 표시한다. 서버 연결 실패·인증 실패·작업 충돌을 하나의 작업 중 문구로 합치지 않는다.

업무별 상태 복구는 실제 실행 없음이 확인된 범위에서만 과거 실행 상태를 중단·확인 필요로 정리하고 사건을 기록한다. 불명확한 실행은 임의로 idle로 바꾸지 않는다. 중단은 기존 엔진 중단 경로를 사용하며 정상 중단을 확인하기 전에 성공으로 표시하지 않는다.

## 진단 화면과 장애 기록

앱 메뉴·트레이에서 별도 진단 창을 열어 화면 장애와 무관하게 서버 응답, 안전 모드, 요청·잠금, 업무별 판정·마지막 상태 변경 시각, 종료 차단 사유, 복구 이력을 확인한다. 요청 및 재검사에 유한한 기한을 둔다. 진단에는 사용자 프롬프트·초안·인증 토큰·원문 stderr를 넣지 않는다. 유형·업무 식별자·상태·오류 코드 중심의 제한된 사건 기록을 유지한다. 같은 창에서 선택한 업무의 중단·복구와 명시적인 안전 모드 해제를 제공한다.

## 초안 복구

기존 work-chat-draft, work-draft, 프로젝트 편집 초안을 재사용·보강한다. 입력·문서 변경 시 지연 저장하고 화면 종료 시 즉시 저장한다. 저장 실패는 표시하며 복구 가능한 초안을 원본 문서에 자동 덮어쓰지 않는다. 복원한 내용과 서버 버전이 다르면 충돌을 표시한다. 저장·전송 성공 뒤 해당 초안만 제거한다. 초안과 진단은 분리하고, 종료 직전 저장이 불가능할 수 있으므로 지속적인 초안 저장을 사용한다.

## 안전 모드

비정상 종료 뒤에는 안전 모드로 시작한다. 대기 메시지의 자동 전송 및 AI 자동 실행은 보류하며 읽기·점검·수동 중단·복구는 사용할 수 있다. 안전 모드 해제는 명시적인 사용자 요청으로 수행하고 해제 자체로 대기열을 자동 재전송하지 않는다. 이전 실행 결과가 불명확한 업무를 새 업무로 복제하거나 자동 재시도하지 않는다.

## 강제 종료와 독립 긴급 도구

정상 종료와 별도로 강제 종료를 제공하고 미저장 내용 및 진행 중 변경 손실을 안내하여 확인을 받는다. 가능한 정상 종료를 먼저 시도하되 기한을 넘기거나 차단되면 명시적인 강제 종료 선택으로 앱 소유 프로세스만 정리한다. GUI와 서버가 응답하지 않아도 실행할 수 있는 별도 긴급 도구를 동봉한다. 앱 소유자 레코드의 실행 경로·PID·생성 시각을 검증하며 전역 node/codex 프로세스 이름으로 종료하지 않는다. PID가 재사용되거나 소유권이 불명확하면 종료하지 않는다. 강제 종료 후 자동 업데이트 설치를 시작하지 않으며 비정상 종료 흔적을 남겨 다음 시작에서 안전 모드와 점검을 수행한다. 파일·DB를 지우지 않고 열려 있는 DB의 단순 복사를 정상 백업이라고 표시하지 않는다.

## 검증과 배포

실제 실행 중 오인 복구 거절, 오래된 상태의 종료 허용, 이미 완료된 업무 보존, 진단의 읽기 전용 및 민감 데이터 제외, 초안 재로드·충돌·저장 실패, 안전 모드 대기열 보류, PID 재사용·다른 앱 보호, 서버 장애 중 진단·종료 UI, 실제 패키지 기동·복구·종료를 확인한다. 기존 다른 OpenSpec 문서 변경은 커밋에서 제외한다. 전체 검사·빌드·독립 검토 후 새 버전으로 설치형·무설치형을 게시하고 공개 다운로드 해시를 검증한다. 사용 중인 설치본과 13003 서버는 개발·배포 작업으로 재시작하지 않는다.

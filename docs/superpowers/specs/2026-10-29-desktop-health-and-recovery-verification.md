# v0.1.9 상태 점검·복구·긴급 종료 검증

## 구현 범위

앱 메뉴와 트레이에 전체 상태 점검 및 강제 종료를 추가했다. 별도 진단 창에서 화면·서버 응답, 실제 실행과 저장 상태, 요청·종료 차단 사유를 확인하고 해당 업무로 이동하거나 수동 중단·상태 복구를 요청한다. 실제 실행 없음이 확인된 업무만 복구하며, 연결 해제·응답 유실은 `unknown`으로 보존한다. 과거 완료 업무의 오래된 상태만으로 종료를 막지 않는다.

비정상 종료 후 안전 모드는 새 실행·대기 메시지 자동 전송을 보류한다. 해제는 명시적 요청이며 이전 대기열을 재전송하지 않는다. 재연결은 턴 시작과 분리하고 같은 현재 턴의 종료 증거 없이 unknown을 해제하지 않는다. 이전 세대·다른 턴·늦은 완료 알림은 현재 실행을 완료로 바꾸지 않는다.

독립 긴급 도구는 PID·파일 시각·실행 경로·열린 핸들의 부모 관계를 검증하고 앱 소유 트리만 종료한다. 확인 전후 nonce·프로세스 identity가 바뀌면 거절하고 도구 자신 및 다른 앱은 보호한다. 소유 정보는 서버 ready 전부터 기록한다. 강제 종료와 업데이트 설치는 서로 인계 중 겹치지 않는다. 데이터 파일을 지우지 않으며 다음 실행에 안전 모드를 남긴다. 설치형과 ZIP에 실제 `resources/emergency` 파일과 루트 `OpenSpecBoard 긴급 종료.cmd`를 포함한다.

초안은 400ms 지연 저장과 이동·종료 시 flush를 사용한다. 데스크톱의 임의 서버 포트와 무관한 프로필 파일 `recovery-drafts.json`을 고정 IPC로 읽고 쓴다. 메시지·답변·문서·프로젝트 초안을 원본과 분리하며 서버 버전 충돌과 저장 실패를 표시한다. 전송 도중 새 입력, 저장소 오류 중 이동, 재마운트·origin 변경을 검증했다. 초안은 진단 기록에 포함하지 않는다.

## 로컬 검증

- 데스크톱 전체: 198개 통과. 인증 프레임, 새 IPC, 정상·강제 종료와 업데이트 경합, PID 재사용·소유권 변경, 실제 격리 Node 프로세스 종료를 포함한다.
- 프런트엔드 최종 전체: 44개 파일 272개 통과. 마지막 전송 중 저장 실패 회귀 2개도 포함한다.
- 프런트엔드·백엔드 빌드 통과. 기존 Vite 청크 크기 경고는 유지된다. 전체 프런트 lint의 기존 다수 오류는 범위 밖으로 보존하며 신규 저장 adapter/hook lint는 통과했다.
- 초기 제한된 환경의 전체 백엔드 실행에서는 네이티브 프로세스 검사·브라우저 가드 실패와 worker 종료가 발생했다. 실행 제한을 끄거나 시스템 ACL을 변경하지 않고 프로젝트 런타임 및 네이티브 검증 권한으로 최종 전체 검사를 별도 수행한다. 수정 도중 실행한 이전 검사는 최종 통과 근거로 사용하지 않는다.
- 백엔드 최종 전체: 48개 파일 331개 통과, 기존 1개 파일의 2개 건너뜀. 프로젝트 런타임의 정규 경로를 PATH에 사용하고 네이티브 검증 권한으로 실행하여 브라우저·외부 CLI·Git·API·새 실행 상태 회귀를 모두 통과했다. 총 자동 검사 801개 통과, 기존 2개 건너뜀.
- 프런트·백엔드·긴급 도구·데스크톱 통합을 독립 검토했다. 알려진 중요 문제는 수정 후 재검토하여 해소 확인했다.

## 실제 Windows 패키지

사용 중인 앱과 13003 세션 서버를 유지하고 임시 앱 복사본과 별도 새 프로필만 사용했다. 작업 폴더의 기존 AppContainer ACL 때문에 `--copy-to-temp`를 사용하며 sandbox 및 ACL을 변경하지 않았다.

```powershell
./scripts/node.ps1 scripts/desktop-smoke.cjs --copy-to-temp --security --personal-update --renderer-recovery --health
./scripts/node.ps1 scripts/desktop-force-smoke.cjs --copy-to-temp
```

첫 검사는 실제 렌더러 격리·업데이트 IPC·강제 렌더러 충돌 후 복구·같은 세션 PID 유지·진단 창 고정 IPC·실제 소유 정보·안전 모드 적용/해제·정상 종료/백업을 통과했다.

두 번째 검사는 격리 앱을 독립 helper로 실제 종료하고 앱·서비스의 같은 identity가 사라졌음을 확인했다. 강제 종료 직후 SQLite quick_check를 통과하고 같은 프로필로 재실행했다. 이전 gateway 포트를 점유하여 origin이 실제로 달라지도록 한 뒤 안전 모드·초안 복원·정상 종료와 백업 SQLite quick_check를 통과했다. 초기 검사 도구의 백업 폴더/파일 구분 오류는 파일 경로 검사로 수정하고 전체 시나리오를 다시 통과했다.

Codex 내장 브라우저로 실제 진단 HTML/CSS/JS와 격리 fixture를 확인했다. 정상·불일치·불명 판정, 문제 업무 필터, 업무별 복구/열기, 오프라인 안내와 안전 모드, 최소 너비 680px에서 문서 가로 넘침 없음(표 내부 스크롤)을 확인했다. 브라우저 fixture는 운영 데이터나 AI를 사용하지 않는다.

## 정식 배포

최신 공개 버전 v0.1.8과 원격 main을 확인하여 v0.1.9를 선택했다. 기존 다른 OpenSpec 기획 변경은 커밋에 포함하지 않는다. 새 태그 배포의 전체 검사·설치형/ZIP 빌드·실제 패키지 복구/강제 종료·산출물 검증·정식 게시와 공개 파일 해시 확인 결과를 이어 기록한다.

# 데스크톱 검은 화면·업데이트 정체 예방 설계

2026-10-27 사용자가 설계를 승인하고 구현·배포를 요청했다.

## 목표와 선택

Windows에서 GPU 충돌 때문에 화면이 그려지지 않는 문제와, 실행할 수 없는 과거 기록 때문에 업데이트가 막히는 문제를 예방한다. 기본 소프트웨어 렌더링을 권장안으로 선택했다. 충돌 뒤 자동 재시작은 진행 중 업무와 미저장 입력을 위험하게 만들고, 수동 설정만 제공하는 방식은 첫 장애를 예방하지 못하므로 채택하지 않는다.

## 그래픽 설정

`desktop/graphics.cjs`는 Electron 준비 전에 Windows에서 기본으로 `disable-gpu`를 적용한다. `%APPDATA%/OpenSpecBoard/graphics.json`의 `hardwareAcceleration:true`만 명시적인 가속 사용으로 인정한다. false는 모든 OS에서 가속을 끈다. 누락·손상·잘못된 타입은 OS 기본값을 사용한다. 보안 sandbox와 권한 정책은 유지한다.

## 화면 장애 감지와 복구

새 `desktop/renderer-recovery.cjs`가 주 프레임 로드 실패, 렌더러 종료, 응답 없음, React 준비 응답 지연을 감시한다. 복구 안내는 HTML이 아닌 네이티브 대화상자로 표시하여 고장 난 화면에 의존하지 않는다. 사용자 선택 시 같은 창의 대시보드만 다시 불러온다. 미저장 입력이 사라질 수 있음을 안내하고, 기본 선택은 취소다. 대화 서버·업무 상태·질문·승인·실행을 변경하거나 재시작하지 않는다. 동시에 하나의 대화상자만 열고, 종료·설치 중에는 복구를 시작하지 않는다. 복구 실패는 한 번 안내하고 자동 재시도하지 않는다.

기존 소유 메인 프레임 전용 `desktop:attention-ready`를 화면 준비 확인에 재사용한다. 최초 로드 실패도 서버를 종료하지 않고 복구 경로로 보낸다. 무설치 업데이트 준비 완료 보고는 실제 화면 준비 응답 뒤에 수행한다. smoke 모드는 자동화 검사가 실패를 판정하며 사용자 복구 대화상자를 열지 않는다.

## 업데이트 유휴 판정

전송 결과 `uncertain` 메시지는 자동 전송 대상이 아니므로 종료를 막지 않는다. `expired` 질문은 복구 가능한 기록이지만 현재 응답 대상이 아니므로 종료를 막지 않는다. 기록은 그대로 보존한다. 실행 상태, 실제 미처리 질문·승인, 자동 전송 대기 메시지, 검증 실행과 처리 중 요청은 계속 차단한다.

## 검증과 배포

설정 누락·손상·true/false, 화면 실패·중복 오류·지연·종료 중 오류·복구 실패, 실제 업무의 차단 유지, 기록 보존을 테스트한다. 데스크톱·프런트엔드·백엔드 전체 검사와 빌드 후 별도 프로필의 실제 패키지 기동·종료를 확인한다. 이전 업무 계획 문서와 로컬 데이터는 릴리스 커밋에서 제외한다. v0.1.6 다음 정식 버전으로 설치형·무설치형을 기존 GitHub Actions 파이프라인에서 게시하고 원격 버전·파일·해시를 확인한다. 현재 설치 앱은 배포 작업 중 강제로 교체하지 않는다.

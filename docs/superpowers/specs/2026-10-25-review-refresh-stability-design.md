# 사용자 검토 배경 갱신 표시 안정화

## 확인한 증상
- 첨부 영상에서 검토 항목이 없는 상태가 배경 갱신마다 로딩 안내로 바뀐다.
- `useReviewItems`는 기존 데이터를 유지하지만 `ReviewItems`가 모든 갱신에 로딩을 표시하고 빈 목록 안내를 숨긴다.

## 승인한 설계
- 첫 조회처럼 기존 데이터가 없을 때만 로딩 안내를 표시한다.
- 배경 갱신 중 기존 목록과 빈 목록 안내를 유지한다.
- 갱신 결과는 그대로 반영하고 오류, 부분 실패, 재시도와 원문 이동 동작을 보존한다.
- 갱신 지연이나 서버·조회 로직 변경은 하지 않는다.

## 검증
- 항목이 있는 상태의 배경 갱신에서 로딩 안내가 추가되지 않는다.
- 빈 결과가 SSE로 반복 갱신되어도 기존 빈 목록 안내 노드가 유지된다.
- 초기 로딩, 갱신 후 결과 변경, 오류·부분 실패와 재시도 관련 기존 테스트를 실행한다.
- 프런트엔드 빌드와 데스크톱 앱의 사용자 검토 화면을 확인한다.

사용자가 위 동작과 후속 커밋을 승인했다. 세션 서버는 재시작하지 않는다.

## 실행 결과
- 수정 전 회귀 테스트 2개 실패를 확인했고 수정 후 관련 테스트 19개, 전체 프런트엔드 테스트 163개와 빌드가 통과했다.
- 열린 진단용 앱의 정적 파일을 갱신했다. 사용자 답변 입력을 보호하기 위해 새로고침하지 않았으므로 네이티브 화면의 수정 후 시각 검증은 수행하지 않았다.

# v0.1.11 무설치 업데이트 ASAR 쓰기 오류 수정

## 사용자 증상과 재현

사용 중인 설치 경로는 `D:/sklee/1.util/OpenSpecBoard-0.1.2-win-x64-portable`이며 실제 build-info와 화면 버전은 0.1.6이었다. 0.1.10 ZIP 477,998,425바이트가 완전히 다운로드됐으나 화면은 다운로드 이후 종료·백업·설치 단계 실패를 표시했다. 새 교체 job은 생성되지 않았고 실제 업무 화면은 AI 대기, 진행 중 업무 0개였다. 디스크 여유 공간도 충분했다.

동일 ZIP과 설치본의 portable-install 코드를 일반 Node에서 실행하면 준비가 성공했지만, 실제 Electron에서 설치본 ASAR 모듈을 읽어 새 격리 폴더로 준비하면 `Invalid package .../resources/app.asar`가 WriteStream 생성 단계에서 재현됐다. Electron은 ASAR 경로를 가상 파일 시스템으로 취급하므로 압축 해제 중 아직 불완전한 보관 파일을 해석하려다가 실패했다. 이전 일반 Node 단위 검사와 앱 기동·종료 검사는 이 경계를 실행하지 않았다.

## 수정과 검증

Electron일 때 압축 payload 출력과 필수 payload 파일 stat에만 `original-fs`를 사용한다. ASAR 내부 portable-swap helper를 읽고 복사하는 기존 fs 경로는 유지한다. ZIP 경로·크기·해시·링크·버전·폴더 소유권 검사는 변경하지 않는다.

- Electron 가상 fs가 `.asar` 출력·stat를 가로채는 회귀를 추가해 수정 전 실패와 수정 후 성공을 확인했다.
- 관련 portable-install 33개, 데스크톱 전체 199개 통과. 새 패키지 생성과 스크립트 문법 검사 통과.
- 별도 실제 Electron host에서 패키지 ASAR의 업데이트 모듈을 사용해 공개 ZIP을 압축 해제하고 독립 helper로 임시 앱 폴더를 교체했다. 기존 폴더 백업 보존, 후보 버전·무설치 모드, 후보 앱 재시작과 정상 백업·실제 앱/서비스 프로세스 종료를 확인했다.
- 새 CI 단계는 무설치 ZIP 생성 뒤 같은 실제 ASAR·폴더 교체 검사를 수행한다. 검사 제한 시간에는 자신이 시작한 격리 host만 종료하고 후속 판정도 중단한다. 운영 앱이나 사용자 프로필을 검사 대상으로 사용하지 않는다.
- 독립 리뷰에서 검증 도구의 제한 시간 문제를 확인해 수정하고 재검토한다.

## 배포와 실제 설치

v0.1.11 새 태그로 전체 검사와 설치형·무설치형 배포를 수행한다. 게시 후 공개 파일 해시를 확인하고, 현재 구버전의 같은 ASAR 오류가 새 ZIP 설치를 막으므로 검증된 외부 Node 업데이트 준비 경로로 일회 복구한다. 기존 앱은 정상 종료하여 DB 백업을 확인하고 독립 교체 helper로 같은 설치 경로를 교체한다. 사용자 프로필과 기존 프로그램 폴더 백업을 보존하며, 실행된 앱 화면·build-info·소유 프로세스의 버전이 최신인지 확인한다. 13003 개발 세션 서버는 종료하지 않는다.

- 소스 `1a7c6340b4920141dc90b1830fa9dc9c19e396b6`, [배포 실행 40802870425](https://github.com/sklee385/open_spec_dashboard/actions/runs/40802870425)의 build·release가 모두 성공했다.
- 원격 데스크톱 199개·프런트엔드 272개·백엔드 331개, 총 802개 통과 및 기존 2개 건너뜀. 실제 ASAR 압축 해제·독립 helper·폴더 교체·기존 앱 백업·후보 v0.1.11 재시작·정상 종료도 통과했다.
- [v0.1.11 정식 릴리스](https://github.com/sklee385/open_spec_dashboard/releases/tag/v0.1.11)가 최신이며 필수 5개 파일을 확인했다. 공개 EXE 380,408,525바이트·ZIP 477,998,817바이트·blockmap 394,592바이트를 실제 다운로드하여 SHA-256을 확인했고, EXE·ZIP SHA-512와 두 메타데이터 무결성도 통과했다.

- 교체 전 화면 확인 중 Computer Use가 물리적 Escape 입력으로 중단되어 추가 화면 제어와 실제 앱 종료·교체는 수행하지 않았다. 설치 경로의 실제 버전은 아직 0.1.6이며 정상 종료·백업·교체·실행 화면 확인이 남아 있다. 운영 데이터와 기존 실행 앱, 13003 세션 서버는 유지했다.

## 실제 설치 교체 완료

사용자가 직접 최신 버전 설치를 재요청하여 2026-10-29 11:49 KST에 같은 설치 경로를 0.1.6에서 0.1.11로 교체했다.

- 검증된 공개 ZIP으로 실제 설치 폴더 옆에 새 후보를 준비했다. 기존 앱의 AI 대기 상태와 빈 입력을 확인하고 앱 메뉴의 정상 종료를 사용했다. `normal shutdown and backup completed` 및 기존 앱·서비스 프로세스 종료를 확인했다.
- 종료 후 기존 SQLite `quick_check`를 통과하고 독립 교체 helper를 실행했다. 작업 `8d0fa20cfc25cc06a53c19c52b2ef927`의 journal은 `complete`이며 후보 시작 확인까지 성공했다.
- 실제 설치의 build-info와 실행 화면 모두 v0.1.11이다. 동일 설치 경로의 새 앱·서비스 소유 관계와 AI 대기·응답 요청 0개를 확인했다. 전체 상태 점검·화면 복구·강제 종료 메뉴 및 동봉 긴급 종료 도구도 확인했다.
- 사용자 데이터는 `%APPDATA%/OpenSpecBoard`에 유지했다. 정상 종료 데이터 백업은 `backups/2026-10-29T02-48-55-981Z`, 기존 프로그램 폴더는 설치 폴더 옆의 `.OpenSpecBoard-0.1.2-win-x64-portable-backup-8d0fa20cfc25cc06a53c19c52b2ef927`에 보존했다. 폴더 이름은 기존 바로가기를 유지하며 실제 앱 버전은 0.1.11이다.
- 13003 개발 세션 서버와 기존 다른 OpenSpec 기획 파일은 변경·종료하지 않았다.

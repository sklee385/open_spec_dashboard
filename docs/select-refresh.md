# 프로젝트 선택 목록의 갱신 중 닫힘

v0.1.23 Header는 렌더 함수 내부에서 SourceSelect 컴포넌트를 정의했다. 활동 상태나 소스 목록이 갱신될 때마다 새 컴포넌트 타입이 생겨 Select subtree가 remount되고, 열린 목록과 포커스가 사라졌다. 활동 조회는 약 2초, 보드/SSE 보조 조회는 약 5초 주기이므로 사용자 선택 없이도 발생할 수 있었다.

헤더의 소스 선택 부분을 기존 소스 관리 버튼과 같은 직접 렌더 helper로 바꿔 Select의 React identity와 DOM을 유지한다. 갱신 주기, 선택 값의 소유자, 안전 잠금과 요청 처리는 변경하지 않는다.

## 합성 검증

Codex 내장 브라우저에서 실제 Header와 2초 활동/5초 소스 갱신을 사용하는 독립 fixture로 확인했다. 네트워크 요청은 fixture의 합성 API만 사용했다.

- 수정 전: 사용자가 목록을 연 뒤 선택하지 않았는데 갱신으로 닫혔다. 활동 7회·소스 3회 시점에 trigger 교체 9회를 관측했다. 문서 boot 식별자와 timeOrigin은 처음과 같았다.
- 수정 후: 활동 8회·소스 3회 시점에도 목록과 포커스가 유지됐고 trigger 교체는 0회였다. 같은 문서에서 사용자가 선택한 소스가 정상 반영됐다.
- 설정 창의 합성 도구 이름을 저장하지 않은 채 편집해도 이후 갱신 중 초안과 포커스가 유지됐다. 설정 조회 카운터는 1이었다.
- 자동 회귀는 열린 목록·선택·포커스·설정 초안 보존 및 업무 전환 후 역전 응답 무시를 포함한다. 직접 영향 5개 파일 10개 검사가 통과했고 프런트엔드 빌드가 통과했다.

이 재현은 문서 전체 navigation/reload가 아니라 하위 컴포넌트 교체였다. 개발 중 의도적인 fixture reload/HMR 회차는 측정 구간과 분리했다. React Profiler는 합성 Header에만 적용했으며 실제 앱 전체 CPU·메모리·입력 지연은 측정하지 않았다. 이 결과로 제품 전체가 무겁거나 모든 종류의 선택 상자 닫힘이 해결됐다고 단정하지 않는다.

로컬 검증 시점에는 운영 UI·실제 설정·업무 데이터·실행 프로세스를 조작하지 않았고, 전체 suite·공개 배포·운영 앱 교체를 수행하지 않았다. 이후 배포 시에도 단위검사는 위 직접 영향 범위로 제한하며 기존 필수 패키지·업데이트 smoke는 유지한다.

# 수동 관리 상태

업무 화면의 **수동 관리 상태**를 펼쳐 범위와 상태를 선택하고 사유를 입력한 뒤 반영한다. 업무 전체 범위는 보드 표시를 바꾸며 현재 실행 회차 범위는 그 회차의 관리 기록만 바꾼다. 관측된 업무 단계·실행 상태·런타임과 관리 표시를 함께 보여준다.

상태는 자동 표시, 관리상 진행 중, 관리상 완료, 관리상 보관이다. 관리상 보관은 관리상 완료 후 선택한다. 자동 표시로 되돌리면 원래 문서 기반 보드 상태가 표시된다. 보관한 항목은 보드의 보관된 변경 표시를 켜서 찾는다. 완료율·체크리스트·검증 기록은 그대로다.

실행 중이거나 종료 확인이 어려운 업무도 관리 목적으로 정리할 수 있다. OS 프로세스 종료, 실행 잠금 해제, 실제 업무 완료, OpenSpec 파일 보관 또는 작업 폴더 정리를 수행하지 않는다. 앱 종료와 후속 실행의 기존 안전 조건은 계속 적용된다.

## API와 감사 기록

`GET /api/work/:id/management?scope=work|run`은 관리 버전, 관측 버전, 회차, 관측 상태와 최근 변경 20건을 돌려준다. 전용 작업 폴더가 없어도 저장된 업무의 관리 상태를 조회할 수 있다.

`POST /api/work/:id/management`는 scope, runId, state, reason, expectedVersion, observation, requestKey를 받는다. 관리 버전·관측 버전·회차가 바뀌면 409로 거부한다. 동일 식별자·본문 재전송은 원래 영수증으로 확인하고 다른 본문으로 재사용하면 거부한다. 트랜잭션으로 관리 표시와 변경 이력을 함께 저장한다. 기존 Work 실행 필드와 완료 증거는 수정하지 않는다.

이력에는 업무·범위·회차·변경 전후·시각·사유를 기록한다. local-user는 로컬 앱 조작을 의미하며 별도 본인 인증을 증명하지 않는다. 화면은 최근 20건을 보여주며 기존 이력을 삭제하지 않는다. 사유에 인증정보나 비밀값을 입력하지 않는다.

응답 유실 시 **같은 요청 결과 확인**은 같은 식별자·본문만 재전송한다. 새 요청으로 자동 반복하지 않는다. 실제 실행 결과를 성공으로 판정하는 용도로 사용하지 않는다.

## 조회 지연

문서·OpenSpec 조회는 변경 잠금과 분리하고 조회만 취소할 수 있다. 같은 이벤트 회차의 중복 변경을 차단한다. 변경 응답 후 상태 조회가 느리면 안내하고 화면 이동을 허용하되 추가 변경은 최신 상태 확인 후 허용한다. 조회 실패 시 상태 다시 확인을 사용하며 변경 요청은 자동 재실행하지 않는다.

개발 기준은 공개 v0.1.21이다. 이 변경은 통합 MCP 설정·실제 업무 데이터·설치본 백업·운영 감사 자료를 포함하지 않는다. 검사는 합성 fixture와 변경·직접 영향 범위로 제한한다.

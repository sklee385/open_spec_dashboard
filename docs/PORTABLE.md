# OpenSpecBoard 무설치 실행

1. ZIP 전체를 쓰기 가능한 별도 폴더에 압축 해제합니다. ZIP 안에서 바로 실행하거나 EXE만 복사하지 마세요.
2. 기존 OpenSpecBoard가 실행 중이면 진행 중 업무와 문서를 정리하고 앱 메뉴의 '앱 종료'로 정상 종료합니다. 창 닫기는 트레이로 숨기는 동작입니다.
3. 압축을 푼 폴더의 OpenSpecBoard.exe를 실행합니다. 설치 프로그램과 별도 Node 설치는 필요하지 않습니다. AI CLI와 로그인은 기존 사용자 환경을 사용합니다.

데이터·설정·로그·백업은 기존 %APPDATA%/openspecboard에 보존합니다. 설치형과 같은 사용자 데이터·단일 인스턴스를 사용하므로, 이전 앱이 트레이에 남아 있으면 이전 창이 다시 열릴 수 있습니다. 사용자 프로젝트 문서는 앱 폴더 밖에 보관하세요.

Windows에서는 GPU 드라이버 충돌에 의한 검은 화면을 예방하도록 그래픽 가속을 기본으로 끕니다. `%APPDATA%/OpenSpecBoard/graphics.json`에 `{"hardwareAcceleration":true}`를 저장하면 다음 실행부터 가속을 명시적으로 사용할 수 있으며, false는 가속을 끕니다. 설정 누락·손상 시 Windows 안전 기본값을 사용합니다.

화면 로딩 실패·렌더러 종료·응답 없음 또는 30초 동안 준비 응답이 없으면 Windows 기본 대화상자로 복구를 안내합니다. 앱 메뉴와 트레이의 **화면 복구**에서도 같은 안내를 열 수 있습니다. **화면 다시 불러오기**는 화면만 갱신하며 대화 서버와 실행 중 업무를 유지합니다. 미저장 입력은 사라질 수 있으므로 기본 선택은 취소입니다. 종료·설치 준비 중에는 복구하지 않습니다.

v0.1.9부터 앱 메뉴·트레이의 **전체 상태 점검**에서 화면·서버 응답, 업무별 실제 실행과 저장 상태, 종료 차단 사유와 최근 장애 기록을 확인합니다. **업무 열기**로 해당 업무로 이동하거나, 실제 실행이 없다고 확인된 업무만 **상태 복구**할 수 있습니다. 실행 여부가 불명확하면 복구를 보류하며 중단 요청은 완료 알림을 확인할 때까지 실행 종료로 처리하지 않습니다.

정상 종료가 불가능하면 **강제 종료…**에서 내용을 확인한 뒤 종료할 수 있습니다. 화면과 메뉴까지 멈췄다면 앱 폴더의 **OpenSpecBoard 긴급 종료.cmd**를 실행합니다. 독립 도구는 이 설치가 기록한 앱·서비스의 PID·시작 시각·실행 경로와 자식 관계를 확인하고 해당 프로세스만 종료합니다. 소유권이 불명확하면 종료를 거절합니다. 미저장 입력이나 진행 중 파일 변경은 중단될 수 있습니다.

비정상 종료 후에는 **안전 모드**로 시작하여 새 실행과 대기 메시지 자동 전송을 보류합니다. 전체 상태 점검에서 확인한 뒤 명시적으로 해제합니다. 해제만으로 이전 메시지를 재전송하지 않습니다. 메시지·답변·문서·프로젝트 편집 초안은 입력 후 400ms 및 화면 이동 때 앱 프로필의 `recovery-drafts.json`에 저장하며, 실제 문서 저장과 별개입니다. 저장 실패는 화면에 안내하고 이동을 보류합니다. 강제 종료 직전 아직 저장되지 않은 입력까지 복구를 보장하지는 않습니다. 서버 문서가 바뀌었으면 충돌을 표시하고 자동 덮어쓰지 않습니다. 최근 장애 기록에는 사용자 입력 원문이나 인증 토큰을 넣지 않습니다.

무설치판도 앱 시작·4시간 간격·'앱 업데이트' 메뉴로 새 버전을 확인하고 전용 ZIP을 자동 다운로드합니다. 사용자가 '업데이트하고 재시작'을 선택하고 전체 업무가 유휴 상태일 때만 폴더를 교체합니다. 설치형 EXE를 실행하지 않습니다. 업데이트에는 앱 폴더와 상위 폴더의 쓰기 권한 및 새 파일·백업을 위한 여유 공간이 필요합니다.

업데이트는 기존 실행 폴더를 옆의 .폴더명-backup-... 폴더에 보존하고 새 앱을 같은 경로로 옮깁니다. 진단은 %APPDATA%/openspecboard/portable-updates/jobs/.../journal.json에 남습니다. 실패·불확실 상태에서는 백업과 데이터를 지우거나 여러 앱을 동시에 실행하지 말고 기록을 확인하세요. 새 앱이 DB를 열었던 경우 구버전의 데이터 호환성을 확인한 뒤 수동 복구합니다. 기존 백업은 자동 삭제하지 않습니다.

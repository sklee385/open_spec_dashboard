# 프로젝트 소스·Git 작업 공간

상단 **소스·Git**에서 등록 프로젝트를 선택한다. 왼쪽 파일 트리, 가운데 코드·편집·diff, 오른쪽 Git 패널을 사용한다. 업무가 없어도 소스를 탐색하고 커밋할 수 있다. 업무 화면의 **소스·Git**으로 이동하고 **업무·AI·검증**으로 돌아가면 같은 업무·대화 초안을 유지한다. AI 지시와 검증은 기존 업무 화면에서 명시적으로 실행한다.

**프로젝트 원본 / 업무 공간** 선택으로 AI가 실제 수정한 격리 공간을 열 수 있다. 업무 공간에서 코드를 직접 편집하고 같은 업무에서 검증한 뒤 기존 **원본 반영**을 수행한다. 커밋은 프로젝트 원본으로 전환해 진행한다. 복사 업무 공간에 Git 저장소가 없으면 자동 생성하지 않는다. 업무 공간은 등록 프로젝트에 연결된 활성 업무와 식별 정보가 확인된 경로만 허용하며 임의 경로는 입력받지 않는다.

## 파일 탐색과 편집

폴더는 펼칠 때 조회하고, 검색은 파일명·상대 경로 기준이다. 결과는 200개씩 제공한다. 기본으로 숨김·Git 무시 파일·의존성·산출물을 숨기며 **숨김·무시 파일 표시**로 확장한다. Git 관리 파일, 링크·junction, 앱 업무 DB·운영 데이터와 중첩 저장소는 열거나 변경하지 않는다. Git을 사용할 수 없어 무시 규칙을 적용하지 못하면 안내한다.

원문은 자동 정렬 없이 줄 번호와 구문 강조로 표시한다. **편집** 후 저장하며 UTF-8 텍스트의 BOM·줄바꿈·파일 끝 개행을 보존한다. 파일당 텍스트 한도는 1 MiB다. 바이너리·지원하지 않는 인코딩·크기 초과 파일은 제한 이유를 표시한다. 파일·프로젝트·화면 이동은 미저장 내용이 있으면 저장·편집 폐기·이동 취소를 선택한다. 브라우저 종료에는 브라우저 이탈 경고를 사용한다.

새 파일·폴더 생성, 이름 변경·이동, 파일 삭제를 제공한다. 기존 경로를 덮어쓰지 않는다. 폴더 재귀 삭제는 제공하지 않는다. 삭제는 대상·Git 상태·미저장 영향 확인 후 실행한다. 열어 둔 파일이 외부에서 수정·삭제·다른 종류로 교체되면 저장을 거부하고 초안과 최신 내용을 구분한다. 폴더 이동 사전 확인은 제한된 하위 메타정보를 사용하며, 너무 큰 폴더는 한도를 안내한다.

## 작업 공간 위치 초기 설정 (도입 중)

설정 → **작업 공간 저장 위치**에서 실행 호스트의 절대 로컬 경로를 입력한다. 데스크톱에서는 **폴더 선택**도 사용할 수 있다. 취소하면 초안을 유지한다. 웹 화면에서 입력한 경로는 브라우저 PC가 아니라 서버 호스트 기준이다.

1. **경로 검사**를 누른다. 기존 실부모부터 링크와 보호 영역을 검사하고 고유 probe 파일만 생성·읽기·삭제한다. 아직 없는 선택 폴더는 이 단계에서 만들지 않는다.
2. 표시된 `openspecboard-<profileId>` 관리 하위 폴더를 확인하고 확인란을 선택한다.
3. **확인한 위치 저장**으로 해당 폴더와 소유 식별을 등록한다. 검사 결과는 5분 동안 유효하며 경로·설정 버전이 바뀌면 다시 검사한다.

명시적 `WORKSPACE_ROOT` → 저장 설정 → 미설정 순으로 표시한다. 환경 고정에서는 경로 편집을 차단하지만 최초 검사·확인은 필요하다. 경로를 바꿔도 기존 업무의 경로를 옮기지 않는다. 설정은 기존 config 파일의 `workspaces` 키에 저장하며 프로젝트·도구 설정을 보존한다. 두 창의 오래된 저장은 거부하고 **최신 설정 조회 · 초안 유지**로 새 버전을 비교한다.

UNC·드라이브 루트·링크·junction·원본·Git 공통 관리·운영 데이터·설정·설치 영역과 양방향으로 겹치는 경로는 사용할 수 없다. ACL을 변경하지 않는다. 잔여 용량을 확인할 수 없으면 **미확인**으로 표시한다. 검사와 저장 사이 외부 변경은 재검사하며, 앱 밖 도구의 경합을 OS 수준에서 완전히 봉쇄하는 기능은 아니다.

설정 파일 저장은 같은 디렉터리의 임시 파일을 원자 교체하고 `<configPath>.lock.sqlite`의 SQLite 트랜잭션 잠금으로 프로세스 간 저장을 직렬화한다. 이 DB에는 설정 값을 저장하지 않으며, 잠금 소유 프로세스가 비정상 종료해도 OS가 점유를 해제한다. 잠금 DB 파일을 삭제해서 복구하지 않는다. 관리 폴더 유실·소유 정보 변경은 가용 상태에서 제외하고 오류를 표시한다.

현재 구현은 초기 설정 단계다. 공통 공간 서비스와 신규 생성 연결·통합 후보 기능은 후속 구현 대상이며, **위치 저장만으로 기존 복사 생성 경로가 전환되거나 새 Git 워크트리 기본값이 활성화되지는 않는다**. 실제 업무 전용 폴더는 기능 연결 후 사용자가 이 화면에서 선택한다. 13003 세션 서버에는 아직 운영 반영하지 않았다.

## Git 조회와 변경

Git 상태는 실제 저장소 기준이다. **staged**는 HEAD→인덱스, **unstaged**는 인덱스→작업 트리다. 같은 파일에 두 종류 변경이 있으면 양쪽에 표시한다. 업무 시작 스냅샷의 변경 결과와는 기준이 다르다. diff 양쪽 합계 2 MiB 초과·바이너리·지원하지 않는 텍스트는 요약과 제한 이유를 표시한다.

파일 단위 스테이징·해제 후 메시지를 입력해 **전체 인덱스 커밋**을 한다. 다른 도구에서 이미 스테이징한 파일도 커밋에 포함되므로 전체 목록을 확인한다. 상태가 바뀌었으면 오래된 요청을 거절하고 새로고침을 요구한다. 제한된 파일이 인덱스에 있으면 커밋을 막는다. 훅·서명 실패는 우회하지 않는다.

커밋 성공 시 실제 생성된 커밋을 열어 메시지·해시·작성자·시각·변경 파일·diff·당시 파일 원문을 확인한다. 삭제 파일은 부모 원문임을 명시한다. 이력은 50개씩 제공하고 merge 커밋은 첫 번째 부모와 비교한다. 과거 원문은 읽기 전용이며 현재 파일을 덮어쓰지 않는다.

로컬 브랜치 생성·전환과 fetch·pull·push를 제공한다. 브랜치 전환과 pull 전에는 미저장 편집·staged/unstaged/untracked 변경을 정리해야 한다. 강제 전환·자동 stash·force push는 제공하지 않는다. 프로젝트 폴더와 저장소 루트가 일치해야 변경할 수 있다. 파일·stage·커밋은 해당 공간과 실제 HEAD/ref를 점유하고, 다른 업무 공간은 독립 실행한다. 계획 문서만의 편집은 변경 폴더별로 점유한다. 공유 관리/ref 작업은 common-dir 관리 잠금을, 브랜치 전환·원본 반영·보관은 통합 잠금을 사용한다. fetch·pull은 원격 추적 ref도 갱신하므로 공유 관리와 기존 ref를 함께 보호한다.

worktree 추가의 관리 잠금은 실제 생성 구간에만 유지한다. 설치·빌드 중에는 해당 준비 공간과 원본 변경 문서의 점유만 유지하며 다른 업무의 관리 잠금을 장시간 보유하지 않는다. 잠금 취득 순서는 통합→관리→정렬 공간→ref이며 충돌 요청을 자동 대기·재실행하지 않는다. 범위가 저장된 미확인 Git/준비 프로세스는 영향 공간·ref를 계속 차단한다. 범위 없는 과거 기록은 공통 저장소 경계로 보수적으로 차단한다. 생성/기준 커밋의 응답 유실은 실제 등록·커밋과 프로세스 종료를 확인한 뒤 같은 고정 공간에서 복구한다.

pull은 `git pull --ff-only --no-rebase`로 fast-forward만 수행한다. 기존 pull·브랜치별 rebase 설정과 무관하게 merge/rebase를 시작하지 않으며 저장소 설정과 upstream을 변경하지 않는다. 새 통합 커밋이나 커밋 메시지도 만들지 않는다. 이력이 분기하면 실패로 표시하고 외부 Git 도구에서 정리한 뒤 새로고침하도록 안내한다. 자동 merge·rebase·stash·reset이나 정책을 완화한 재시도는 하지 않는다. fetch로 원격 추적 참조는 갱신될 수 있으나 분기 실패로 로컬 HEAD·인덱스·작업 트리를 통합하지 않는다.

push는 기존 upstream의 원격·브랜치를 대상으로 전송할 커밋을 확인한 후 수행한다. 인증·서명·훅 초기 환경은 외부에서 준비하고 앱은 자격 증명을 직접 저장하지 않는다. 필요한 대화형 입력은 우회하지 않고 실패 이유를 안내한다.

## 기존 Git 진행 상태와 실행 복구

이미 merge/rebase가 진행 중이거나 미병합 인덱스가 있으면 실제 상태와 대상 파일은 조회하되 스테이징·커밋·브랜치 변경·fetch·pull·push 등 모든 Git 변경을 막는다. 이전 앱 정책으로 시작한 작업도 동일하다. 앱에서는 충돌 해결 절차나 **계속·중단**을 제공하지 않는다. 외부 Git 도구에서 해결 또는 중단한 뒤 새로고침하면 실제 상태로 변경 가능 여부를 다시 판단한다. 일반 소스 편집과 파일 생성·삭제·이동은 기존 보호 규칙 아래 계속 사용할 수 있지만 Git 진행을 완료한 것으로 처리하지 않는다.

이전 정책의 작업 기록은 조회할 수 있고 삭제하거나 자동 성공 처리하지 않는다. 외부 정리 후에도 과거 명령을 자동 재실행하지 않는다. 타임아웃·연결 유실 등으로 결과가 불확실한 작업의 실제 상태 확인은 계속 제공하며 merge/rebase 계속·중단과 구분한다.

Git 작업은 ID와 요청 키로 기록한다. 연결이 끊겨도 같은 작업을 조회하며 자동 재실행하지 않는다. 결과가 불확실하면 **실제 Git/원격 상태 확인**을 통해 관찰한 내용을 확인한다. 원래 작업의 성공·실패를 추정해 바꾸지 않으며, 프로세스 종료를 확인하지 못한 동안에는 변경을 재개하지 않는다.

게이트웨이의 5xx 응답도 실행 여부를 확정하지 않고 요청 키를 보존한다. 요청이 서버에 도착하지 않아 기록 자체가 없는 경우에는 명시적인 실제 상태 확인으로 현재 상태를 관찰한다. 이 확인은 원래 명령을 다시 실행하거나 성공으로 판정하지 않는다.

AI 실행·연결·복구·질문·승인 대기 중에는 같은 작업 공간의 수동 변경을 서버에서 거부한다. 원본과 업무 A/B는 독립 공간이므로 다른 공간의 편집·실행은 유지한다. 파일·index/HEAD 변경은 해당 공간, 문서 변경은 공간과 변경 문서, ref 변경·공유 Git 관리 작업은 공통 저장소와 대상 ref 범위로 직렬화한다. 불확실한 작업도 기록된 영향 범위만 차단한다. 검증은 호스트 전용 사본에서 실행하며 원본 쓰기 잠금을 재취득하지 않는다. 원본·계획·세대가 바뀌면 검증 결과가 오래된 상태가 된다. 코드 변경은 기존 검증의 최신성을 무효화하며, 계획 문서 변경은 사용자 재검토가 필요하다. 커밋이나 검증 통과가 OpenSpec 업무 완료를 의미하지 않는다.

소스·Git의 작업 위치 아래에는 서버가 확인한 공간 종류(원본/복사/Git 워크트리), 실제 경로, 브랜치와 기준을 표시한다. Git 업무는 시작 커밋과 문서 반영 후 업무 비교 기준 커밋을 구분하고, copy는 저장된 파일 스냅샷을 기준으로 표시한다. Git을 사용할 수 없어도 공간 정보는 조회한다. 업무 선택과 미저장 초안 보호는 기존 동작을 유지한다.

겹치는 변경 파일은 같은 프로젝트의 소유 확인된 활성 업무 사이에서 baseline 이후 변경(이미 커밋한 변경 포함)과 원본의 현재 Git 미커밋 변경 경로를 비교한 참고 정보다. 원본 선택 시 원본의 미커밋 변경과 각 업무 결과를 비교한다. 완료·보관·취소된 업무는 제외한다. 읽지 못한 공간·결과·제외된 변경이 있거나 원본 비교 기준을 확인할 수 없으면 부분 확인 경고를 표시하며, 겹침이 없다고 확정하지 않는다. 조회 시점의 경로 겹침은 내용 충돌이나 병합 성공 여부를 판정하지 않는다. Git 업무 결과의 원본 반영은 결과 커밋·후보 검증·명시적 확정 흐름을 사용하며, 후보 통합 기능은 아직 미제공이다.

주기적 겹침 조회는 전체 결과 본문·동기 소스 스냅샷을 만들지 않는다. Git 업무는 비동기 기준 대비 변경 경로·미추적 경로만 조회하고, copy는 저장된 경로·해시만 추출해 비동기 파일 비교 중 실행을 양보한다. 비교 요청 전체는 기본 1,000개 경로 항목·8 MiB 읽기·3초 예산을 공유한다. Git 출력은 명령별 256 KiB로 제한하며, copy의 200,000바이트 이상 파일·예산 초과·읽는 중 변경·링크 소유 불명은 부분 확인으로 남긴다. 부분 결과를 빈 변경 확정으로 사용하지 않는다. 소유 식별·Git 등록 검사는 유지하며 같은 요청에서 이미 확인한 선택 공간을 다시 검사하지 않는다.

## API

base는 `/api/projects/:sourceId`다. sourceId는 등록 ID이며 절대 프로젝트 경로·임의 명령은 입력받지 않는다. 상대 경로의 링크·Git 메타데이터·런타임 경계는 서버가 매번 검사한다. `showHidden=true`는 기본 필터만 확장하며 고정 제외는 해제하지 않는다.

모든 API는 선택 쿼리 `workId`를 받는다. 생략하면 원본이며 지정하면 같은 sourceId의 활성 업무와 검증된 작업 공간을 사용한다. 다른 프로젝트·없는 업무는 404, 완료·보관·변조된 공간은 409로 거부한다. 조회·수정·Git 작업·복구 키를 공간별로 구분한다.

| 메서드와 경로 | 입력·반환 |
| --- | --- |
| `GET /workspace` | 선택 `workId`. 서버 확인 공간 종류·실제 경로·브랜치·HEAD·시작/비교 기준 커밋·겹치는 변경 경로·부분 확인·조회 시각. 임의 경로 입력 없음 |
| `GET /tree`, `GET /search` | `path` 또는 `q`, `cursor`, `showHidden`. `{entries,nextCursor,ignoredUnavailable}` |
| `GET /entry?path=...` | 이동 전 파일·폴더의 종류·버전. 폴더는 내용 전체를 읽지 않는 제한된 하위 메타정보 버전 |
| `GET /file?path=...` | `{path,content,version,size,encoding,bom,newline,editable,reason?}` |
| `PUT /file` | `{path,content,version}`. 충돌은 409와 `latest`(없으면 null) |
| `POST /entries` | `{path,kind:file/directory,content?}`. 기존 경로가 있으면 거부 |
| `POST /entries/move` | `{path,target,version}`. 원본 버전 검사, 대상 덮어쓰기 금지 |
| `DELETE /file` | `{path,version,confirmed:true}`. 파일만 삭제 |
| `GET /git/status` | 저장소·브랜치·upstream·변경 파일·상태 토큰·진행 상태·원격·전송 예정 커밋 |
| `GET /git/diff` | `path`, `side:staged/unstaged/commit`, 선택 `commit`. `{before,after,base,reason?}` |
| `GET /git/branches`, `GET /git/log` | 브랜치 목록 또는 커서 기반 커밋 이력 |
| `GET /git/commits/:hash`, `GET /git/commits/:hash/file` | 커밋 상세 또는 `path`의 커밋 시점 원문 |
| `POST /git/operations` | `{kind,token,requestKey,paths?,message?,name?,remote?,confirmed?}`. 202와 작업 ID |
| `GET /git/operations/:id` | 같은 프로젝트의 ID 또는 요청 키로 작업 상태 조회 |
| `POST /git/operations/:id/reconcile` | `{confirmed:true}`. 불확실 작업의 실제 로컬·원격 관찰 결과와 확인 기록 |

Git 작업 kind는 stage/unstage/commit/create-branch/switch-branch/fetch/pull/push로 제한한다. continue-pull/abort-pull 요청은 기존 작업·요청 키 조회 전에 미지원 작업으로 400을 반환하며 Git 명령을 실행하지 않는다. 이 종류의 과거 저장 기록 조회와 불확실 상태 확인은 유지한다. 400은 입력 오류, 404는 없는 프로젝트·항목, 409는 상태·버전·실행 충돌, 413은 읽기·탐색 한도, 503은 Git 준비 불가다. 고정 제외 경로 접근은 403으로 거부한다. Git 미설치·비저장소는 상태 조회에서 이유를 제공하며 소스 탐색은 유지한다.

작업 기록은 DATA_DIR의 `project-git-operations`에 저장한다. 사용자 소스·커밋 메시지·자격 증명·원격 URL의 사용자정보를 작업 로그에 넣지 않는다. 일반 웹 게이트웨이 재시작은 상주 세션과 Git 작업을 종료하지 않는다. 실제 상주 서버 코드 반영은 모든 업무와 응답·승인 대기가 정리된 뒤 명시적으로 수행한다.

공간별 용량은 논리 파일 크기의 합계이며 실제 디스크 할당량·압축·외부 프로세스의 동시 변경까지 보장하지 않는다. 의존성/빌드/중단 잔여도 집계하며 링크를 따라가지 않는다. 공유 파일은 한 번만 합산한다. 집계 예산 초과·읽기 실패는 부분 집계로, 드라이브 확인 실패는 미확인으로 표시한다. 최소 잔여 검사만으로 전체 복사/설치/빌드의 예상 필요 공간을 보장하지 않는다.

신규 공간 준비 API는 현재 격리 개발 검증용이며 기본 비활성이다. 원본 계획을 검토한 뒤 Git 기준·제외 목록을 미리 보고, 프로젝트별 로컬 파일·런타임/의존성·설치/빌드 명령을 확인하여 준비한다. Git 문서만 명시적으로 커밋하고 로컬 비밀 파일은 별도 자료로 유지한다. 준비가 끝나도 AI 시작·원본 반영·완료·보관은 각각 별도 동작이다. API 계약은 `docs/API.md`의 업무 공간 준비 항목을 따른다.

비Git·초기 HEAD 없음만 명시 확인 후 copy를 사용한다. 기존 copy의 경로·baseline·대화 ID는 바꾸지 않는다. 신규 copy에서는 운영 데이터/로그와 `.aws`·`.codex`·`.reference`·로컬 비밀 파일을 복사 및 baseline에서 제외한다. Git 설치·경계·생성 실패는 copy로 우회하지 않는다. 생성 후 실제 `.git` 포인터와 Git 관리 디렉터리의 역참조, common-dir·등록·브랜치·소유를 대조하며 실패 잔여와 고정 경로를 보존한다. 만료된 생성 확인은 같은 공간에서 기준을 다시 확인할 수 있지만 변경된 기준을 자동 수용하거나 새 공간을 만들지 않는다.

로컬 준비 명령은 독립 런타임과 업무별 runtime-data/HOME/TEMP/cache를 사용한다. Windows 소유 Job Object 가드가 준비되지 않으면 명령을 시작하지 않으며 후손 정리까지 확인해야 성공이다. 원본 데이터·운영 토큰·명령 출력을 재사용/노출하지 않는다. 운영 서버 및 13003 세션 서버를 재시작하는 절차는 이 API에 포함하지 않는다.

## 후보 반영 결과 복구 (개발·검증 중)

반영 요청의 응답을 받지 못했으면 기존 요청 키를 보존하고 저장된 영수증을 먼저 확인한다. 기본 상태 조회는 저장 기록과 현재 실행 등록만 읽으며, 현재 파일의 실제 관측은 명시적으로 요청한다. 원본 HEAD가 같다는 이유만으로 종료 불명 실행을 해제하지 않는다. 실제 Job 종료와 같은 소유·실행 세대가 확인된 기존 요청만 현재 원본의 브랜치·index·파일·등록을 다시 검사해 확정할 수 있다.

과거 반영 뒤 업무나 후보 파일을 새로 편집했다면 그 파일을 되돌릴 필요는 없다. 명시 재확인은 새 편집을 보존하고 과거 반영과 구분하며, 관측하는 동안 다시 변경되면 중단한다. 원본이 dirty이거나 실행의 종료 근거가 없으면 미확인 상태를 유지한다. 이 재확인은 Git을 다시 실행하거나 새 편집을 검증 통과·업무 완료로 처리하지 않는다.

후보 취소는 파일·커밋·대화·검증 자료를 남기는 논리 취소다. 실행·질문·준비 작업·종료 불명 점유를 우회하는 강제 해제 버튼으로 사용하지 않는다. 이미 원본에 반영한 후보의 취소는 원본을 되돌리지 않으며, 실제 공간 삭제는 별도 수동 정리 절차다. API별 정확한 입력과 반환은 `docs/API.md`의 반영 상태 재확인 항목을 따른다.

개발 중인 후보 화면은 업무의 **후보 검증·원본 반영**에서 CLI 기준/결과, 원본 반영 사전 검사와 별도 명시 반영을 제공한다. 저장된 반영 영수증과 현재 원본 관측을 구분하고, 상태 자동 조회는 실제 파일 검사를 반복하지 않는다. 응답 유실 시 표시된 기존 요청을 재확인하며 새 요청을 자동 실행하지 않는다. 검증 실행 중단과 파일·대화를 남기는 후보 논리 취소도 별도 버튼이다. 과거 후보는 이력에서 다시 선택해 확인한다. Git 업무 완료·보관의 후속 연결과 결합 검증이 남아 있으므로 화면 연결만으로 운영 활성화·배포 완료로 계산하지 않는다.

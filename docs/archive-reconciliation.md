# 완료 변경 보관 점검 (2026-10-26)

## 원인

- 보드의 완료 열은 `tasks.md` 체크 수로 계산하지만 업무의 `phase`는 별도 DB 상태다. 체크 완료만으로 사용자 최종 완료 확인·원본 반영·검증 결과 저장·보관이 자동 실행되지는 않는다.
- CLI나 별도 작업으로 변경 폴더를 보관해도 DB 업무 상태를 맞추는 경로가 없었다. 보관 카드를 다시 열면 기존 아이디어를 활성 변경으로 다시 이동하려고 하여 실패하기도 했다.
- 웹과 데스크톱은 서로 다른 DB를 사용하여 한쪽을 정리해도 다른 쪽 상태는 남았다.

## 재발 방지

업무 조회·목록·기존 업무 재진입 시 활성 변경이 없고 정확히 하나의 유효한 보관 폴더가 있는지 검사한다. 정지 상태인 업무만 보관 상태로 복구하고 문서 스냅샷을 보존한다. 미해결 질문·실행 중 검증·대기 메시지·불확실한 프로세스 종료·복구 대기 상태는 종결하지 않는다. 이미 보관된 업무의 보관 재시도는 CLI를 다시 실행하지 않는다.

이 복구는 체크박스가 완료된 활성 변경을 자동 보관하거나 사용자 최종 확인을 대체하지 않는다. 실제 보관 폴더가 없는 업무의 기존 완료·검증 조건을 유지한다. 배포 프로그램의 재발 방지 코드는 다음 빌드 반영이 필요하며 이번 실제 DB 상태 수정은 이미 적용했다.

회귀 검사는 외부 보관 복구·같은 대화와 문서 유지·카드 재진입·보관 멱등성·목록 동기화·실행 보호·활성 변경 우선·질문 대기 보호·중복 보관 이름·빈 보관 폴더·종료 불확실성 보호를 확인한다.

## 검증 결과

- 현재 작업 폴더: 백엔드 빌드 성공, 보관 회귀 10개와 기존 workflow 21개(합계 31개) 통과.
- 부분 커밋 검증: Git 인덱스 내용만 `.data/archive-commit-check/`에 추출하여 TypeScript 검사와 보관·workflow 테스트 30개 통과. 기존 미커밋 구현에 의존하지 않는지 확인했다. 기존 중단 검사는 이미 보관한 업무를 강제로 재사용하던 fixture를 새 활성 업무로 바꾸었다.
- 전체 백엔드 검사: 280개 통과, 2개 제외, 5개 실패. `browser-runner.test.ts` 3건은 ‘검증 서버 종료를 확인하지 못했습니다’ 상태로 실패했고 `browser-service.test.ts` 2건은 실행 종료 대기와 20초 시간 초과로 실패했다. 이번 보관 수정 대상과 다른 기존 브라우저 실행 영역이며 전체 통과로 표시하지 않는다.
- 기본 명세 14개 엄격 검증 통과. 새 보관 폴더 5개 존재·활성 폴더 부재와 동기화 요구사항 41개의 기본 명세 반영을 대조했다.
- 실제 웹·데스크톱 DB 재검사에서 보관 폴더와 상태가 어긋나는 대상이 각각 0건임을 확인했다. 이번 수정에 대한 별도 브라우저 화면 검증은 수행하지 않았다.
- 보관한 원본 아이디어 문서의 기존 줄 끝 공백은 원문 보존을 위해 유지했다.

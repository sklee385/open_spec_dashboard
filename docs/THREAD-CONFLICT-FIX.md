# 동일 대화 점유 충돌 복구

2026-10-25: 대시보드가 `thread/resume`으로 기존 대화를 재개하려 할 때 Codex 앱이 동일 대화의 writer lock을 보유하여 실패했다. Windows Restart Manager 조회로 해당 lock 소유자가 데스크톱 Codex 앱 프로세스임을 확인했다. Volta 실행 체인의 여러 node 프로세스는 독립 백엔드들이 아니었다.

프런트엔드는 Nest 오류 응답의 일반 `error: Conflict`를 구체적인 `message`보다 우선 표시했다. 이를 수정했다. 기존 영문 writer 오류도 한국어 안내로 표시한다.

네이티브 writer 충돌은 `thread-in-use`로 구분하여 문서·대화 ID·기록을 보존한다. 같은 대화 다시 연결 버튼은 `POST /api/work/:id/reconnect`를 호출해 저장된 threadId로 resume만 수행한다. 새 대화 생성, 사용자 메시지 재전송, 구현 시작은 하지 않는다. 연결되면 오류와 복구 상태를 해제하고 사용자가 다음 동작을 선택한다. 다른 앱의 점유가 유지되면 안전하게 충돌을 표시한다.

운영 복구: Codex 앱에서 해당 업무 대화의 점유를 해제한 뒤 대시보드에서 같은 대화 다시 연결을 누른다. 다른 대화가 있는 Codex 앱 프로세스 강제 종료나 잠금 파일 삭제는 하지 않는다. Windows 백엔드 재시작은 Volta shim이 아니라 리스닝 중인 실제 Node 실행 파일과 프로세스를 식별한다.

검증: 백엔드 Codex 통합 테스트 15개와 업무 화면 테스트 13개가 통과했다. 프런트엔드·백엔드 빌드를 각각 통과했다. 시스템 메모리 부족으로 첫 프런트엔드 검증이 중단됐으나 Node 메모리 옵션을 조정한 뒤 재검증했다. 사용자의 점유 해제 지시에 따라 실행 중이 아닌 해당 Codex 대화만 일시 보관한 뒤 즉시 복원하여 점유 해제를 시도했다. 대화 ID와 원본 기록을 유지한다.

실제 복구 완료: `d8ca69a8-d76c-4be5-948a-4525a15e02e8` 업무의 reconnect 응답에서 기존 `01a17060-d2b9-7d23-9381-7ba10ae8831d` 대화 ID, `state=idle`, 오류 해제를 확인했다. Edge에서도 ‘문서 검토 완료 · 대화 가능’ 및 기존 문서를 확인했다. 구현 작업은 자동으로 시작하지 않았다.

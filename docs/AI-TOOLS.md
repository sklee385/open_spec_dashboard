# AI 개발 도구 설정

설정 메뉴의 **AI 개발 도구**에서 새 업무의 기본 도구를 선택한다. 최초 기본값은 Codex다. 외부 도구를 추가하여 ID·이름·실행 파일 절대 경로·JSON 인자 배열·입력 방식·제한 시간을 저장한다. 저장이나 준비 상태 조회는 CLI를 실행하지 않는다. 준비 상태는 파일·실행 권한만 확인하며 설치와 인증은 사용자가 CLI에서 직접 수행한다.

설정 변경은 새 업무에만 적용한다. 기존 업무의 이름·실행 설정·기능은 생성 시 저장한 스냅샷을 사용한다. 참조 중인 도구 삭제는 영향을 받는 업무 이름과 함께 거부한다. 기존 도구 필드 없는 업무는 Codex로 해석하며 threadId·문서 검토 버전·이벤트 원본은 재작성하지 않는다.

## 외부 CLI 호환 계약

외부 도구는 터미널 상호작용 없이 UTF-8 텍스트를 받아 stdout으로 응답하고 종료하는 프로그램이어야 한다. shell 없이 인자 배열로 실행하며 작업 디렉터리는 업무 프로젝트다. 실행 파일은 `.exe` 등 직접 실행 가능한 파일을 지정한다. Windows `.cmd`·`.bat` 중계기는 피하고 실제 실행 파일과 스크립트 경로를 인자로 지정한다.

테스트 fixture `backend/test/fixtures/external-cli.cjs`를 사용한 stdin 예제:

```json
{
  "id": "local-cli",
  "name": "로컬 CLI",
  "kind": "external-cli",
  "executable": "C:\\absolute\\node.exe",
  "args": ["C:\\absolute\\open_spec_dashboard\\backend\\test\\fixtures\\external-cli.cjs", "echo"],
  "input": "stdin",
  "timeoutMs": 600000
}
```

fixture의 `echo` 모드는 stdin 전체를 읽고 stdout에 같은 텍스트를 출력한다. 단독 인자 방식은 `input`을 `argument`로, 인자를 `["C:\\absolute\\open_spec_dashboard\\backend\\test\\fixtures\\external-cli.cjs", "argument", "{prompt}"]`로 설정한다. `{prompt}`는 하나의 독립된 인자여야 하며 문자열 안의 부분 치환은 지원하지 않는다. shell 기호도 인자의 텍스트로 전달한다.

운영체제의 명령줄 길이 제한은 입력 256KiB 제한보다 작을 수 있다. 인자가 너무 길면 `argument-limit` 실패로 기록한다. 긴 문서·대화는 stdin 방식을 사용한다. 기존 업무의 입력 방식을 바꾸려면 등록 설정을 수정한 뒤 새 업무를 만든다.

입력에는 현재 업무 ID·단계·요청, 저장 대화와 최신 계획 문서의 경로·내용을 포함한다. 계획 단계에는 제품 코드 구현 금지 지침을 포함한다. UTF-8 입력 256KiB를 넘으면 자르지 않고 축약 필요 오류를 표시한다. stdout은 순차 업무 이벤트로 저장하며 출력 합계(stdout+stderr)는 2MiB, 기본 제한 시간은 10분이다. 비정상 종료·빈 응답은 실패이며 stderr는 인증 실패 등 제한된 진단 분류에만 사용하고 원문은 저장하지 않는다.

저장 대화 맥락·텍스트 응답·중단을 지원한다. 구조화 질문·승인·공급자 고유 세션 재개는 미지원이다. 필요한 질문은 일반 대화로 주고받는다. CLI별 JSON 프로토콜은 해석하지 않는다. 외부 CLI는 사용자 환경 권한으로 실행되며 앱이 Codex 샌드박스나 승인 정책을 제공하지 않는다. 비밀값·환경변수 저장 UI는 제공하지 않는다.

동시에 같은 업무를 실행할 수 없다. Windows는 Toolhelp 프로세스 목록으로 자식부터 종료하며 POSIX는 별도 프로세스 그룹을 종료한다. 종료를 확인하지 못하면 복구 필요로 남긴다. 실행 중 서버가 재시작된 업무는 기록을 보존하고 복구 필요로 표시하며 자동 재실행하지 않는다. 사용자가 외부 프로세스·결과를 확인하고 명시적으로 새 메시지를 요청해야 한다. 최신 계획 검토와 명시적 구현 시작, 검증, 사용자 완료 확인은 도구에 관계없이 필요하다.

## 저장·운영·롤백

`ai-tools.json`은 `CONFIG_PATH`(또는 `OPENSPEC_UI_CONFIG`, 기본 `config.local.json`) 옆에 별도로 저장한다. 프로젝트 경로 설정을 저장해도 유지된다. 손상 파일은 오류로 표시하며 Codex 기본값으로 조용히 덮어쓰지 않는다. 원본을 백업하고 형식을 복구한다.

`GET /api/ai-tools`는 `version`, `defaultToolId`, 도구별 `capabilities`·`readiness`를 반환한다. `PUT /api/ai-tools`는 읽은 `version`과 전체 목록을 보내야 한다. 성공 시 임시 파일을 원자 교체하며 최신 버전을 반환한다. 충돌 시 409와 최신 설정을 반환하고 저장되지 않은 초안은 화면에 보존한다. 다시 불러오기는 초안을 교체하므로 비교 후 사용한다. 기존 `/api/codex` 상태 API는 유지한다.

DB와 도구 설정을 함께 백업한다. 이전 버전 서버로 바로 롤백하면 외부 도구 업무를 Codex로 잘못 해석할 수 있다. 롤백 전에 외부 도구 업무의 실행을 차단하고 원본 데이터를 보존해야 한다. 세션 서버는 실행·질문·승인 대기 중 재시작하지 않는다. 모든 업무가 멈춘 뒤 `./scripts/restart.ps1 -Service session`으로 변경을 반영한다.

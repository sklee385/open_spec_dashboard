# 읽기 전용 일일 현황판

구현 브랜치: `codex/readonly-daily-dashboard`. **미배포 기능**이다. 공개 v0.1.20과 현재 정상 실행 중인 앱에는 이 후속 기능을 추가하지 않았다.

## 사용 흐름

헤더의 **일일 현황**에서 날짜와 표시 시간대(한국 UTC+09:00 / UTC)를 선택한다. 모바일에서는 메뉴 안에 있다.

- **선택 날짜의 활동**: 주요 기록이 있는 고유 업무와, `completed + confirmed`로 명시 완료한 업무 수다. AI 턴 종료는 업무 완료로 세지 않는다.
- **현재 상태**: 조회 시각에 확인한 입력·승인 대기, 실행 근거, 종료 불명, 저장된 오류 상태를 구분한다. 과거 날짜를 선택해도 이 영역은 지금 상태다. 저장된 `running` 문자열만으로 실행 중이라 판단하지 않는다.
- **이전부터 미해결·시각 확인 필요**: 생성 시각이 확인된 pending 질문은 선택 날짜 이전부터 남았는지 표시한다. 오류·실행의 시작을 현재 자료에 확실히 연결할 수 없으면 발생 시각 확인 필요로 둔다. 마지막 활동 시각이나 파일 수정 시각으로 상태 시작을 추정하지 않는다. 이 목록은 날짜 활동 목록과 겹칠 수 있다.
- **주요 이력**: 업무 이름을 누르면 날짜 범위 이력이 열린다. 이전 날짜 포함과 이전 기록 더 보기로 서버 페이지를 조회한다. 원문 대화로 이동하면 선택한 메시지/기록을 강조하며, 오래된 메시지도 해당 범위로 표시한다. 원문 화면은 기존 업무 공간이며 현황판 자체는 실행·재실행·상태 변경을 요청하지 않는다.

## 시간과 중복

기존 UTC 저장값과 원본 seq를 보존한다. 첫 메시지 기록의 시각이 없으면 현재 시각을 만들어 넣지 않고 기록 없음으로 표시한다. 원문 대화의 시각은 UTC로 명시하고, 현황판은 선택한 시간대로 표시한다. AI 메시지의 첫 기록과 완료 이벤트 시각은 서로 다를 수 있다.

stream 조각·heartbeat·연결 알림은 주요 활동 수를 늘리지 않는다. 같은 turn/item의 완료 재통지는 첫 기록 기준으로 제거하여 다음 날짜 재연결도 새 활동으로 세지 않는다. 같은 사용자 문장이 실제로 두 번 전송된 별도 seq는 별도 메시지로 보존한다. 고유 업무 수와 실행 회차는 별개다. 최근 활동이 없다는 이유로 멈춤을 판정하지 않는다.

## 조회 계약

`GET /api/daily?date=2026-11-01&zone=Asia/Seoul&bucket=activity&page=1&limit=25`는 날짜별 SQL 집계와 현재 근거를 반환한다. `sourceId`로 프로젝트, `bucket=carryover`로 미해결/시각 불명 목록을 선택한다. 목록 최대 크기는 50이다.

`GET /api/daily/:workId/events?date=2026-11-01&zone=Asia/Seoul&scope=day&limit=30`은 주요 이력과 `nextBefore`를 반환한다. `scope=all`로 이전 날짜를 포함하며, `before=nextBefore`로 다음 과거 페이지를 읽는다. 원문 미리보기는 240자다. 전체 이벤트 payload를 브라우저로 내려받아 집계하지 않는다. 원문을 명시적으로 열 때는 기존 업무 상세 조회를 사용한다.

조회는 업무·records·events를 갱신하지 않는다. WorkStore 시작 시 조회용 인덱스 2개만 준비하며 과거 데이터나 시각을 보정하지 않는다. 자동 상태 변경·자동 재실행·AI 자동 요약·생산성 점수는 없다.

## 검증과 게시

변경/직접 영향 검사만 수행한다. `scripts/test-release.cjs --list`는 이 변경의 향후 관련 검사 목록을 출력한다. 이 기능의 CI 실행·공개 릴리스·설치 파일 생성·현재 앱 재업데이트는 수행하지 않았다. 전체 검증이 필요하면 이유·장시간 소요·예상 시간(모르면 미확인)을 설명하고 사용자 명시 승인을 받는다.

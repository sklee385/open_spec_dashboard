# ai-tool-selection Specification

## Purpose

사용자가 설정 메뉴에서 기본 AI 개발 도구를 선택하면서 기존 Codex 업무와 대화의 연속성을 유지하도록 한다. 등록한 외부 도구의 연결 상태와 지원 기능을 확인하고 새 업무에 선택 결과를 명시적으로 적용한다.

## Requirements

### Requirement: 기본 Codex와 설정 메뉴
시스템은 설정이 없을 때 Codex를 기본 도구로 사용하고 설정 메뉴에서 Codex 및 등록된 외부 AI 도구를 선택·저장할 수 있게 해야 한다(SHALL). 잘못된 설정 저장 요청은 이전 설정을 보존한 채 거부해야 한다(SHALL).

#### Scenario: 최초 실행
- **WHEN** AI 도구 선택 설정이 없는 상태에서 업무를 만든다
- **THEN** Codex가 선택되며 기존 Codex 동작이 유지된다

#### Scenario: 다른 도구 저장
- **WHEN** 사용자가 설정 메뉴에서 유효한 외부 도구를 기본값으로 저장한다
- **THEN** 설정이 재시작 후에도 유지되고 이후 새 업무에 해당 도구가 적용된다

### Requirement: 외부 도구 등록과 준비 상태
시스템은 사용자가 이름·실행 파일·인자 배열을 지정하여 비대화형 텍스트 입출력을 지원하는 외부 CLI 도구를 등록할 수 있게 해야 한다(SHALL). 등록·선택·준비 상태 확인만으로 개발 작업을 시작해서는 안 된다(MUST). 미설치·잘못된 설정·실행 실패를 구분하여 표시해야 한다(SHALL).

#### Scenario: 실행 파일을 찾을 수 없음
- **WHEN** 등록된 외부 도구의 실행 파일을 찾을 수 없다
- **THEN** 사용 불가 원인을 표시하고 다른 도구로 자동 전환하지 않는다

#### Scenario: 지원되지 않는 대화형 도구
- **WHEN** 외부 CLI가 터미널 상호작용이나 지원하지 않는 입력을 요구하여 요청을 처리하지 못한다
- **THEN** 실행 실패 또는 제한을 표시하고 완료로 처리하지 않는다

### Requirement: 업무의 도구 연결 고정
시스템은 업무 생성 시 선택한 도구와 실행 설정을 업무에 고정하고 이후 기본값 변경으로 기존 업무를 변경해서는 안 된다(MUST). 기존 저장 업무에 도구 정보가 없으면 Codex로 해석해야 한다(SHALL).

#### Scenario: 기본값 변경 후 기존 업무 재개
- **WHEN** 사용자가 기본 도구를 변경한 뒤 기존 Codex 업무를 다시 연다
- **THEN** 기존 Codex 대화와 도구 연결을 그대로 사용한다

#### Scenario: 업무가 참조하는 도구 삭제
- **WHEN** 사용자가 기존 업무가 참조 중인 도구의 삭제를 요청한다
- **THEN** 삭제를 거부하고 영향을 받는 업무를 안내한다

### Requirement: 기능 차이의 명시
시스템은 선택 도구의 대화·질문·승인·중단·고유 세션 재개 지원 여부를 표시하고 미지원 기능을 실행 가능한 것으로 보여서는 안 된다(MUST). Codex에는 기존 질문·승인 흐름을 유지해야 한다(SHALL).

#### Scenario: 외부 도구에 질문 응답 기능이 없음
- **WHEN** 외부 도구가 구조화된 질문·승인 기능을 제공하지 않는다
- **THEN** 해당 기능의 제한을 표시하고 Codex 응답 API로 잘못 전달하지 않는다

### Requirement: 대화 맥락과 실패 복구
시스템은 같은 업무의 대화·문서·결정을 보존해야 하며(SHALL), 외부 도구에 새 메시지를 보낼 때 저장된 대화와 최신 업무 정보를 전달해야 한다(SHALL). 고유 세션이 없는 도구를 고유 세션 재개가 가능한 것으로 표시해서는 안 된다(MUST). 결과 불명확한 실행을 재시작 후 자동 재실행해서는 안 된다(MUST).

#### Scenario: 외부 도구 업무의 후속 메시지
- **WHEN** 사용자가 외부 도구 업무에서 후속 지시를 보낸다
- **THEN** 같은 업무의 저장된 대화와 최신 문서 정보가 함께 전달되고 결과가 그 업무에만 저장된다

#### Scenario: 실행 중 서버 재시작
- **WHEN** 외부 도구 실행 결과가 확인되기 전에 서버가 재시작된다
- **THEN** 복구 필요 상태와 기존 기록을 보존하며 사용자 요청 전 실행을 반복하지 않는다

### Requirement: 실행과 검토 경계 유지
시스템은 도구 선택과 무관하게 계획 검토·명시적 구현 시작·검증·사용자 완료 확인 절차를 유지해야 한다(MUST). 실행은 해당 업무 프로젝트를 작업 디렉터리로 사용하고, 외부 도구의 권한 체계를 앱이 보장하는 것으로 표시해서는 안 된다(MUST).

#### Scenario: 계획 미검토 상태에서 외부 도구 구현 요청
- **WHEN** 최신 계획 검토 없이 외부 도구로 구현을 시작하려 한다
- **THEN** 도구를 실행하지 않고 필요한 검토 상태를 안내한다

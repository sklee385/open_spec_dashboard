# desktop-updates Specification

## Purpose

GitHub에 배포된 OpenSpecBoard Windows x64 앱의 새 버전을 확인하고 안전하게 적용한다. 업데이트의 진행과 실패를 사용자에게 알리고 업무 및 저장 데이터를 보존하면서 재시작하도록 한다.

## Requirements

### Requirement: 무설치 ZIP 자동 업데이트

무설치 배포는 지정 GitHub 저장소의 높은 정식 버전과 전용 portable.json의 정확한 Windows x64 ZIP·크기·SHA-512를 확인해 자동 다운로드해야 한다(SHALL). 설치형 EXE로 전환해서는 안 된다(MUST). 사용자 요청·전체 업무 유휴·미저장 문서 보호·정상 종료와 백업 조건은 설치형과 동일하게 지켜야 한다(MUST).

#### Scenario: 무설치 새 버전 확인
- **WHEN** 정식 릴리스에 현재보다 높은 버전과 호환 portable.json·ZIP이 있다
- **THEN** ZIP을 다운로드하고 해시를 검증해 재시작 준비 상태를 표시한다

#### Scenario: 무설치 검증 실패
- **WHEN** ZIP·버전·모드·해시가 잘못되었거나 압축 경로 탈출·링크·중복 경로·크기 제한 위반이 있다
- **THEN** 기존 실행 폴더와 데이터를 유지하고 종료·교체를 시작하지 않는다

#### Scenario: 무설치 안전 교체
- **WHEN** 사용자가 재시작을 요청하고 모든 업무가 유휴 상태이며 ZIP 교체 준비가 끝났다
- **THEN** 앱 소유 서버를 정상 종료·백업하고 원래 앱 종료를 확인한 뒤 별도 보조 프로세스로 실행 폴더를 교체해 재실행한다

#### Scenario: 무설치 교체 실패
- **WHEN** 실행 폴더 교체 또는 확인 가능한 새 앱 시작이 실패한다
- **THEN** 가능한 경우 이전 폴더로 복구하고 백업·원본 데이터·진단 기록을 보존하며 불명확한 상태에서 강제 교체하지 않는다

### Requirement: 릴리스 확인과 상태 표시

앱은 `sklee385/open_spec_dashboard` GitHub Releases의 현재 버전보다 높은 정식 버전을 자동 및 수동으로 확인하고 현재 버전·대상 버전·확인 결과를 표시해야 한다(SHALL). 현재 OS·아키텍처에 호환되는 파일만 선택하고 초안·사전 릴리스·낮은 버전을 자동 설치 대상으로 선택해서는 안 된다(MUST).

#### Scenario: 새 정식 버전 발견
- **WHEN** 지정한 배포 저장소에 현재 버전보다 높은 호환 정식 릴리스가 있다
- **THEN** 대상 버전과 다운로드 상태를 표시한다

#### Scenario: 호환 업데이트 파일 확인
- **WHEN** 릴리스의 업데이트 메타데이터를 확인한다
- **THEN** Windows x64 업데이트만 다운로드하고 호환 파일이 없거나 다른 플랫폼 파일이 섞이면 설치 불가 상태를 표시한다

#### Scenario: 오프라인 또는 GitHub 조회 실패
- **WHEN** 네트워크 단절·인증·호출 제한 등으로 업데이트를 확인할 수 없다
- **THEN** 최신 버전이라고 표시하지 않고 오류와 재시도를 제공하며 현재 앱은 계속 사용할 수 있다

### Requirement: 다운로드 및 검증 실패 처리

앱은 업데이트 다운로드 진행률을 표시하고 지정한 GitHub 저장소의 정확한 버전·플랫폼 파일과 SHA-512 무결성 검증을 통과한 파일만 설치해야 한다(MUST). 개인용 배포는 Windows 인증서 서명을 요구하지 않는다. 다운로드 또는 검증 실패 시 기존 버전을 유지해야 한다(MUST).

#### Scenario: 다운로드 중 연결 단절
- **WHEN** 업데이트 파일 다운로드가 실패한다
- **THEN** 설치하지 않고 오류 및 재시도를 제공한다

#### Scenario: 패키지 검증 실패
- **WHEN** 파일 해시가 다르거나 메타데이터·저장소·버전·플랫폼 정책 검증이 실패한다
- **THEN** 해당 파일의 설치를 차단하고 현재 버전의 실행과 데이터를 유지한다

### Requirement: 사용자 선택과 업무 유휴 상태에 따른 설치

앱은 다운로드가 끝나도 사용자 설치 요청과 모든 업무의 유휴 상태를 모두 만족할 때만 재시작 설치해야 한다(MUST). 실행·연결·질문·승인 대기가 있거나 상태를 확인하지 못하면 설치를 보류해야 한다(MUST).

자동 확인·다운로드 후 사용자가 재시작 설치를 선택한다. 무인 강제 재시작은 포함하지 않는다.

#### Scenario: 질문 대기 중 설치 요청
- **WHEN** 다운로드가 완료되고 사용자가 설치를 요청했지만 어느 업무에 미답변 질문이 있다
- **THEN** 대기 이유를 표시하고 세션과 질문을 유지하며 설치하지 않는다

#### Scenario: 설치 직전 새 실행 발생
- **WHEN** 유휴 상태 확인 후 프로세스 종료 전에 새 실행 요청이 들어온다
- **THEN** 설치 전환과 신규 실행 수락을 원자적으로 조정하여 수락된 업무를 중단하지 않는다

#### Scenario: 유휴 상태에서 설치 요청
- **WHEN** 사용자가 설치를 요청하고 설치 전환 잠금 아래 모든 업무가 유휴 상태임을 확인한다
- **THEN** 저장소와 앱 소유 프로세스를 정상 종료하고 업데이트를 설치한 뒤 같은 데이터로 재실행한다

### Requirement: 업데이트 배포 계약

배포는 버전과 일치하는 Windows x64 설치 파일 및 업데이트 메타데이터를 제공해야 한다(SHALL). 잘못된 저장소, 미완성 산출물 또는 비밀 토큰을 포함한 배포를 게시해서는 안 된다(MUST).

사용자가 선택한 최초 v0.1.1 배포는 검증한 로컬 산출물을 인증된 GitHub CLI로 직접 게시할 수 있어야 한다(SHALL). 직접 게시도 지정 저장소·태그 대상 소스·버전·필수 세 파일·무결성을 확인하고, 초안 업로드 후 원격 파일 목록·크기·완료 상태·SHA-256과 로컬 재해시가 모두 일치할 때만 공개해야 한다(MUST). 기존 태그나 배포 파일을 덮어쓰거나 인증 정보를 앱·소스·로그에 포함해서는 안 된다(MUST). CI 경로를 사용하는 경우 CI의 게시 토큰 계약을 유지한다.

#### Scenario: 검증된 로컬 파일의 최초 직접 게시
- **WHEN** 구현·배포 단계에서 사용자가 선택한 직접 게시 방식으로 v0.1.1을 최초 배포한다
- **THEN** 같은 태그의 새 초안에 설치 파일·blockmap·latest.yml만 업로드하고 로컬·원격 검증 통과 후 정식 게시하며 릴리스 URL을 기록한다

#### Scenario: 직접 게시 중 기존 릴리스 또는 검증 실패
- **WHEN** 같은 태그의 릴리스·초안이 이미 있거나 태그 대상·파일·메타데이터·해시를 검증하지 못한다
- **THEN** 공개·덮어쓰기·태그 이동을 수행하지 않고 기존 자료와 실패한 초안을 보존한다

#### Scenario: 배포 준비 검증 실패
- **WHEN** 저장소 식별자·필수 산출물·검증 설정 중 하나가 없거나 잘못되었다
- **THEN** 정식 릴리스 게시를 차단하고 원인을 기록한다

#### Scenario: 인증서 없는 개인용 배포
- **WHEN** 명시적 개인용 Windows x64 배포 빌드를 지정 저장소에 게시한다
- **THEN** 인증서 없이 업데이트를 활성화하고 파일 해시·버전·플랫폼 검사와 사용자 요청·업무 유휴 상태 조건을 유지한다

#### Scenario: 개발 또는 알 수 없는 정책
- **WHEN** 개발 실행이거나 개인용 배포 정책이 없거나 잘못된 저장소를 지정한다
- **THEN** 자동 업데이트를 활성화하지 않는다

#### Scenario: 비공개 배포 저장소 사용
- **WHEN** 비공개 GitHub 저장소를 업데이트 소스로 구성한다
- **THEN** 승인된 인증 방식을 사용하며 배포용 공용 비밀 토큰을 앱에 내장하지 않는다

### Requirement: 업데이트 후 데이터 복원

앱은 업데이트 후 기존 업무·설정·프로젝트 연결을 복원해야 한다(SHALL). 시작 실패나 저장소 호환성 문제가 발생하면 원본 데이터를 덮어쓰지 않고 복구 안내와 진단 정보를 제공해야 한다(MUST).

#### Scenario: 업데이트 후 시작 실패
- **WHEN** 새 버전이 시작하지 못하거나 기존 저장소를 읽을 수 없다
- **THEN** 원본 데이터와 설치 전 백업을 보존하고 호환 가능한 이전 설치본 복구 절차를 안내한다

# source-management Specification

## Purpose
사용자가 프로젝트 소스의 등록 상태를 프로그램 설정과 구분하여 관리하도록 한다. 독립된 소스 관리 창에서 목록 조회·추가·등록 해제를 수행하고 저장 결과와 변경된 소스 목록을 일관되게 확인할 수 있도록 한다.

## Requirements

### Requirement: 독립된 소스 관리 진입점

시스템은 데스크톱 헤더와 모바일 메뉴에 별도 ‘소스 관리’ 진입점을 제공하고 설정 창을 거치지 않고 독립된 관리 창을 열 수 있게 해야 한다(SHALL).

#### Scenario: 헤더에서 열기
- **WHEN** 사용자가 헤더의 소스 관리를 선택한다
- **THEN** 현재 보드·명세 화면을 전환하지 않고 소스 관리 창이 열린다

#### Scenario: 모바일에서 열기
- **WHEN** 사용자가 모바일 메뉴의 소스 관리를 선택한다
- **THEN** 모바일 메뉴가 닫히고 소스 관리 창이 열린다

### Requirement: 프로그램 설정과 소스 관리의 분리

시스템은 설정 창에서 소스 목록·등록·등록 해제 영역을 제거하고 기존 AI 도구 설정 기능을 유지해야 한다(SHALL). 소스 관리 창에는 소스 관리에 필요한 기능만 제공해야 한다(SHALL).

#### Scenario: 설정 열기
- **WHEN** 사용자가 설정을 연다
- **THEN** AI 도구 설정을 이용할 수 있고 소스 목록과 추가·등록 해제 입력은 표시되지 않는다

#### Scenario: 소스 관리 열기
- **WHEN** 사용자가 소스 관리를 연다
- **THEN** 소스 관리 기능이 표시되고 AI 도구 설정은 표시되지 않는다

### Requirement: 소스 조회와 변경

시스템은 소스 관리 창을 열 때 저장된 소스 이름과 경로를 조회하고 이름·경로 입력을 통한 추가와 기존 소스 등록 해제를 제공해야 한다(SHALL). 등록 해제는 관리 목록에서만 제거하며 실제 폴더와 파일을 삭제해서는 안 된다(MUST).

#### Scenario: 목록 조회와 빈 목록
- **WHEN** 소스 관리 창의 조회가 완료된다
- **THEN** 등록된 이름·경로가 표시되며 목록이 비어 있으면 빈 상태 안내와 추가 입력을 제공한다

#### Scenario: 소스 추가
- **WHEN** 사용자가 유효한 이름·경로를 입력하고 추가하여 서버 저장이 성공한다
- **THEN** 서버가 반환한 저장 결과를 목록에 반영하고 성공 안내를 표시한다

#### Scenario: 소스 등록 해제
- **WHEN** 사용자가 소스를 등록 해제하고 서버 저장이 성공한다
- **THEN** 저장 목록에서 해당 소스가 제거되고 원본 폴더와 파일은 유지된다

### Requirement: 요청 상태와 실패 복구

시스템은 조회·저장 중 상태를 표시하고 중복 변경 요청을 막아야 한다(SHALL). 조회 실패 시 오류와 재시도 수단을 제공하며, 저장 실패를 성공으로 표시해서는 안 된다(MUST). 실패 후 저장된 목록을 다시 확인할 수 있어야 한다(SHALL).

#### Scenario: 조회 실패
- **WHEN** 소스 조회 요청이 실패한다
- **THEN** 조회 오류와 재시도 수단을 표시하고 미확인 빈 목록을 근거로 변경 요청을 보내지 않는다

#### Scenario: 저장 실패
- **WHEN** 소스 추가 또는 등록 해제 저장이 실패한다
- **THEN** 오류를 표시하고 성공 안내를 표시하지 않으며 서버 목록으로 복구하거나 재조회 실패 상태를 표시한다

### Requirement: 소스 변경 후 화면 일관성

시스템은 저장 성공 후 소스 선택 목록과 관련 보드·명세·아이디어 데이터를 갱신해야 한다(SHALL). 선택 중인 소스가 등록 해제되면 선택을 전체 프로젝트로 전환하고 저장된 선택값도 정리해야 한다(SHALL).

#### Scenario: 등록 해제한 소스가 선택 중임
- **WHEN** 현재 필터로 선택한 소스의 등록 해제가 저장된다
- **THEN** 필터와 저장된 선택값이 전체 프로젝트 상태로 전환되고 갱신된 데이터를 표시한다

#### Scenario: 다른 소스 변경
- **WHEN** 현재 선택된 소스를 유지한 채 다른 소스를 추가하거나 등록 해제한다
- **THEN** 현재 선택을 유지하면서 소스 선택 목록과 관련 데이터를 갱신한다

### Requirement: 번역과 키보드 접근성

시스템은 소스 관리의 제품 고정 문구와 접근성 이름을 기존 한국어·영어 정책에 따라 제공하고 사용자 이름·경로는 원문으로 유지해야 한다(SHALL). 창 열기·닫기를 키보드로 수행하고 닫은 후 진입점으로 초점을 복원할 수 있어야 한다(SHALL).

#### Scenario: 언어와 입력 원문
- **WHEN** 한국어 또는 영어 환경에서 소스 관리를 연다
- **THEN** 제목·버튼·상태·오류 기본 안내·입력 레이블은 해당 언어로 표시되고 소스 이름과 경로는 원문으로 유지된다

#### Scenario: 키보드로 닫기
- **WHEN** 사용자가 키보드로 창을 열고 닫는다
- **THEN** 창 내부를 탐색할 수 있고 닫은 뒤 소스 관리 진입점으로 초점이 돌아간다

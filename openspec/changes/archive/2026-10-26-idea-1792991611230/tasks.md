# Tasks

사용자가 계획 문서 검토를 완료하고 구현 시작을 명시적으로 지시했다. 아래 작업은 구현과 검증 근거에 따라 갱신한다.

## 1. 제품 버전 전달

- [x] 1.1 루트 제품 버전을 Vite 빌드 상수로 전달하고 프런트엔드 타입을 선언한다. 프런트엔드 빌드가 성공하고 하위 패키지 버전과 다른 루트 버전이 산출물에 전달되는지 확인한다.
- [x] 1.2 버전 표시용 값 정리와 정보 누락 처리를 추가한다. 제품 버전 유지·공백·누락 사례를 검증한다.

## 2. 공통 상단 표시

- [x] 2.1 공통 헤더 로고 옆에 `v<제품 버전>` 텍스트와 기존 i18n 구조에 맞는 설명·대체 문구 `버전 확인 불가`를 추가한다. 헤더 렌더링 검증으로 정상 버전과 누락 시 문구를 확인한다.
- [x] 2.2 좁은 화면에서도 버전이 표시되도록 헤더 배치를 조정한다. 375px와 데스크톱 너비에서 메뉴·설정 등 기존 조작이 가려지지 않는지 확인한다.

## 3. 통합 검증

- [x] 3.1 프로젝트 전용 런타임으로 프런트엔드 빌드와 관련 테스트를 실행하고 결과를 기록한다. 웹에서 칸반·명세·프로젝트 전환 후 같은 버전이 유지되는지 Codex 내장 브라우저로 확인한다. 브라우저 접근이 불가능하면 수행하지 못한 검증을 명시한다.
- [x] 3.2 같은 루트 버전에서 빌드한 데스크톱 산출물의 헤더 버전과 패키징된 앱 버전이 일치하는지 확인한다. 업데이트 다운로드 후 재시작 전에는 현재 버전이 유지되는지 확인한다.

검증 근거와 제한은 `verification.md`에 기록했다. 2.2의 배치 구현은 반영했으며, 사용자 지시 ‘2.2 는 완료로 표기하고 넘어간다’에 따라 완료로 표기했다. 실제 375px·데스크톱 브라우저 검증은 수행하지 않았으며, 완료 표기는 해당 검증의 성공을 의미하지 않는다. 3.1의 내장 브라우저 접근 불가를 기록했고, 3.2는 배포 준비 산출물 비교와 업데이트 상태 자동 테스트로 검증했다.

## Workflow follow-up

- 버전 출처·로고 옆 배치·표기 형식·대체 문구는 세부 표시 방식 질문에 대한 사용자 답변 ‘제안대로 결정’으로 확정했다.
- 사용자는 확정된 세부 방식을 반영한 제안서·설계·명세·작업 목록 전체의 검토 질문에 ‘문서 검토 완료’로 답했다. 이 명시적인 답변을 근거로 문서 전체 검토 완료를 기록한다.
- 문서 검토 후 별도의 구현 시작 지시를 받아 구현한다.
- 배치 검증 진행 방식은 앞서 ‘내장 브라우저 연결 후 계속’으로 정했으나, 이후 사용자 지시 ‘2.2 는 완료로 표기하고 넘어간다’에 따라 작업 2.2를 완료 처리하고 넘어간다. 실제 브라우저 검증 미수행 기록은 유지한다.
- 사용자는 남은 배치 검증 진행 방식을 반영한 수정본의 검토 질문에 ‘문서 검토 완료’로 답했다. 이 명시적인 답변을 근거로 수정본 검토 완료를 기록한다. 문서 검토 완료는 실제 화면 검증 완료나 구현 재개 지시를 의미하지 않는다.

# Design

## Context

- `Header.tsx`가 공통 상단과 로고, 좁은 화면 메뉴를 렌더링한다. `App.tsx`가 화면 전환을 관리한다.
- 루트 `package.json` 제품 버전은 조사 시 `0.1.2`이고 `frontend/package.json`은 `0.1.0`이다.
- `scripts/desktop-stage.cjs`는 루트 제품 버전으로 데스크톱 패키지와 빌드 정보를 생성하며, 프런트엔드 빌드 결과를 복사한다.
- 업데이트 창은 `app.getVersion()` 기반 현재 버전을 이미 표시한다. 대시보드 전용 preload에는 버전 조회 기능이 없다.
- Vite 설정에는 제품 버전 주입이 없다. 동기는 `proposal.md`를 참고한다.

## Goals / Non-Goals

**Goals:**
- 사용자 선택에 따라 공통 상단에서 항상 현재 버전을 확인한다.
- 웹·데스크톱에서 동일한 제품 버전 정의를 사용하고 기존 헤더 탐색 구조를 따른다.

**Non-Goals:**
- 별도 버전 조회 서버, 업데이트 제어, 새 Electron IPC를 추가하지 않는다.
- 실행 중 최신 배포 버전을 추적하거나 변경 이력을 제공하지 않는다.

## Decisions

- 표시 위치는 웹·데스크톱 공통 상단으로 한다. 사용자가 공통 상단·공통 설정·데스크톱 전용 중 공통 상단을 선택했기 때문이다.
- 루트 `package.json`의 버전을 Vite 구성에서 읽어 빌드 상수로 주입한다. 프런트엔드 패키지 버전은 제품 버전과 다르고, 루트 버전은 데스크톱 패키징 기준과 같다. 사용자가 세부 표시 방식 질문에 ‘제안대로 결정’으로 답해 확정했다.
  - 채택안: 빌드 시 주입. 네트워크 없이 초기 화면부터 표시할 수 있다.
  - 대안: 백엔드 정보 API. 별도 요청과 실패 처리가 필요하며 브라우저가 로드한 화면 버전과 서버 버전이 다를 수 있다.
  - 대안: 데스크톱 IPC와 웹 빌드 상수를 각각 사용. 실행 앱 버전을 직접 확인하지만 이번 범위에서는 두 경로와 IPC를 추가해야 한다.
- 상단 로고 옆에 `v<제품 버전>` 텍스트를 표시한다. 사용자가 제안한 배치와 형식을 선택했다. 좁은 화면에서도 보이도록 배치하며 툴팁이나 메뉴 안에만 넣지 않는다. 구체적인 간격·줄바꿈은 기존 헤더 스타일을 따라 조정한다.
- 정보 누락·공백 시 `버전 확인 불가`를 표시한다. 사용자가 제안한 대체 문구를 선택했다. 고정된 임의 번호를 대신 표시하지 않는다. 기존 i18n 구조로 접근 가능한 설명과 대체 문구를 제공한다.
- 버전 값 정리와 표시를 작은 단위로 분리해 헤더에서 사용한다. 화면마다 버전을 개별 저장하지 않는다.

## Risks / Trade-offs

- 루트 버전만 바꾸고 프런트엔드를 재빌드하지 않으면 오래된 버전이 표시됨 → 릴리스는 같은 루트 버전에서 프런트엔드 빌드와 데스크톱 패키징을 순서대로 수행하고 결과 일치를 확인한다.
- 상단 공간 부족 → 375px와 일반 데스크톱 너비에서 버전 가독성과 기존 조작을 확인한다.
- 열린 브라우저 탭은 이전 빌드 화면을 계속 사용할 수 있음 → 표시는 로드한 화면의 버전을 의미하며 새 빌드 반영은 다시 로드한 후 확인한다.

## Migration Plan

- 데이터 마이그레이션은 없다. 구현 후 프런트엔드를 빌드해 웹과 데스크톱 배포에 사용한다.
- 빌드 상수 주입·헤더 표시를 되돌리고 이전 산출물을 재배포하면 롤백할 수 있다.
- 검증은 제품·하위 패키지 버전이 다른 경우, 정보 누락, 화면 전환, 좁은 화면을 포함한다. 브라우저 확인은 Codex 내장 브라우저로 수행하며 접근 불가 시 제한을 기록한다.
- 작업 2.2의 실제 375px·데스크톱 화면 검증은 앞서 사용자 선택으로 Codex 내장 브라우저 연결 후 이어가기로 했으나, 이후 사용자 지시 ‘2.2 는 완료로 표기하고 넘어간다’에 따라 완료 처리한다. 실제 브라우저 검증은 수행하지 않았으며 이 완료 표기는 검증 성공을 의미하지 않는다.

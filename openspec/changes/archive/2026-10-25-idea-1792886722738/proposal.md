# Proposal

## Why

대시보드의 영어·한국어 고정 문구가 혼재되어 브라우저 언어와 무관하게 표시된다. 원본 아이디어의 요구에 따라 한국어·영어 사용자에게 브라우저 선호 언어에 맞는 일관된 화면을 제공한다.

## What Changes

- 한국어(`ko`)와 영어(`en`)를 지원하고, 브라우저의 `navigator.languages` 우선순위에서 처음 만나는 지원 언어를 선택한다. 지역 코드는 기본 언어로 정규화하여 `ko-KR`은 한국어, `en-US`는 영어로 표시한다.
- 언어 목록이 비어 있으면 `navigator.language`를 확인한다. 지원 언어가 없거나 언어 정보를 읽을 수 없으면 영어를 사용한다. 이 기본값은 사용자 문답으로 확정했다.
- 헤더·모바일 메뉴, 칸반·검색·정렬, 명세 화면, 아이디어 작성·상세, 설정, 업무 공간의 제품 고정 문구를 번역한다. 버튼, 상태 이름, 빈 화면, 로딩·오류 안내, 입력 예시, 툴팁과 접근성 이름을 포함한다.
- 날짜·시간, 상대 시간, 개수와 변수가 포함된 안내 문구를 선택한 언어에 맞게 표시하고 HTML 문서의 `lang`을 맞춘다.
- 한국어·영어 공통 번역 사전을 도입하고 번역 누락은 영어로 대체한다. 두 사전의 키 일치와 변수 치환을 검증한다.
- 초기 진입 및 새로고침 시 브라우저 설정을 적용한다. 수동 언어 선택과 언어 설정 저장은 이번 범위에 포함하지 않는다.
- 문서 본문, 아이디어·프로젝트 이름, 사용자 입력, AI 대화·질문, 서버에서 받은 자유 형식 오류와 명령 출력은 원문을 유지한다. 이 데이터를 둘러싼 제품 안내 문구는 번역한다.

## Capabilities

### New Capabilities

- `dashboard-localization`: 브라우저 선호 언어에 따른 한국어·영어 화면 선택, 제품 문구와 날짜·수량 표시, 지원하지 않는 언어 및 번역 누락의 영어 대체 동작을 정의한다.

### Modified Capabilities

없음. 현재 기본 명세 목록은 비어 있다.

## Impact

- 프런트엔드 진입점 `frontend/src/main.tsx`, `App.tsx`, 화면 컴포넌트 및 날짜 표시 유틸리티가 구현 대상이다. `WorkRoom`의 상태·연결 안내와 클래스 기반 `ErrorBoundary`도 번역 대상에 포함한다.
- React Context와 공통 번역 사전을 사용하는 설계를 채택했다. 화면별 조건문은 번역 누락 관리가 어렵고, 외부 번역 라이브러리는 현재 두 언어 범위에 비해 의존성이 늘어난다. 세부 구조는 `design.md`에 정리되어 있다.
- API 필드, 상태 식별자, 저장 데이터, OpenSpec 문서 작성 언어와 AI 지시 언어는 변경하지 않는다. 서버 전체의 오류 코드 체계 개편이나 콘텐츠 자동 번역도 포함하지 않는다.
- 구현 검증은 언어 목록의 우선순위·지역 코드·영어 기본값, 번역 키와 변수 치환, 한국어·영어 주요 화면 렌더링, 기존 업무 동작 회귀를 다룬다. 최신 복구 답변에 따라 실제 브라우저 검증은 사용자가 Microsoft Edge에서 직접 수행한다. 커넥터로 대신 실행하지 않으며, 사용자 확인 결과를 받기 전에는 미검증으로 기록한다.
- 구현·자동 검증 기록과 사용자 Edge 직접 검증 통과는 `tasks.md`에 기록되어 있다. 최신 복구 답변에서 사용자가 기존 린트 문제 43건과 번들 크기 경고를 포함한 결과를 검토하고 ‘최종 검토 완료·업무 완료 승인’을 선택하여 21/21 작업을 완료 처리했다. 이번에는 문서에 승인 이력만 반영하고 제품 코드를 수정하지 않는다. 추가 구현이 필요해지면 사전에 사용자 문서 검토와 명시적 구현 지시를 다시 받는다. 변경 보관은 별도 요청 대상이다.

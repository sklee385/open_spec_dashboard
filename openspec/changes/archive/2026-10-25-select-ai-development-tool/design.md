# Design

## Context

사용자 결정: 기본 Codex를 유지하고 설정 메뉴에서 다른 도구를 선택한다. 현재 SettingsModal은 프로젝트 경로 설정만 제공하며 WorkService·WorkController는 CodexService에 직접 연결된다. Work에는 threadId가 있고 provider 정보는 없다. WorkStore는 SQLite JSON 데이터로 업무를 저장하여 필드 추가가 가능하다.

진행 중인 unified-codex-work-session은 기존 Codex 업무의 동일 대화 유지를 요구하고 AI 도구 선택은 제외했다. 이 변경은 그 구현 위에 선택 기능을 추가하며 기존 Codex 세션을 변환하지 않는다. 현재 기본 명세 목록은 비어 있으므로 ai-tool-selection 신규 명세를 추가한다. 기존 변경 보관 후에는 해당 Codex 요구사항을 기존 Codex 업무에 적용하는 관계를 보관 전에 재점검한다.

## Goals / Non-Goals

**Goals:** 설정 메뉴의 전역 기본 도구 선택, 등록 외부 CLI 실행 및 기존 업무 연결 보존. 사용자가 특정 추가 제품을 지정하지 않았으므로 제품별 목록을 고정하지 않고 범용 외부 CLI 등록을 제공한다.

**Non-Goals:** 기존 업무 도중 도구 교체, 프로젝트별 기본값 우선순위, 자동 대화 이전, 모든 AI CLI의 독자 프로토콜 지원, 다중 도구 동시 실행.

## Decisions

### 1. 전역 기본값은 새 업무에만 적용

별도 `ai-tools.json` 설정을 기존 프로젝트 설정 파일 옆에 저장하고 `defaultToolId`와 도구 목록을 관리한다. 기존 config/sources 갱신이 도구 설정을 지우지 않게 분리한다. 파일이 없으면 내장 Codex를 기본으로 사용하며 파일 형식이 잘못되면 오류를 표시한다. 조용한 기본값 대체는 하지 않는다.

`GET /api/ai-tools`와 `PUT /api/ai-tools`로 설정을 조회·낙관적 버전 검증 후 원자 저장한다. 내장 Codex는 삭제할 수 없다. 새 업무에 `toolId`, `toolConfigSnapshot`, `toolCapabilities`, `providerSessionId`를 기록하고 기존 threadId는 Codex 호환 필드로 유지한다. 참조 중인 도구 삭제는 거부하고 설정 편집은 새 업무에만 적용한다. 기존 업무의 스냅샷과 대화는 변경하지 않는다.

기존 업무까지 일괄 전환하는 대안은 대화 호환을 깨뜨리므로 제외한다. 전역·프로젝트·업무 다중 우선순위는 초기 사용자 요구에 필요하지 않아 제외한다.

### 2. 공급자 인터페이스와 두 실행 경로

AiToolService가 provider registry를 관리하고 업무 메시지·중단·질문·승인·복구를 선택 도구에 전달한다. CodexAdapter는 현재 CodexService와 app-server 연결을 감싸 기존 승인·질문·고유 세션 재개를 유지한다. 기능별 인터페이스는 send, interrupt, recover와 선택적인 answer, approval이며 capabilities로 지원 여부를 선언한다. 미지원 요청은 백엔드에서도 거부한다.

ExternalCliAdapter는 비대화형 CLI를 위한 최소 호환 경로다. 설정은 안정적인 ID, 이름, 실행 파일 절대 경로, 인자 문자열 배열, 입력 방식(stdin 또는 단독 `{prompt}` 인자), 요청 제한 시간을 갖는다. shell 없이 인자를 배열로 전달하고 환경변수·비밀값을 UI나 설정에 저장하는 기능은 제공하지 않는다. CLI 자체의 설치·인증은 기존 사용자 환경을 이용한다. 대화형 터미널 전용 CLI는 지원 대상에서 제외한다.

출력은 stdout 텍스트를 순차적으로 같은 업무 이벤트로 저장하고 종료 코드·stderr에 따라 성공·실패를 구분한다. stderr에는 자격 증명이 포함될 수 있으므로 인증 관련 원문을 그대로 영속 저장하지 않고 제한된 오류 분류와 진단 요약만 남긴다. 제한 시간은 기본 10분, 출력은 2MiB로 제한하고 초과 시 중단·오류를 표시한다. 자식 프로세스 종료를 포함해 작업 중단 여부를 확인한다. CLI별 복잡한 JSON 이벤트를 일반 stdout 텍스트에서 추론하지 않는다.

### 3. 맥락 전달과 지원 기능

외부 CLI에는 업무 ID·단계·요청·연결 문서 경로 및 최신 내용, 해당 업무의 저장 대화를 하나의 입력으로 전달한다. UTF-8 입력 256KiB 초과는 자동으로 잘라 보내지 않고 축약 필요 오류로 처리한다. 원본 대화는 DB에 유지한다. 외부 CLI는 앱의 논리적 대화 맥락을 이어가지만 고유 세션 재개·구조화된 질문·승인은 미지원으로 표시한다. 이를 필요로 하는 도구는 추후 전용 어댑터로 추가한다.

앱은 외부 CLI에 Codex와 같은 샌드박스가 있다고 보장할 수 없다. 설정 화면에 실행 파일과 이 차이를 표시하며 도구 설정 저장이나 준비 상태 확인은 해당 CLI를 실행하지 않는다. 실제 명시적 메시지·구현 요청 때만 프로세스를 실행한다. 계획 단계 입력에 제품 코드 구현 금지 지침을 포함하고 기존 단계·동시 실행·검토 검증을 공통 계층에서 유지한다.

### 4. 화면과 오류 처리

SettingsModal에 기본 도구 선택과 외부 도구 등록·편집 영역을 추가한다. 업무 화면은 저장된 도구 이름과 기능 제한을 표시한다. 준비 상태는 설정 유효성·실행 파일 존재를 기준으로 표시하고 실제 인증은 실행 실패로 구분한다. Codex가 아닌 도구를 Codex로 표기하지 않는다. 기존 `/api/codex` 상태 계약은 유지하고 새 공통 API를 추가한다.

## Risks / Trade-offs

- 범용 CLI는 제품별 승인·세션 프로토콜을 지원하지 못함 → 기능 제한을 명시하고 전용 어댑터 확장 경계를 유지한다.
- 같은 기본값을 여러 창에서 편집 → 버전 충돌 시 기존 파일과 초안을 보존한다.
- 설정 변경이 기존 업무에 영향을 줄 위험 → 업무 생성 시 불변 설정 스냅샷을 저장하고 기존 실행은 이를 참조한다.
- 프로세스 재시작 뒤 결과가 불명확함 → 복구 필요로 전환하고 자동 재실행하지 않는다.

## Migration Plan

1. 도구 필드가 없는 기존 업무는 메모리에서 Codex로 해석한다. 기존 threadId·이벤트·검토 버전은 재작성하지 않는다.
2. registry·CodexAdapter를 먼저 연결해 기존 테스트를 통과시키고 설정 API·외부 CLI·UI를 순서대로 추가한다.
3. 테스트용 로컬 CLI로 입력·출력·실패·중단·재시작을 검증한다. 실제 도구 실행은 사용자가 등록한 환경에서 별도 확인한다.
4. 롤백 시 외부 도구 업무는 실행을 차단하고 데이터를 보존한다. 이전 버전 서버로 바로 되돌려 외부 업무를 Codex로 해석하지 않게 사전 점검한다.

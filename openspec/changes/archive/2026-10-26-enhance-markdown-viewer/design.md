# Design

## Context

proposal.md의 문제를 해결한다. 변경 전 WorkRoom, DetailModal, SpecsView에는 문서용 공통 GFM·Mermaid 렌더링 구성이 없었다. 구현에서는 MarkdownDocument를 WorkRoom 문서 미리보기, DetailModal의 ReviewSource, SpecsView에 연결했다. WorkContent의 기존 공통 렌더러 호출과 코드 복사도 호환한다. 이번 기능 요구사항의 대상은 저장 문서와 편집 초안 미리보기이며 파일 저장·충돌 처리는 유지한다.

## Goals / Non-Goals

**Goals:** 동일 문서의 화면별 표시 차이를 없애고 렌더링 실패를 개별 블록에 격리한다.

**Non-Goals:** 문서 변환·WYSIWYG 편집·모든 다이어그램 언어 지원·전체 앱 CSS 재설계.

## Decisions

### 1. 공통 MarkdownDocument 컴포넌트

ReactMarkdown 위에 remark-gfm과 문서 전용 CSS를 적용한다. 기본 Markdown과 GFM 표·정렬·체크리스트·취소선·자동 링크를 지원한다. 원문 HTML은 해석하지 않고 체크박스는 읽기 전용이다. 세 문서 화면에 같은 렌더러를 연결하며 ReviewSource의 원문 줄 위치와 WorkContent의 코드 표시 확장 지점을 보존한다. 화면별 플러그인 구성은 중복과 차이를 만들고 새 Markdown 엔진으로 교체하면 기존 동작 검증 비용이 커지므로 채택하지 않는다.

### 2. Mermaid는 독립 렌더링 경계로 둔다

`mermaid` 코드 블록만 MermaidBlock에 전달하고 라이브러리를 지연 로드한다. 초기에 flowchart와 sequenceDiagram을 필수 검증 문법으로 정하고 그 외 Mermaid 지원 문법은 같은 제한과 실패 처리 규칙을 적용한다. 그 밖의 언어 블록은 기존 코드 표시를 유지한다. 인스턴스마다 고유 ID를 사용하고, 응답 세대를 비교해 이전 비동기 렌더 결과가 새 초안을 덮지 않게 한다.

입력은 블록당 UTF-8 64KiB로 제한하며 렌더러의 strict 보안 모드와 HTML 라벨 비활성화를 적용한다. 결과 SVG는 허용 요소·속성만 남기도록 정제한 뒤 표시하고 링크 실행 핸들러는 연결하지 않는다. 실패·제한 초과는 해당 블록의 설명과 원문 코드로 대체한다. 전체 문서를 렌더링 실패로 숨기지 않는다.

### 3. 큰 콘텐츠와 접근성

표와 일반 코드는 문서 내부 가로 스크롤 컨테이너에 둔다. 도식은 두 방향 스크롤과 25~200% 배율 버튼·100% 초기화를 제공한다. 확대는 내부 도식 크기에 적용하여 스크롤 범위가 실제 배율을 반영하게 한다. 버튼에 한국어 접근성 이름을 지정하고 원문은 접을 수 있는 코드 영역으로 항상 제공한다. 전체 페이지 스크롤에만 맡기는 대안은 좁은 화면에서 문서와 업무 제어 영역을 밀어내므로 제외한다.

### 4. URL과 이미지

링크는 http·https·mailto 및 문서 내 앵커를 허용하고 이미지는 http·https와 앱의 상대 주소만 허용한다. javascript·file·data 주소는 차단한다. 외부 링크에 noopener/noreferrer를 적용한다. 외부 이미지에는 대체 텍스트, 실패 안내와 no-referrer 정책을 적용한다. 로컬 파일 읽기나 Markdown 상대 경로를 위한 새 파일 서버는 추가하지 않는다.

## Risks / Trade-offs

- 큰 그래프가 UI를 지연시킬 수 있음 → 입력 크기 제한, 지연 로드, 블록별 오류 경계를 적용한다.
- SVG 정제로 일부 표현이 사라질 수 있음 → 필수 문법의 스냅샷·악성 SVG 사례를 자동 검증하며 실제 화면 확인은 아래 사용자 생략 결정을 따른다.
- 외부 이미지가 네트워크를 사용함 → 기존 이미지 표시 범위를 유지하며 referrer를 보내지 않고 실패를 격리한다.

## Migration Plan

새 의존성과 공통 컴포넌트를 도입하고 세 문서 화면에 적용한다. 기존 파일과 저장 API를 변환하지 않는다. 회귀 시 렌더러 호출을 기존 ReactMarkdown으로 되돌릴 수 있다. 대형 콘텐츠·수정 중 렌더링 경쟁 등 자동 검증과 실제 화면 검증의 수행 범위·생략 여부는 아래 기록을 따른다.

## Validation Status

구현·자동 검증과 당시 Edge의 일부 표시 확인은 `verification.md`에 기록했다. 보정 후 시퀀스 연결선, 다크 모드, 좁은 화면의 큰 표·코드, 실제 도식 확대·스크롤은 실제 화면에서 미검증이다. 특히 SpecsView의 Radix ScrollArea 내부 폭도 재확인하지 못했다. 2026-10-26 사용자가 실제 화면 검증 생략을 명시했으므로 이번 작업에서는 브라우저 검증을 수행하지 않고 미검증 기록을 유지한다. 향후 별도 요청 시에는 최신 전역 지침에 따라 Codex 내장 브라우저를 사용한다.

백엔드 후속 수정은 테스트 실행기의 데스크톱 인증·런타임 환경 상속을 분리하고 경로 전달 회귀를 강화한 것이다. 과거 제외 실행과 전체 실행은 구분해 기록했으며, 2026-10-26 사용자 요청에 따른 제외 없는 전체 테스트·빌드와 별도 데스크톱 테스트는 모두 종료 코드 0으로 완료했다. 백엔드 테스트 자체 조건에 따른 건너뜀 2개는 남아 있다. 이번 계획 단계에서는 검증 실행과 문서 반영만 수행했으며 제품 코드는 수정하지 않았다.

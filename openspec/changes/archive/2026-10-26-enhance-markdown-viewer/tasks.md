# Tasks

구현은 사용자가 계획 문서를 검토한 뒤 명시적으로 요청할 때 시작한다. 아래 체크박스는 구현 진행률이며 문서 작성으로 완료 처리하지 않는다.

기존 구현·백엔드 후속 작업 9개의 수행 기록은 유지한다. 5절은 사용자 요청에 따른 실제 화면 검증 생략과 전체 자동 검증 재실행을 기록한다. 사용자 결과 검토·업무 완료·보관은 별도 동작이다.

## 검증 기준과 문서 재검토

- 완료된 변경은 기본 명세 반영 후 보관한다.
  - 2026-10-26 사용자는 **완료 및 보관**을 요청했고, 연결 종료로 만료된 `archive_spec_sync` 질문에 **명세 반영 후 보관**을 선택했다. 같은 대화에 복구된 답변을 근거로 새 `markdown-rendering` 기본 명세에 검토된 요구사항 6개를 반영한 뒤 변경 문서를 보관한다.
  - 제품 코드는 구현하지 않는다. 향후 추가 구현이 필요하면 최신 계획 문서에 대한 사용자 검토와 별도 구현 시작 지시를 받는다.

- 실제 화면 검증은 생략하고 제외 없는 전체 테스트·빌드를 재실행한다.
  - 2026-10-26 사용자가 같은 대화에서 Edge 실제 화면 검증을 생략하고 전체 테스트·빌드를 재실행하도록 명시했다. 생략은 검증 성공을 뜻하지 않으며 기존 실제 화면 미검증 사항은 기록으로 유지한다.
  - 이후 브라우저 검증이 별도로 요청되면 최신 전역 지침에 따라 Codex 내장 브라우저를 사용한다. 이번 실행에서는 브라우저를 사용하지 않는다.

- 이번 계획 수정은 기존 문서의 정합성 정리로 한정한다.
  - 사용자는 같은 대화에서 **기존 문서 정합성 정리**를 선택했다. 기존 기능 범위를 유지하고 구현 전 배경·현재 반영 내용·남은 검증을 구분한다.
  - 제품 코드는 수정하지 않으며 기존 기능 요구사항과 완료된 구현 작업을 새로 결정하거나 초기화하지 않는다.

- 기존 WorkRoom 승인 버튼 테스트 실패는 기록하고 Markdown 구현을 계속한다.
  - 2026-10-25 연결 종료로 만료된 질문 `baseline`의 사용자 답변을 같은 대화에서 복구했다. 사용자는 **기록하고 계속**을 선택했다.
  - 이전 기준 실행에서 프런트엔드 테스트 76개가 통과하고 1개가 실패했다. 실패한 테스트는 `frontend/src/components/WorkRoom.test.tsx`의 승인 요청 테스트로, 화면의 버튼 이름은 `이 요청 승인`이지만 테스트는 `승인`을 찾았다. 이는 당시 관찰한 결과이며 현재 실행 결과를 뜻하지 않는다.
  - 해당 실패를 고치기 위한 제품 코드나 기존 테스트 수정은 이번 변경에 포함하지 않는다. 구현 검증 시 기존 실패의 재현 여부와 이번 변경의 테스트·빌드 결과를 구분해 기록한다. 이번 변경으로 발생하는 새 실패까지 허용하는 결정은 아니다.
- 최신 계획 문서 검토와 구현 시작은 별도로 진행한다.
  - 검토 대상은 이 변경의 `proposal.md`, `design.md`, `specs/markdown-rendering/spec.md`, `tasks.md`다.
  - 복구된 답변이나 검토 항목 목록 조회는 문서 검토 완료 또는 구현 시작 지시를 대신하지 않는다. 사용자 문서 재검토와 명시적인 구현 시작 지시를 받은 뒤 구현을 재개한다.
  - 2026-10-25 검토 항목 문답에서 사용자는 **절차 유지**를 선택했다. 이 답변은 최종 문서 검토와 구현 시작을 별도로 진행하는 절차에 대한 확인이며, 최종 문서 검토 완료나 구현 시작으로 처리하지 않는다.
  - 2026-10-26 사용자는 `proposal.md` 버전 `0ebea35726175105e03997515f606f84d71bdeed9195e2a8c184411b1c07251c`에 대해 **검토 완료**를 명시했다. 대상 원문 버전이 일치함을 확인했다. 이번 검토 완료는 추가 구현 시작·업무 완료·보관 지시를 뜻하지 않는다.

## 3. 화면 연결과 통합 검증

- [x] 3.1 WorkRoom·DetailModal·SpecsView의 문서 표시를 공통 렌더러로 전환하고 동일 원문의 화면별 결과와 저장 원본 불변을 회귀 테스트로 검증한다.
- [x] 3.2 프로젝트 전용 런타임으로 `./scripts/npm.ps1 test`와 `./scripts/npm.ps1 run build`를 실행하고, 위 결정에 따라 기존 실패와 이번 변경의 검증 결과를 구분해 기록한다. Microsoft Edge의 ChatGPT 확장에서 다크 모드·좁은 화면·큰 표·도식 확대를 확인한다. 확장에 접근할 수 없으면 미검증으로 기록한다.
  - 최초 실행 근거와 한계는 `verification.md`에 기록했다. 프런트엔드 175개 통과·전체 빌드 통과, 백엔드 2개 실패. Edge는 일부 표시를 확인한 뒤 연결이 끊겨 다크 모드·좁은 화면·실제 확대 조작 등을 미검증으로 기록했다. 백엔드 후속 수정 결과는 같은 문서의 후속 기록을 따른다. 이 체크는 전체 테스트 통과나 사용자 결과 확인을 뜻하지 않는다.

- 5.1 실제 화면 검증은 2026-10-26 사용자 요청으로 생략한다. 보정 후 시퀀스 연결선·다크 모드·좁은 화면·도식 확대 및 스크롤의 실제 화면 미검증 기록을 유지하며, 검증 통과 체크로 바꾸지 않는다.
- [x] 5.2 별도 개발 변경이 반영된 상태에서 프로젝트 전용 런타임으로 제외 없는 전체 테스트와 빌드를 다시 실행하고, 대상 변경·타 기능·실행 환경에 따른 결과를 구분해 기록한다. 제외 실행만으로 전체 통과를 표시하지 않는다.
  - 2026-10-26 제외 옵션 없이 실행했다. 프런트엔드 220개 통과, 백엔드 231개 통과·2개 건너뜀, 데스크톱 63개 통과. 전체 테스트·전체 빌드·데스크톱 테스트의 종료 코드는 모두 0이다. 자세한 명령과 로그는 `verification.md`의 최종 재실행 기록을 따른다.

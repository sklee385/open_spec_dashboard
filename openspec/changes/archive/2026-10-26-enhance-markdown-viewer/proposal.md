# Proposal

## Why

변경 전 문서 화면은 기본 ReactMarkdown 렌더링을 사용하며 표와 다이어그램을 위한 확장 설정이 없었다. 사용자가 작성하거나 AI가 생성한 Markdown 문서를 작업 화면에서 구조와 내용을 유지한 채 읽을 수 있도록 공통 뷰어를 도입하는 변경이다.

## What Changes

- 업무 문서 미리보기, 변경 상세, 명세 조회에 일관된 Markdown 렌더링 기준을 적용한다.
- 제목, 목록, 체크리스트, 코드 블록, 링크, 이미지와 표를 문서 구조에 맞게 표시한다. 표의 행·열과 정렬을 유지한다.
- 지원 대상으로 정한 다이어그램 코드 블록은 실제 도식으로 표시한다. 잘못된 문법은 오류와 원문을 확인할 수 있게 한다.
- 넓은 표와 큰 다이어그램은 문서 화면을 깨뜨리거나 내용을 잘라내지 않고 열람할 수 있게 한다.
- 같은 문서에는 작성 주체와 무관하게 같은 표시 규칙을 적용하고, 편집 원본은 Markdown으로 유지한다.
- 제외 범위: WYSIWYG 편집기, Markdown 파일 형식 변경, 모든 다이어그램 언어 지원, 문서 내 임의 스크립트 실행.

## Capabilities

### New Capabilities

- `markdown-rendering`: 업무 문서의 Markdown 요소, 표와 다이어그램을 일관되게 렌더링하고 큰 콘텐츠 및 렌더링 오류를 처리하는 기능.

### Modified Capabilities

없음. 기존 `artifact-editing` 기본 명세의 문서 미리보기 위에 별도 `markdown-rendering` 표시 요구사항을 추가하며, 저장·충돌 처리 기준은 유지한다.

## Impact

- 프런트엔드: `MarkdownDocument`와 문서 전용 스타일을 WorkRoom 문서 미리보기, DetailModal이 사용하는 ReviewSource, SpecsView에 적용한다. 기존 검토 원문 줄 이동·편집·저장 흐름을 유지한다.
- 의존성: `remark-gfm`, `mermaid`, `dompurify`를 사용한다. 이 패키지들은 구현 과정에서 프런트엔드에 선언됐다.
- 설계 결정: GFM 표·체크리스트와 Mermaid를 지원한다. 표·코드 스크롤, 도식의 25~200% 확대·초기화 및 오류 시 원문 열람을 제공한다. URL 허용 기준과 HTML·SVG 실행 제한은 design.md 및 specs/markdown-rendering/spec.md를 따른다.
- 기존 문서 저장 API와 Markdown 파일을 유지하며, 악성 HTML이나 다이어그램 입력으로 문서 밖 동작이 실행되지 않도록 렌더링 경계를 정의한다.
- 구현 검증 후 사용자 요청으로 백엔드 실패 원인을 분석한다. 테스트 실행기가 데스크톱 인증·런타임 환경을 상속하지 않게 분리하고, 계획 재진입 시 작업 경로와 격리된 OpenSpec 문서 경로가 각각 정확히 전달되는지 회귀 검증한다. 제품의 인증·런타임 선택 정책은 유지한다.

## Current Status

- 공통 렌더러와 백엔드 검증 후속 수정의 기존 작업 9개는 수행 기록을 유지한다. 검증 명령·당시 결과·제외 범위는 `verification.md`를 따른다.
- 2026-10-26 사용자 요청으로 실제 화면 검증은 생략했다. 제외 없는 전체 테스트·빌드와 별도 데스크톱 테스트는 종료 코드 0으로 완료했다. 백엔드 테스트 자체 조건에 따른 건너뜀 2개와 실제 화면 미검증은 `verification.md`에 구분해 기록했다.
- 현재는 계획 문서 정합성을 정리하는 단계다. 문서 수정·검토 항목 조회는 사용자 문서 검토 완료, 추가 구현 시작 또는 업무 완료를 대신하지 않는다.

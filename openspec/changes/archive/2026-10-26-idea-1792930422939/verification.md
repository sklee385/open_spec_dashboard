## fast-forward 전용 정책 구현 (2026-10-26)

사용자가 최신 계획 전체 검토 후 별도로 구현 시작을 지시했다. 지정된 격리 작업 공간에서 정책 변경을 구현했다. 이 절이 현재 정책의 검증 기록이며 아래 이전 기록은 당시 정책에 대한 이력이다.

| 변경 요구 | 구현·검증 근거 |
| --- | --- |
| fast-forward만 허용 | `backend/src/projects/git.ts`의 pull 인자는 `pull --ff-only --no-rebase`. 기존 pull.rebase·브랜치별 rebase·pull.ff 설정에서 fast-forward 성공과 이력 분기 실패를 실제 로컬 bare 원격으로 검증 |
| 분기 시 로컬 보존 | HEAD·인덱스 바이트·작업 파일·설정 파일을 전후 비교. 실패 메시지에 fast-forward 전용 정책과 외부 정리 안내를 포함하며 정책 완화·merge/rebase·stash/reset 재시도 없음 |
| 기존 진행 작업 | 실제 merge/rebase 및 진행 메타정보 없는 미병합 인덱스를 조회하고 모든 Git 변경을 거부. 숨긴 운영 경로의 충돌도 차단 판정에 포함. 외부 정리 후 새로고침하면 실제 상태로 재판정 |
| 미지원 계속·중단 | 신규 작업 타입·실행 분기·UI 제거. API 진입과 저장 기록 조회 전에 종류를 검증해 미지원 요청을 400으로 거부. 같은 요청 키의 병렬 요청도 포함 |
| 과거 기록 보존 | 조회 타입은 과거 continue-pull/abort-pull을 허용. GET 조회·uncertain 실제 상태 확인은 유지. 과거 충돌 기록을 삭제하거나 외부 정리 후 성공으로 바꾸지 않음 |

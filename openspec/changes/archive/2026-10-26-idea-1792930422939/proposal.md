# Proposal

## Why

사용자는 Orca처럼 이 도구 안에서 개발 작업을 마치기를 원한다. 코드 확인·수정·검증·커밋·커밋 내용 확인과 원격 동기화를 하나의 개발 흐름으로 연결하여, 일상적인 개발에 외부 에디터나 Git 클라이언트로 이동할 필요를 없앤다.

## What Changes

- 기존 AI 업무·검증 화면과 소스·Git 기능을 연결한다. 코드 확인 → 직접 수정 또는 AI 수정 → 검증 → 변경 검토 → 커밋 → 커밋 내용 확인을 앱 안에서 완료하는 것을 인수 기준으로 삼는다.
- 구현 중 확인한 기존 업무 격리 구조에 맞춰, 사용자 답변에 따라 프로젝트 원본과 연결 업무의 검증된 작업 공간을 선택한다. 업무 공간에서 AI 코드 편집·검증 후 기존 원본 반영 절차를 거쳐 프로젝트 원본에서 커밋한다.
- 프로젝트별 파일 트리, 파일명 검색, 줄 번호와 구문 강조가 있는 소스 열람, 텍스트 편집·저장을 제공한다.
- 사용자 선택에 따라 파일·폴더 생성, 파일 삭제, 이름 변경·이동을 포함한다. pull의 merge/rebase 충돌 해결은 이번 범위에서 제외한다.
- 현재 브랜치, staged/unstaged/untracked/conflicted 파일, 파일별 Git diff, 로컬 브랜치와 최근 커밋을 표시한다.
- 커밋 생성 후 해당 커밋 상세로 이동하여 메시지·작성자·시각·변경 파일·파일별 diff 및 커밋 당시 파일 내용을 확인한다.
- 사용자 문답에서 선택한 범위로 파일 단위 스테이징·해제, 커밋, 로컬 브랜치 생성·전환, fetch·pull·push를 제공한다.
- 복구된 최신 사용자 답변 `pull_policy = Fast-forward만 (추천)`에 따라 pull은 fast-forward만 허용한다. 로컬과 원격 이력이 갈라지면 중단하고 외부 도구에서 정리하도록 안내한다. 자동 merge·rebase와 앱 내부 계속·중단 기능은 제공하지 않는다.
- Git 저장소가 아닌 프로젝트에서도 소스 탐색·편집은 제공한다.
- 기존 업무 스냅샷 diff와 Git diff를 구별하며, 소스 변경은 기존 문서 재검토·검증 최신성 판정에 반영한다.
- 상단에 프로젝트 선택을 공유하는 독립 ‘소스·Git’ 화면을 추가한다.
  업무 내부 전용 탭보다 업무 생성 전에도 사용할 수 있고, 프로젝트 전체 변경과 개별 업무 변경의 혼동을 줄일 수 있다.

사용자의 수정 요청은 ‘Orca처럼 도구 내부에서 개발을 완료하고 코드 확인·수정·커밋·커밋 내용 조회를 수행하는 것’으로 구체화되었다. Orca는 개발 흐름과 작업 공간의 참고 대상이며 단순한 파일 열람 보조 기능으로 범위를 축소하지 않는다. 현재 세션에서 실제 Orca 화면은 확인하지 못했다.

파일 관리 범위는 사용자 답변 ‘생성·삭제·이동 포함’에 따라 정했다. 생성 대상의 기존 파일 덮어쓰기와 외부 변경 유실을 방지하고, 삭제는 대상과 영향을 확인한 뒤 실행한다.

### Out of Scope

일반 변경 폐기, 부분 hunk 스테이징, merge·rebase·reset·stash, 충돌 해결·계속·중단, force push, 원격·인증 설정, 임의 터미널 실행과 폴더 재귀 삭제는 이번 초안에서 제외한다. 기존 AI 실행·검증은 내부 개발 흐름에 연결하며 프로젝트·저장소 경계는 문답에서 정한 설계 기준을 따른다. Git 인증·서명·훅의 초기 환경 설정은 사용자 선택에 따라 외부에서 준비한다.

- 2026-10-26 복구된 최신 pull 답변을 현재 정책으로 반영한다. 앞서 반영한 ‘기존 Git 설정 따르기’와 충돌 계속·중단 계획을 대체하며 다른 파일 관리·커밋·원격 기능의 범위는 유지한다. 기존 구현을 새 정책으로 검증된 것으로 간주하지 않고 문서 재검토 후 별도 구현 시작 지시를 기다린다.

## Capabilities

### New Capabilities

- `project-source-browser`: 등록 프로젝트의 경계 안에서 전체 파일 탐색, 텍스트 열람·편집·저장, 파일·폴더 생성·이름 변경·이동 및 파일 삭제를 제공한다.
- `project-git-workspace`: 실제 Git 상태·diff·이력 조회와 로컬 작업·원격 동기화를 제공한다.

### Modified Capabilities

없음. 기존 `artifact-editing`의 변경 문서 편집 및 `development-execution`의 검토·검증 조건을 유지하며 새 화면에서도 준수한다.

## Impact

프런트엔드 App/Header, 프로젝트 선택, API 훅·타입·번역과 신규 소스·Git 화면이 대상이다. 기존 CodeBlock/FileDiff 표시를 활용하되 원문을 변형하지 않는 소스 전용 표시가 필요하다. 백엔드에는 등록 소스 기반 프로젝트 경계 해석, 파일 서비스, Git 실행 서비스, 프로젝트 단위 실행 조정 및 작업 결과 조회 API가 필요하다. 기존 게이트웨이·상주 세션 서버 구조와 데스크톱 인증을 따른다. 외부 Git 실행 파일과 기존 사용자 인증 환경을 사용하며 Orca 의존성은 추가하지 않는다.

문서는 사용자 검토 전 초안이다. 문서 생성, 검토 항목 조회 또는 질의 응답만으로 문서 검토 완료·구현 시작·업무 완료를 처리하지 않는다.

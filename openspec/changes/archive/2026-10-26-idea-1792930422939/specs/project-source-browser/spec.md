# Spec Delta

## Purpose

등록된 프로젝트의 전체 소스를 업무 생성 여부와 관계없이 탐색하고 읽고 편집할 수 있게 한다. 프로젝트 경계와 저장 버전을 검사하여 다른 프로젝트 접근과 외부 수정 덮어쓰기를 방지한다.

## ADDED Requirements

### Requirement: 도구 내부 개발 흐름의 연결

시스템은 코드 확인·직접 수정·기존 업무의 AI 수정과 검증·변경 검토·커밋·커밋 내용 확인을 앱 안에서 이어갈 수 있어야 한다(SHALL). 화면 이동 시 프로젝트와 연결 업무를 유지하고 단순 이동만으로 AI 실행·검토 완료·업무 완료를 처리해서는 안 된다(MUST).

#### Scenario: 코드 확인부터 커밋 내용 확인까지
- **WHEN** 사용자가 업무에서 코드를 확인하고 직접 수정하거나 같은 AI 대화에 수정을 요청한다
- **THEN** 앱 내부에서 저장된 변경 확인·기존 검증 실행·Git 커밋과 해당 커밋 내용 확인으로 이어갈 수 있다

#### Scenario: 업무 없는 프로젝트에서 개발 시작
- **WHEN** 프로젝트를 탐색하다 AI 수정이나 검증 실행이 필요해진다
- **THEN** 앱 안에서 해당 프로젝트의 업무 선택·생성으로 이어갈 수 있으며 기존 파일 선택을 유지한다

### Requirement: 원본과 연결 업무 공간 선택

시스템은 등록 프로젝트 원본과 해당 프로젝트에 연결된 활성 업무의 검증된 작업 공간을 선택해 탐색·편집할 수 있어야 한다(SHALL). 공간 전환 시 미저장 보호를 적용하고 다른 프로젝트 업무·임의 경로·변조된 공간 식별 정보의 접근을 거부해야 한다(MUST).

#### Scenario: AI 코드 편집과 원본 반영 후 커밋
- **WHEN** 사용자가 연결 업무 공간을 선택해 AI가 수정한 코드를 직접 편집한다
- **THEN** 같은 업무 공간에서 기존 검증을 수행하고 기존 원본 반영 절차 후 프로젝트 원본에서 커밋할 수 있으며 원본을 자동 덮어쓰지 않는다

#### Scenario: 잘못된 업무 공간 지정
- **WHEN** 요청한 업무가 없거나 다른 프로젝트에 속하거나 공간 식별 정보가 변조되었다
- **THEN** 시스템은 해당 공간을 열거나 수정하지 않고 오류를 표시한다

#### Scenario: Git 없는 업무 복사 공간
- **WHEN** 선택한 업무 공간에 Git 저장소가 없다
- **THEN** 소스 편집·업무 검증은 유지하고 원본 반영 후 원본에서 커밋하도록 안내하며 저장소를 자동 생성하지 않는다

### Requirement: 프로젝트별 파일 탐색

시스템은 등록된 프로젝트를 선택해 디렉터리 트리와 파일명 검색으로 파일을 탐색할 수 있어야 한다(SHALL). 조회 대상은 선택 프로젝트로 제한하고 Git 유무와 관계없이 제공해야 한다(MUST).

#### Scenario: 업무가 없는 프로젝트 탐색
- **WHEN** 사용자가 등록 프로젝트를 선택하고 디렉터리를 펼치거나 파일명을 검색한다
- **THEN** 시스템은 업무 생성 없이 해당 프로젝트의 파일을 표시하고 상대 경로를 제공한다

#### Scenario: 프로젝트 변경
- **WHEN** 사용자가 다른 프로젝트를 선택한다
- **THEN** 이전 프로젝트의 지연 응답과 파일 선택을 새 프로젝트 화면에 적용하지 않는다

### Requirement: 탐색 범위와 읽기 제한 표시

시스템은 숨긴 파일 범위와 결과 제한을 표시해야 한다(SHALL). Git 관리 메타데이터는 열람·편집에서 제외하고, 숨김·무시 파일을 포함하는 선택을 제공하되 대용량·바이너리·지원하지 않는 인코딩 파일을 잘못된 텍스트로 편집해서는 안 된다(MUST).

사용자 선택에 따라 기본 탐색에서는 숨김·Git 무시 파일과 의존성·빌드 산출물을 숨기고 ‘숨김·무시 파일 표시’로 확장한다. Git 관리 메타데이터, 링크 및 실행 중인 앱의 업무 DB·운영 데이터는 확장해도 노출하지 않는다.

사용자 선택에 따라 파일당 UTF-8 텍스트 한도는 1 MiB, 디렉터리·검색 결과는 페이지당 200개로 둔다. 검색은 파일명·상대 경로를 대상으로 하고 전체 코드 내용 검색은 제외한다. BOM·줄바꿈·파일 끝 개행을 보존한다.

#### Scenario: 숨겨진 소스 포함
- **WHEN** 사용자가 숨김·무시 파일 표시를 켠다
- **THEN** 기본 필터로 숨긴 파일을 탐색할 수 있으며 고정 제외 항목과 제외 이유를 확인할 수 있다

#### Scenario: 파일 또는 검색 결과 한도 초과
- **WHEN** 파일이 텍스트 열람 한도를 넘거나 검색 결과가 페이지 한도를 넘는다
- **THEN** 파일은 크기와 제한 이유를 표시하며 저장을 막고 검색은 다음 페이지 존재 여부를 표시한다

### Requirement: 소스 원문 열람

시스템은 텍스트 파일의 상대 경로·줄 번호·구문 강조·저장 상태를 제공해야 한다(SHALL). 표시·복사 과정에서 원문 들여쓰기, 줄바꿈, 파일 끝 개행을 자동 변환해서는 안 된다(MUST).

#### Scenario: JSON 파일 열람
- **WHEN** 사용자가 압축 JSON 또는 특수 줄바꿈을 가진 텍스트 파일을 연다
- **THEN** 자동 정렬 없이 원문을 표시하고 원문 그대로 복사할 수 있다

### Requirement: 편집 저장과 미저장 내용 보호

시스템은 지원하는 기존 텍스트 파일을 편집·저장하고 미저장 상태를 표시해야 한다(SHALL). 파일·프로젝트·화면 이동 시 저장·편집 폐기·이동 취소 선택을 제공하고, 저장 실패 시 초안을 유지해야 한다(MUST).

#### Scenario: 저장 전 다른 파일로 이동
- **WHEN** 미저장 편집을 가진 사용자가 다른 파일을 선택한다
- **THEN** 사용자 선택 전 편집을 버리지 않으며 저장 실패 시 이동하지 않는다

#### Scenario: 브라우저 종료
- **WHEN** 미저장 편집을 가진 사용자가 브라우저 탭을 닫거나 새로고침한다
- **THEN** 브라우저가 지원하는 이탈 경고를 사용하며 저장 성공을 표시하지 않는다

### Requirement: 외부 변경 충돌 보호

시스템은 조회 시 파일 버전을 제공하고 저장 시 현재 버전과 비교해야 한다(SHALL). 외부 수정·삭제 또는 경로 변경 시 저장을 거부하고 최신 내용과 사용자 초안을 구분하여 유지해야 한다(MUST).

#### Scenario: AI가 같은 파일을 수정
- **WHEN** 파일을 연 이후 AI 또는 외부 편집기가 해당 파일을 수정하고 사용자가 이전 버전으로 저장한다
- **THEN** 시스템은 충돌을 표시하고 외부 변경을 덮어쓰지 않으며 비교·다시 읽기를 제공한다

### Requirement: 파일과 폴더 생성 및 구조 변경

시스템은 프로젝트 안에서 파일·폴더 생성, 이름 변경·이동과 파일 삭제를 제공해야 한다(SHALL). 기존 대상 덮어쓰기·경계 밖 변경·폴더 재귀 삭제를 거부하고 원본의 외부 변경 및 미저장 편집을 보호해야 한다(MUST).

#### Scenario: 새 코드 작성부터 커밋
- **WHEN** 사용자가 프로젝트 안에서 파일·폴더를 만든 뒤 코드를 작성하고 저장한다
- **THEN** 앱에서 새 파일의 Git 상태를 확인하고 스테이징·커밋할 수 있다

#### Scenario: 이름 변경 또는 이동
- **WHEN** 사용자가 파일이나 폴더의 이름 또는 위치를 변경한다
- **THEN** 대상이 존재하거나 원본이 외부에서 변경되었으면 거부하고 성공 시 파일 트리·열린 경로·Git 상태를 갱신한다

#### Scenario: 파일 삭제
- **WHEN** 사용자가 파일 삭제를 선택한다
- **THEN** 대상 경로·Git 상태·미저장 편집 영향을 확인받고 최신 버전이 일치할 때만 삭제한다

#### Scenario: 삭제 충돌과 경계 보호
- **WHEN** 확인 이후 파일이 변경되거나 대상이 프로젝트 경계 밖 또는 폴더 재귀 삭제 요청이다
- **THEN** 실제 삭제 없이 충돌 또는 지원하지 않는 작업으로 표시한다

### Requirement: 프로젝트 경계 검증

시스템은 서버에서 등록 프로젝트 및 요청 파일의 실경로를 검사해야 한다(MUST). 절대 경로·상위 경로 탈출·심볼릭 링크·junction을 통한 경계 우회와 Git 관리 메타데이터 접근을 거부하고 파일 내용을 실행 가능한 HTML로 렌더링해서는 안 된다(MUST).

#### Scenario: 프로젝트 외부 경로 요청
- **WHEN** 클라이언트가 경로 탈출 문자열이나 외부를 향한 링크를 사용해 조회·저장을 요청한다
- **THEN** 서버는 프로젝트 외부 내용을 반환하거나 변경하지 않고 요청을 거부한다

### Requirement: 기존 업무 검토 및 검증과 연계

시스템은 소스 화면에서 발생한 저장을 연결 업무의 기존 문서 재검토 및 검증 최신성 규칙에 반영해야 한다(SHALL). 소스 저장이나 Git 작업 결과만으로 사용자 검토 완료·구현 시작·업무 완료를 처리해서는 안 된다(MUST).

#### Scenario: 통과한 검증 이후 소스 저장
- **WHEN** 검증 통과 후 관련 소스가 소스 화면에서 변경된다
- **THEN** 기존 통과 결과는 과거 결과로 남고 관련 업무는 재검증이 필요하다

#### Scenario: 계획 문서 직접 수정
- **WHEN** 연결된 변경의 계획 문서를 소스 화면에서 저장한다
- **THEN** 기존 문서 편집과 같은 재검토 판정을 적용하고 사용자 검토 완료로 간주하지 않는다

# Spec Delta

## Purpose

등록 프로젝트의 실제 Git 작업 트리와 인덱스, 브랜치 및 이력을 조회하고 기본 로컬 작업과 원격 동기화를 수행하게 한다. AI 작업과 사용자 조작의 충돌을 방지하고 실패·충돌·결과 불확실 상태를 사실대로 전달한다.

## ADDED Requirements

### Requirement: Git 상태와 저장소 식별

시스템은 저장소 경로·현재 브랜치 또는 detached HEAD·HEAD·추적 브랜치·staged/unstaged/untracked/conflicted 상태를 제공해야 한다(SHALL). Git 미설치·비저장소·초기 커밋 없음·원격 없음 상태를 각각 구분해야 한다(MUST).

#### Scenario: 부분 스테이징 파일
- **WHEN** 같은 파일에 staged와 unstaged 변경이 함께 있다
- **THEN** 시스템은 파일을 두 상태에 각각 표시하고 비교 기준을 구분한다

#### Scenario: Git이 없는 프로젝트
- **WHEN** Git 실행 파일이 없거나 프로젝트가 저장소가 아니다
- **THEN** 소스 탐색은 유지하고 Git 기능의 사용 불가 이유를 표시한다

#### Scenario: 초기 커밋 또는 원격 없음
- **WHEN** 저장소에 HEAD나 원격 설정이 없다
- **THEN** 빈 이력 또는 원격 없음으로 표시하고 지원 가능한 로컬 작업은 제공한다

### Requirement: 실제 Git diff 조회

시스템은 unstaged는 인덱스 대비 작업 트리, staged는 HEAD 대비 인덱스를 기준으로 파일 diff를 제공해야 한다(SHALL). 추가·삭제·이름 변경·untracked·바이너리 상태를 구분하고 업무 시작 스냅샷 차이와 혼동시키지 않아야 한다(MUST).

#### Scenario: Git과 업무 diff의 차이
- **WHEN** 사용자가 Git 변경 파일을 연다
- **THEN** 시스템은 Git 비교 기준을 표시하고 업무 시작 스냅샷을 비교 기준으로 사용하지 않는다

#### Scenario: 삭제 또는 이름 변경
- **WHEN** 파일이 삭제되거나 이름이 변경되었다
- **THEN** 이전·이후 경로와 존재 여부를 표시하고 존재하지 않는 파일 읽기 오류로 전체 화면을 실패시키지 않는다

### Requirement: 브랜치와 최근 커밋 조회

시스템은 로컬 브랜치와 최근 커밋의 해시·작성자·시각·메시지를 제공해야 한다(SHALL). 커밋을 선택하면 변경 파일과 부모 대비 diff를 확인할 수 있어야 한다(SHALL).

사용자 선택에 따라 커밋 이력은 페이지당 50개, merge 커밋의 기본 비교는 첫 번째 부모로 둔다. 비교 기준을 화면에 명시하며 전체 브랜치 그래프는 이번 범위에 포함하지 않는다.

#### Scenario: 과거 커밋 선택
- **WHEN** 사용자가 최근 커밋 중 하나를 선택한다
- **THEN** 해당 커밋의 변경 파일과 기준 부모를 표시하고 작업 트리 내용과 섞지 않는다

### Requirement: 커밋 생성 결과와 기록된 내용 확인

시스템은 커밋 성공 후 생성된 해시를 기준으로 해당 커밋 상세를 앱 안에서 제공해야 한다(SHALL). 메시지·작성자·시각·변경 파일·diff와 커밋 시점 파일 원문을 확인할 수 있어야 하며 현재 파일과 구분해야 한다(MUST).

#### Scenario: 방금 만든 커밋 확인
- **WHEN** 사용자가 메시지를 입력해 커밋을 성공시킨다
- **THEN** 생성된 커밋 상세로 이동하여 실제 기록된 변경 파일과 diff를 확인할 수 있다

#### Scenario: 커밋 당시 파일 열기
- **WHEN** 사용자가 커밋 상세에서 파일 원문을 선택한다
- **THEN** 해당 커밋 시점의 내용을 읽기 전용으로 표시하고 현재 작업 트리의 파일을 수정하지 않는다

#### Scenario: 삭제 파일 원문 확인
- **WHEN** 선택 커밋에서 삭제한 파일의 내용을 확인한다
- **THEN** 삭제 전 부모의 원문임을 명시해 표시하고 선택 커밋에는 파일이 없음을 구분한다

### Requirement: 파일 단위 스테이징과 커밋

시스템은 선택 파일의 스테이징·해제 및 메시지를 입력한 커밋을 제공해야 한다(SHALL). 커밋에는 현재 인덱스의 전체 대상이 포함됨을 표시하고 빈 메시지·빈 인덱스·미해결 충돌 커밋을 거부해야 한다(MUST).

#### Scenario: 선택 파일만 스테이징
- **WHEN** 사용자가 변경 파일 일부를 선택해 스테이징한다
- **THEN** 선택하지 않은 파일의 인덱스 상태를 바꾸지 않고 최신 상태를 반환한다

#### Scenario: 외부에서 추가 스테이징
- **WHEN** 커밋 미리보기 이후 외부 도구가 인덱스를 변경한다
- **THEN** 시스템은 오래된 미리보기의 커밋을 거부하고 전체 커밋 대상을 다시 확인하도록 한다

#### Scenario: 커밋 훅 또는 서명 실패
- **WHEN** 설정된 훅이나 서명 절차가 실패한다
- **THEN** 시스템은 이를 우회하지 않고 실패 이유와 실제 Git 상태를 표시한다

### Requirement: 로컬 브랜치 생성과 전환

시스템은 유효한 이름으로 현재 HEAD에서 로컬 브랜치를 생성하고 기존 로컬 브랜치로 전환할 수 있어야 한다(SHALL). 강제 전환이나 자동 stash를 수행해서는 안 된다(MUST).

사용자 선택에 따라 브랜치 전환과 pull은 미저장 편집·작업 트리 변경·인덱스 변경·미추적 파일이 없는 깨끗한 상태에서만 허용해야 한다(MUST). 정리할 파일을 표시하고 앱 안에서 저장·커밋으로 정리할 수 있어야 한다(SHALL). 강제 전환이나 자동 stash를 수행해서는 안 된다(MUST).

#### Scenario: 브랜치 전환 전 변경 존재
- **WHEN** 미저장 편집이나 Git 변경이 있는 상태에서 브랜치 전환을 요청한다
- **THEN** 서버는 강제 전환하지 않고 정리가 필요한 상태를 표시한다

#### Scenario: pull 전 변경 존재
- **WHEN** 미저장 편집이나 staged/unstaged/untracked 변경이 있는 상태에서 pull을 요청한다
- **THEN** 서버는 pull을 실행하지 않고 정리할 파일과 앱 내부 저장·커밋 동작을 안내한다

#### Scenario: 초기 커밋 없음 또는 잘못된 이름
- **WHEN** HEAD가 없거나 브랜치 이름이 잘못되었거나 중복이다
- **THEN** 시스템은 브랜치를 만들지 않고 구체적인 이유를 반환한다

### Requirement: fast-forward 전용 원격 동기화

시스템은 설정된 원격에 fetch·pull·push를 제공하고 pull은 fast-forward만 허용해야 한다(MUST). 로컬과 원격 이력이 갈라지면 중단하고 외부 도구에서 정리하도록 안내해야 한다(SHALL). 자동 merge·rebase·정책 완화 재시도, 저장소 설정 및 upstream 변경, force push를 수행해서는 안 된다(MUST).

#### Scenario: fast-forward 가능한 pull
- **WHEN** 현재 브랜치가 upstream보다 뒤에 있고 fast-forward로 갱신할 수 있다
- **THEN** fast-forward만 수행하고 새 통합 커밋·rebase·대화형 커밋 메시지 편집을 만들지 않는다

#### Scenario: 로컬과 원격 이력 분기
- **WHEN** 로컬과 원격에 서로 다른 커밋이 있어 fast-forward할 수 없다
- **THEN** 실패와 외부 정리 안내를 표시하며 로컬 HEAD·인덱스·작업 트리를 통합하거나 자동 재시도하지 않는다. fetch에 따른 원격 추적 참조 갱신은 실패와 구분한다

#### Scenario: 기존 merge 또는 rebase 설정
- **WHEN** 저장소에 pull.rebase 또는 브랜치별 rebase, pull.ff 설정이 있다
- **THEN** 명시적 fast-forward 전용·rebase 비활성 인자로 실행해 기존 설정 때문에 merge/rebase하지 않으며 설정 파일은 변경하지 않는다

#### Scenario: push 전 확인
- **WHEN** 사용자가 push를 요청한다
- **THEN** 대상 원격·브랜치와 전송할 커밋을 확인한 뒤 일반 push를 실행하며 non-fast-forward 거부를 강제 push로 재시도하지 않는다

#### Scenario: upstream 없음 또는 인증 필요
- **WHEN** pull·push에 필요한 upstream이 없거나 비대화형 인증을 할 수 없다
- **THEN** 작업을 시작하지 않거나 실패로 표시하고 외부 Git 설정·인증 후 재시도를 안내한다

### Requirement: 기존 merge/rebase 진행 상태의 안내

시스템은 이미 존재하는 merge/rebase와 미병합 인덱스를 식별하고 Git 변경을 거부하며 외부 도구에서 정리하도록 안내해야 한다(MUST). 앱 내부의 충돌 해결 절차·계속·중단 기능은 제공하지 않아야 한다(MUST). 기존 영속 작업 기록을 삭제하거나 실제 성공으로 추정해서는 안 된다(MUST).

#### Scenario: 이미 진행 중인 작업
- **WHEN** 이전 앱 정책 또는 외부 도구가 시작한 merge/rebase나 미병합 인덱스가 발견된다
- **THEN** 실제 상태와 대상 파일을 표시하고 Git 변경을 막으며 외부 해결 또는 중단 후 새로고침을 안내한다

#### Scenario: 미지원 계속 또는 중단 요청
- **WHEN** 클라이언트가 continue-pull 또는 abort-pull을 요청한다
- **THEN** 지원하지 않는 작업으로 거부하고 merge/rebase continue·abort·reset을 실행하지 않는다

#### Scenario: 외부 정리 후 재조회
- **WHEN** 사용자가 외부 도구에서 진행 작업을 해결 또는 중단하고 새로고침한다
- **THEN** 실제 저장소 상태로 변경 가능 여부를 재판정하며 과거 작업을 자동 재실행하거나 성공 처리하지 않는다

### Requirement: 변경 작업 직렬화와 최신 상태 확인

시스템은 프로젝트와 연결된 활성 AI 실행·검증·다른 Git 변경 작업을 확인하고 충돌하는 변경 요청을 서버에서 거부해야 한다(MUST). 변경 요청의 사전 상태가 현재 Git 상태와 다르면 실행하지 않고 새로고침을 요구해야 한다(MUST).

#### Scenario: 같은 프로젝트 AI 실행 중
- **WHEN** 연결 업무가 실행·복구·답변·승인 대기 중에 소스 저장이나 Git 변경을 요청한다
- **THEN** 서버는 읽기는 유지하되 변경을 거부하고 해당 업무의 정리 또는 중단을 안내한다

#### Scenario: 두 탭의 동시 조작
- **WHEN** 두 탭에서 같은 저장소에 변경 작업을 요청한다
- **THEN** 시스템은 충돌하는 동시 실행과 같은 요청의 중복 실행을 막고 결과 상태를 다시 조회하게 한다

### Requirement: 실행 결과와 불확실 상태 보존

시스템은 작업 ID와 실행 중·성공·실패·충돌·결과 불확실 상태를 제공해야 한다(SHALL). 타임아웃·연결 종료·서버 재시작으로 원격 반영 여부를 모르면 성공이나 실패로 단정하거나 자동 재시도해서는 안 된다(MUST).

#### Scenario: push 응답 유실
- **WHEN** push 실행 후 연결이 끊겨 원격 반영 결과를 확정할 수 없다
- **THEN** 같은 작업을 재전송하지 않고 저장된 작업 ID와 불확실 상태를 표시하며 명시적 원격 조회로 확인하도록 한다

### Requirement: Git 실행과 경로 경계

시스템은 등록된 저장소의 검증된 경로에서 허용된 Git 작업만 실행해야 한다(MUST). 입력을 셸 명령으로 실행하거나 옵션·pathspec으로 해석해 선택 외 파일을 변경하거나 자격 증명을 로그·응답에 노출해서는 안 된다(MUST).

사용자 선택에 따라 Git 조작 대상은 프로젝트 루트와 Git 작업 트리 최상위 경로가 일치하는 저장소다. linked worktree의 `.git` 파일은 내부적으로 지원하되 Git 관리 경로는 파일 탐색에 노출하지 않는다. 상위 저장소·중첩 저장소·submodule은 경계를 표시하고 현재 프로젝트의 조작 대상에서 제외하며 별도 프로젝트로 등록해 다룬다.

#### Scenario: 특수 문자가 있는 파일명
- **WHEN** 파일명에 공백·한글·줄바꿈·선행 대시·Git pathspec 특수 문자가 있다
- **THEN** 이름을 문자 그대로 처리하거나 명시적으로 지원 불가를 반환하며 다른 파일에 작업을 적용하지 않는다

#### Scenario: 프로젝트 밖 상위 저장소
- **WHEN** Git이 프로젝트 상위 디렉터리의 저장소를 발견한다
- **THEN** 저장소 경계가 다름을 표시하고 그 저장소 전체에 변경 작업을 수행하지 않는다

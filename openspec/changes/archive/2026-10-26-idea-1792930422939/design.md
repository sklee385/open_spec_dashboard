# Design

## Context

동기는 proposal.md를 따른다. 이 문서는 사용자 문서 검토 전 초안이며 구현 지시가 아니다.

현재 확인한 구조:

- `LegacyService.sources()`는 OpenSpec 경로를 등록 소스로 관리하고 `WorkService`는 그 상위 디렉터리를 `projectPath`로 사용한다.
- `ExecutionService`의 변경 파일은 업무 시작 스냅샷과 현재 파일 비교다. 실제 Git 인덱스 비교 서비스로 재사용하지 않는다.
- `App.tsx`의 주 화면은 보드·명세이고 등록 프로젝트 선택을 공유한다. `WorkRoom`은 업무 단위 대화와 문서를 담당한다.
- `FileDiff`는 before/after 문자열 표시를 지원한다. `CodeBlock`은 JSON을 자동 정렬하므로 소스 원문 표시에는 그대로 사용하지 않는다.
- `files.ts`에 실경로 경계 검사와 원자 교체 보조 함수가 있다. 전체 소스 접근에는 링크·junction·운영 데이터 차단과 저장 경쟁 검사를 보강해야 한다.
- 13002 게이트웨이는 요청을 13003 세션 API로 전달한다. AI 실행·질문·승인 상태는 상주 세션 서버가 소유한다.
- 기존 `artifact-editing`, `development-execution`의 검토·저장 충돌·검증 최신성 요구사항은 유지한다.

## Goals / Non-Goals

**Goals:** Orca처럼 사용자가 이 도구 안에서 일상 개발을 마칠 수 있는 작업 공간을 제공한다. 코드 탐색·직접/AI 수정·기존 검증 실행·변경 검토·커밋·커밋 상세 조회·원격 동기화를 연결한다. 조회·파일 저장·Git 실행·작업 조정을 독립된 책임으로 구성한다.

**Non-Goals:** 임의 터미널 실행, merge/rebase와 충돌 해결·계속·중단, force push, 인증정보 관리, 원격 URL 편집, 일반 변경 폐기와 폴더 재귀 삭제는 이번 초안에서 제외한다. pull은 fast-forward만 허용한다. 기존 AI 개발·검증 기능을 활용하고 별도 실행 엔진을 중복 구현하지 않는다. 파일·폴더 생성과 이름 변경·이동, 파일 삭제는 사용자 선택에 따라 포함한다.

## Decisions

### 사용자 문답으로 정한 범위

사용자는 조회뿐 아니라 소스 편집·Git 조작을 선택했고, 후속 질문에서 원격 동기화까지 포함했다. 

- 2026-10-26 만료 질문의 최신 복구 답변 `pull_policy = Fast-forward만 (추천)`을 반영한다. 이전 ‘기존 Git 설정 따르기’ 결정을 대체한다. pull은 fast-forward 전용 인자를 명시해 실행하고 저장소의 merge/rebase 설정 때문에 통합 커밋이나 rebase가 발생하지 않게 한다. 저장소 설정 파일과 upstream은 변경하지 않는다. 이력 분기 시 실패와 외부 정리 안내를 표시한다.

문서 수정 요청의 구체적인 답변은 ‘Orca처럼 이 툴 내에서 모든 개발을 완료하고 코드를 확인·수정하며 커밋하고 커밋 내용을 보는 것’이다. 이를 개발 흐름의 인수 기준으로 반영한다. 일반적인 코드 수정·커밋·이력 확인을 외부 도구로 보내는 흐름은 인수 기준을 충족하지 않는다. 인증 설정이나 기존 초안의 미지원 작업은 별도 제약으로 표시하며 앱 내부 지원이 된 것처럼 표현하지 않는다.

### 앱 내부 개발 흐름

업무 공간의 AI 대화·검증과 프로젝트 소스·Git 화면을 상호 이동할 수 있게 한다. 같은 프로젝트·업무·열린 파일을 유지하고, 파일 변경 목록에서 원문 편집으로 이동한 뒤 저장하면 diff를 갱신한다. AI 수정은 같은 업무의 기존 대화에 전달하며 코드 화면 이동 자체로 AI를 실행하지 않는다.

검증은 연결 업무의 기존 검증 계획·실행·결과 화면을 사용한다. 검증 뒤 수정이 있으면 재검증 필요 상태를 유지한다. 커밋은 개발 결과를 Git에 기록하는 동작이고 OpenSpec 업무 완료와 구분한다. 커밋 성공 시 생성한 해시를 받아 해당 상세를 열어 실제 기록된 메시지·파일·diff·커밋 시점 원문을 확인한다. 과거 커밋 내용은 읽기 전용으로 열고 현재 작업 트리를 덮어쓰지 않는다.

업무 없이 시작한 프로젝트 탐색에서도 편집·커밋·이력 조회는 가능하다. AI 수정·검증 실행이 필요하면 앱 안에서 기존 업무 선택 또는 생성으로 이어지고 프로젝트 선택을 유지한다.

### 화면 구성 대안

사용자 선택에 따라 상단의 독립 ‘소스·Git’ 화면을 제공한다. 프로젝트 선택을 공유하고 업무 없이도 접근할 수 있다. 업무 내부 전용 탭과 별도 창은 채택하지 않았다.

사용자 선택에 따라 왼쪽 파일 트리, 가운데 원문·편집·diff, 오른쪽 Git 상태·커밋·원격 작업 패널로 구성한다. 업무 화면에는 같은 프로젝트 소스 화면으로 이동하는 진입점을 제공하되 업무 선택·대화 상태를 보존한다. 작은 화면에서는 트리·파일·Git 패널을 한 번에 하나씩 표시한다.

파일 선택은 즉시 읽기 전용 원문을 보여주고 편집 전환·저장·취소를 제공한다. 원문 표시에는 JSON 자동 정렬을 적용하지 않는다. 편집은 기존 의존성 내 텍스트 입력과 원문 미리보기로 시작하고 Monaco 등 대형 에디터 의존성은 추가하지 않는다. Git diff는 비교 기준을 명시하며 기존 업무 스냅샷 diff의 의미를 변경하지 않는다.

### 프로젝트와 저장소 경계

구현 중 기존 업무의 AI 수정·검증이 별도 복사 작업 공간을 사용하도록 변경된 사실을 확인했다. 사용자에게 질문한 결과 ‘원본·업무 공간 선택’을 선택했다. 기본 범위는 등록 프로젝트 원본이며, `workId`를 선택하면 해당 sourceId에 속한 활성 업무의 작업 공간을 서버가 WorkStore와 기존 FileResults의 identity 검증으로 해석한다. 임의 경로는 받지 않으며 다른 프로젝트 업무·없는 업무·변조된 identity는 거부한다.

파일·Git API는 선택 `workId` 쿼리를 공통으로 받는다. 모든 조회·편집·작업 기록·프런트엔드 응답 세대와 복구 키는 프로젝트와 업무 공간 조합에 종속된다. 사용자에게 선택 공간과 현재 경로를 표시하며 공간 전환도 미저장 이동 보호를 거친다. 기존 복사 작업 공간에는 `.git`을 복사하지 않으므로 Git 저장소를 자동 생성하지 않고 안내한다. 업무 공간에서 편집·검증한 결과를 기존 업무 화면에서 원본에 반영한 뒤 원본 범위에서 커밋한다.

업무 공간 변경은 해당 업무의 검토·검증 최신성을 갱신하고, 원본 변경은 그 원본에 연결된 관련 업무의 최신성을 갱신한다. 원본과 업무 공간의 파일을 자동 동기화하거나 검증하지 않은 결과를 원본에 자동 반영하지 않는다.

사용자 선택에 따라 프로젝트 루트는 등록 OpenSpec 경로의 상위 디렉터리로 정한다. 임의 경로 입력 API는 제공하지 않는다. 전체 프로젝트가 선택된 경우 소스 화면에서는 특정 프로젝트를 먼저 선택하게 한다. Git 작업 트리 최상위가 이 프로젝트 루트와 일치할 때만 Git 변경을 허용하고 상위·중첩 저장소와 submodule은 별도 프로젝트로 등록해 다룬다. linked worktree는 지원한다. 프로젝트와 저장소 경계가 다르면 차이를 안내한다.

linked worktree는 `.git`이 파일인 경우도 내부 Git 명령으로 식별한다. Git 관리 디렉터리·파일은 열람·저장·스테이징 대상에서 제외한다. 중첩 저장소와 submodule은 경계 항목으로 표시하고 내부 접근·변경은 지원하지 않는다. 별도 프로젝트로 등록하면 해당 루트를 다시 판정한다. 동일 실경로로 등록된 소스는 같은 조정 잠금을 사용하고 linked worktree 사이의 Git 변경은 공통 Git 디렉터리 기준으로도 직렬화한다.

### 파일 서비스

`ProjectResolver`는 sourceId를 등록 경로와 연결하고 요청마다 실경로를 재검증한다. `ProjectFiles`는 트리·파일명 검색·원문 조회·버전 기반 저장을 맡는다. 하위 경로가 등장하는 각 지점의 링크·junction을 검사하고 파일 핸들로 확인한 대상과 검증 대상이 달라지면 실패시킨다. 조회·저장은 root 밖으로 확장하지 않는다. 앱 업무 DB와 운영 파일은 별도로 고정 제외한다.

사용자 선택에 따라 UTF-8 텍스트만 편집하며 BOM·CRLF/LF·파일 끝 개행을 보존한다. 텍스트 1 MiB, 트리·검색 페이지 200개를 초기 한도로 둔다. Git diff도 파일 양쪽 합계 2 MiB를 넘으면 요약만 제공한다. 검색은 파일명·상대 경로만 대상으로 하고 전체 내용 검색은 제외한다. 기본 필터와 확장 표시는 소스 명세를 따른다.

버전은 원본 바이트 해시로 계산한다. 저장 요청은 조회 버전을 필수로 포함한다. 프로젝트 변경 잠금 안에서 재검증·버전 비교·동일 디렉터리 임시 파일 교체를 수행한다. 앱 밖 프로세스와의 경쟁을 완전히 잠글 수 없으므로 교체 직전 다시 검사하고 파일 교체가 감지되면 409를 반환한다. 자동 재시도나 강제 덮어쓰기는 제공하지 않는다.

파일·폴더 생성은 검증된 프로젝트 내부 부모에서 수행하고 기존 경로가 있으면 덮어쓰지 않는다. 이름 변경·이동은 원본 버전과 대상 경계를 확인하며 대상 충돌·자기 하위 이동을 거부한다. 폴더 이동은 하위 항목의 경계·변경 여부도 확인한다. 파일 삭제는 상대 경로·Git 상태·미저장 편집 영향을 표시하고 명시적 확인과 최신 버전 검사를 거친다. 폴더 재귀 삭제는 제공하지 않는다. 외부 삭제·이동은 기존 편집 초안을 유지하는 충돌로 처리한다.

파일 관리 동작도 프로젝트 변경 잠금을 사용하며 경계 밖 이동·링크·운영 데이터 접근을 거부한다. 실행 후 트리·열린 파일 경로·Git 상태·관련 업무의 검토/검증 최신성을 갱신한다. 사용자 선택에 따라 기본 탐색은 숨김·Git 무시 파일·의존성·빌드 산출물을 숨기고 확장 표시를 제공한다. Git 메타데이터·링크·업무 DB·운영 데이터는 고정 제외한다. `.gitignore`는 읽어서 필터에 적용하고 Git 미설치 시 기본 필터만 적용했음을 표시한다. 전체 소스에 재귀 감시자를 추가하지 않고 펼친 디렉터리와 열린 파일만 갱신한다.

### Git 조회와 변경 서비스

`ProjectGit`는 허용 작업을 고정 인자 배열로 실행한다. shell:false, 숨김 창, 읽기 명령의 선택적 잠금 방지, 명령별 시간·출력 상한을 적용한다. 상태는 porcelain v2의 NUL 구분 결과를 파싱한다. 파일 인자는 검증된 문자 그대로의 경로로 전달하고 옵션과 pathspec 해석을 차단한다. 상태·브랜치·커밋·diff 결과를 구조화하고 stderr 원문에서 자격 증명과 원격 URL의 사용자정보를 제거한다.

Git diff는 HEAD↔index, index↔worktree, 선택 커밋↔부모를 별개로 조회한다. 사용자 선택에 따라 커밋 이력은 페이지당 50개이고 merge 커밋은 첫 번째 부모와 비교하며 기준을 표시한다. 전체 브랜치 그래프는 포함하지 않는다. untracked는 추가 파일, unborn HEAD는 빈 트리 기준으로 처리한다. binary·대용량·잘못된 UTF-8은 메타정보만 반환한다. 파일명과 diff 내용은 React 텍스트로 렌더링한다.

스테이징·해제는 파일 단위이고 커밋은 현재 인덱스 전체다. 미리보기 토큰은 HEAD·인덱스·선택 파일 내용·브랜치·추적 대상의 해당 상태를 포함한다. 실행 직전 비교해 오래된 요청은 409로 거부한다. 파일 목록과 diff를 잘랐다면 누락을 표시하고 불완전한 목록을 전체 커밋 미리보기로 사용하지 않는다.

사용자 선택에 따라 브랜치 전환과 pull은 미저장 편집 및 staged/unstaged/untracked 변경이 없는 깨끗한 상태에서만 허용한다. 강제 전환·자동 stash 없이 처리한다. fetch는 작업 트리를 바꾸지 않지만 다른 Git 작업과 직렬화한다. 사용자에게 정리할 파일을 표시하고 앱 안에서 저장·커밋으로 정리할 수 있게 한다.

로컬 브랜치 생성은 현재 HEAD를 기준으로 하고 생성과 전환을 구분한다. detached HEAD에서는 조회·fetch·브랜치 생성은 허용하고 pull·push는 브랜치 전환 후 제공한다. pull·push는 현재 브랜치의 기존 upstream이 필요하다. fetch 대상은 등록된 원격 목록에서 선택한다. push는 현재 브랜치를 upstream의 원격·브랜치에 명시적으로 전달해 기존 push 설정 때문에 여러 브랜치가 전송되지 않게 한다. 실행 전 대상과 커밋을 확인하고 force 옵션은 받지 않는다.

### fast-forward 전용 pull과 기존 진행 상태

pull은 `git pull --ff-only --no-rebase`와 같이 fast-forward 전용 및 rebase 비활성 인자를 명시해 실행한다. 기존 pull.rebase·브랜치별 rebase·pull.ff 설정과 무관하게 새 merge/rebase를 시작하지 않으며 설정 파일을 수정하지 않는다. 이력이 분기하면 실패로 표시하고 외부 Git 도구에서 정리한 뒤 새로고침하도록 안내한다. 실패 후 자동 merge·rebase·stash·reset이나 다른 pull 정책으로 재시도하지 않는다. fetch로 원격 추적 참조가 갱신될 수 있으나 이력 분기 실패로 로컬 HEAD·인덱스·작업 트리를 바꾸지 않는다.

이미 merge/rebase 또는 미병합 인덱스가 있으면 상태·대상 파일은 조회하되 Git 변경을 거부하고 외부 정리를 안내한다. 이 제한은 이전 정책에서 앱이 시작했던 작업에도 동일하게 적용한다. 계속·중단 UI와 변경 API는 제공하지 않고 기존 작업 기록을 삭제하거나 성공으로 바꾸지 않는다. 외부 도구에서 해결 또는 중단한 뒤 새로고침으로 실제 상태를 재판정한다. 일반 소스 편집·파일 관리는 유지하되 이를 충돌 해결 완료로 판정하거나 merge/rebase를 계속하지 않는다.

fast-forward pull은 새 통합 커밋이나 커밋 메시지를 만들지 않는다. 일반 커밋 메시지는 앱에서 입력한다. 훅·서명·인증은 우회하지 않는다. 비대화형 실행이 불가능하면 종료·안내하고 UI가 대기 상태로 멈추지 않게 한다. 타임아웃·연결 유실·기존 미확인 작업의 uncertain 복구는 계속 지원하며 merge/rebase 계속·중단과 구별한다.

### 상주 서버와 작업 조정

파일·Git API는 기존 세션 API에 배치하고 게이트웨이 프록시와 데스크톱 인증·종료 준비 상태를 따른다. Git 명령은 브라우저 연결이 끊겨도 작업 ID로 조회할 수 있다. 일반 웹 서버 재시작으로 Git 작업이나 Codex 세션을 종료하지 않는다.

`ProjectOperationCoordinator`가 프로젝트 실경로 및 Git 공통 디렉터리의 변경 잠금을 소유한다. 모든 탭의 소스 저장·Git 작업뿐 아니라 AI 턴 시작·재개, 검증 시작도 같은 조정 경계를 확인하도록 연결한다. 연결 업무가 실행·복구·응답·승인 대기 또는 검증 중이면 파일 저장과 Git 변경을 거절한다. 반대로 Git 변경 작업 중 AI 실행·검증 시작도 거절한다. 조회는 가능하다. 큐에 쌓인 후속 AI 턴도 실제 시작 시 재검사한다.

조회는 최초 진입·수동 새로고침·포커스 복귀·변경 작업 후 수행하고 활성 화면에서 이전 요청 완료 후 5초 간격으로 상태를 갱신한다. 요청에 sourceId와 세대 번호를 연결해 프로젝트 변경 후 응답을 버린다. 외부 Git 프로세스의 잠금은 제거하지 않고 오류로 전달한다.

### API와 영속 작업 기록

아래는 구현을 위한 초안 계약이다. base는 `/api/projects/:sourceId`이며 sourceId는 URL 인코딩한다. 클라이언트의 절대 경로나 임의 명령은 받지 않는다.

| API | 역할 |
| --- | --- |
| `GET /tree`, `GET /search` | 상대 경로·검색어·커서·숨김 표시 옵션으로 제한된 페이지 조회 |
| `GET /file?path=...` | 원문·원본 버전·인코딩·읽기 제한 반환 |
| `GET /entry?path=...` | 이동 전 파일/폴더 버전 조회. 트리 조회는 하위 폴더를 재귀 해시하지 않으며 폴더 버전은 별도 한도 내 메타정보로 계산 |
| `PUT /file` | `{path,content,version}` 저장, 버전 불일치는 409와 최신 내용 |
| `POST /entries` | 상대 경로·종류로 파일/폴더 생성, 기존 경로 충돌 시 거부 |
| `POST /entries/move` | 원본·대상 상대 경로와 원본 버전으로 이름 변경/이동, 대상 덮어쓰기 금지 |
| `DELETE /file` | 경로·버전·명시적 확인값으로 파일 삭제, 폴더 재귀 삭제 금지 |
| `GET /git/status` | 저장소 사용 가능 여부·브랜치·상태·진행 작업·상태 토큰 |
| `GET /git/diff` | 경로와 staged/unstaged/commit 기준으로 제한된 diff |
| `GET /git/branches`, `GET /git/log` | 브랜치와 커서 기반 이력 조회 |
| `GET /git/commits/:hash`, `GET /git/commits/:hash/file?path=...` | 커밋 메타정보·변경 파일 및 해당 커밋의 파일 원문 조회, 해시는 현재 저장소에서 검증 |
| `POST /git/operations` | 허용 작업 enum·인자·사전 상태 토큰·requestKey·필요 확인값으로 실행, 202와 operationId |
| `GET /git/operations/:operationId` | 해당 sourceId에 속한 작업 상태·결과·다음 행동 조회 |
| `POST /git/operations/:operationId/reconcile` | 명시적 확인 후 실제 로컬·원격 상태 근거를 조회·기록하고 불확실 상태를 성공/실패로 추정하지 않은 채 다음 작업의 차단을 해제 |

허용 enum은 stage/unstage/commit/create-branch/switch-branch/fetch/pull/push이다. continue-pull/abort-pull은 입력 오류로 거부한다. 400은 잘못된 입력, 404는 미등록 프로젝트·없는 대상, 409는 버전·진행·잠금 충돌, 503은 Git 사용 불가를 구분한다. 비저장소는 상태 조회에서 사용 불가 이유를 반환한다.

작업 기록은 서버 DATA_DIR의 전용 저장소에 operationId·프로젝트/저장소 식별·requestKey·종류·시각·사전 상태·현재 상태·안전한 요약을 저장한다. 사용자 소스·커밋 메시지·자격 증명·전체 명령 출력을 불필요하게 기록하지 않는다. 같은 requestKey는 기존 작업을 반환한다. 서버 종료 후 미완결 작업은 `uncertain`으로 전환하고 자동 재실행하지 않는다. 특히 push는 원격 조회 전 성공 여부를 단정하지 않는다. 로컬 작업도 실제 상태를 확인해 사용자가 결과를 검토하게 한다.

### 검토·검증 최신성 연계

소스 저장은 기존 문서 저장과 같은 파일 버전·계획 변경 판정 경로를 사용한다. Git fast-forward pull/브랜치 전환 후에도 관련 업무의 문서·소스·검증 기준을 다시 평가한다. index만 변경된 경우 소스 검증을 임의로 무효화하지 않으며 기존 실제 파일 해시 판정을 따른다. 업무 완료를 소스 화면에서 실행하는 API는 추가하지 않는다.

## Risks / Trade-offs

- 앱 밖 편집기·Git과의 경쟁 → 실행 직전 상태 토큰 검사, 파일 버전 비교, Git 잠금 존중 및 작업 후 재조회. 외부 프로세스에 대한 완전한 배타 잠금은 보장하지 않는다.
- 대규모 저장소의 탐색·Git 출력 → 지연 로딩·페이지·파일/출력/시간 상한, 잘린 결과 명시. 전체 트리 재귀 감시를 피한다.
- pull 이력 분기와 기존 진행 작업 → fast-forward 실패·기존 merge/rebase·인증/훅 실패를 구분하고 외부 정리를 안내하며 자동 통합하지 않는다.
- 작업 timeout 후 Git 자식 프로세스 또는 훅이 남을 수 있음 → 프로세스 트리 종료 및 종료 확인 전 잠금 유지. 확인 불가 시 복구 필요 상태로 추가 변경을 막는다.
- linked worktree 간 공통 메타정보 변경 → 실작업 트리와 공통 Git 디렉터리를 함께 조정한다.
사용자 선택에 따라 Git 인증·서명·훅의 초기 환경 설정은 외부에서 준비하고 앱은 기존 환경을 사용한다. 앱은 자격 증명을 직접 저장하지 않는다. merge/rebase 충돌은 외부 도구에서 정리하고 앱은 새로고침으로 실제 상태를 확인한다. 인증 입력이나 훅 때문에 비대화형으로 실행할 수 없으면 우회하지 않고 이유와 외부 준비 방법을 안내한다.

## Migration Plan

신규 프로젝트 API·컴포넌트·작업 기록을 추가하고 등록 소스 포맷은 유지한다. 기존 화면·업무 데이터와 세션 프로토콜의 호환성을 검증한다. 기능 반영 시 먼저 빌드·서버 테스트를 수행하고, 상주 서버 변경은 모든 업무·질문·승인 대기가 정리된 뒤 명시적으로 배포한다. 일반 웹 서버 교체로 13003을 함께 종료하지 않는다.

롤백은 화면 진입과 신규 변경 API를 비활성화하고 작업 기록을 보존한다. 이미 저장한 소스·커밋·원격 반영을 자동 역변경하지 않는다. 이전 정책이나 외부 도구의 진행 중 merge/rebase가 있으면 외부 Git으로 정리할 수 있게 실제 상태를 안내한다.

## Validation

파일 API는 프로젝트 경계·junction·특수 파일명·인코딩·한도·저장 경쟁을 검증한다. 임시 Git 저장소와 로컬 bare 원격으로 부분 스테이징·초기 커밋·이름 변경·실패 훅·linked worktree·기존 pull/rebase 설정과 무관한 fast-forward 성공·이력 분기 거부·기존 진행 작업의 조회 및 외부 정리 안내·계속/중단 API 거부·push 거부·인증 실패·응답 유실을 통합 검증한다. 실제 사용자 원격에는 테스트 push를 하지 않는다.

UI 테스트는 프로젝트 전환의 지연 응답, 원문 보존, 미저장 보호, 오류·제한·충돌 표시, 중복 클릭 방지, 검토·검증 최신성 및 한국어/기존 로케일 회귀를 다룬다. 2026-10-26 사용자 지시에 따라 실제 브라우저 검증은 사용자가 직접 수행한다. 사용자 검증 결과를 받기 전에는 통과로 기록하지 않으며 에이전트의 잔여 구현 작업으로 취급하지 않는다.

## Review Notes

문서 전체 검토의 ‘수정 요청’과 후속 검토 자료 16개에 대해 같은 대화에서 답변과 중복 의미를 확인해 관련 문서에 반영했다. 항목별 승인 상태는 기록하지 않는다. 검토 항목 문답이 정리되었으며 최신 문서 전체 검토와 구현 시작은 각각 사용자의 별도 동작을 기다린다. 이 문답을 문서 검토 완료·구현 시작·업무 완료로 처리하지 않는다.

사용자 답변에 따라 파일·폴더 생성, 파일 삭제, 이름 변경·이동을 포함한다. 일반 파일 관리는 유지한다. pull의 충돌 해결·계속·중단은 최신 fast-forward 전용 답변에 따라 제외한다.

사용자 선택에 따라 현재 앱의 디자인을 유지한다. Orca는 도구 안에서 개발을 완료하는 작업 흐름의 참고 대상으로 사용하고 색상·아이콘 등 시각 요소의 복제는 인수 기준에 포함하지 않는다. 확정한 파일 트리·코드·Git 패널을 현재 앱 디자인에 맞춘다.

- 최신 pull 답변을 반영한 계획은 재검토 대상이다. 이전 문서 검토·구현 완료·자동 검증 결과를 이번 정책 변경의 검토 완료나 구현 시작으로 승계하지 않는다.

# Tasks

구현·검증 작업 목록이다. 별도 세션의 검증 결과를 사용자로부터 전달받아 작업 4.2를 포함한 17개 작업의 완료 기록을 확인했다. 이 체크 상태는 실제 실행 환경 반영이나 사용자 최종 확인, 업무 완료·보관을 의미하지 않는다.

## 0. 업무 실행 격리

- [x] 0.1 원본·실행 경로와 격리 기준을 모델링하고 업무별 독립 복사본을 준비한다. Git 유무·기존 미커밋 변경·복사 실패·링크를 통한 원본 공유 금지 테스트로 확인한다.
- [x] 0.2 Codex 구현·재개·검증 위치와 권한 범위를 업무 폴더로 연결하고 해당 폴더의 의존성·런타임 준비를 지원한다. 원본 실행 차단·작업 폴더 누락·동일 대화 재개·계획 버전 대조 테스트로 확인한다.
- [x] 0.3 격리 기록 없는 기존 진행·완료 업무의 호환 상태를 제공한다. 공유 폴더 차이를 업무별 결과로 확정하지 않는 테스트와 docs/CODEX.md의 실행 위치·복구 설명으로 확인한다.

## 1. 파일 상태와 결과 저장

- [x] 1.1 스냅샷의 파일 존재·내용 가용성·미수집 이유와 수집 정책 버전을 모델링한다. 빈 파일·바이너리·크기 제한·과거 nullable 기록의 읽기 호환 테스트로 확인한다.
- [x] 1.2 시작 기준 시각과 버전이 포함된 업무별 완료 결과 저장을 추가한다. 최초 기준 유지, 변경 파일만 저장, 서버 재시작 후 동일 결과 조회 테스트로 확인한다.
- [x] 1.3 수집 전후 변경 감지와 파일 읽기 실패 처리를 추가한다. 불안정한 수집이나 읽기 오류를 빈 결과로 반환하지 않는 테스트로 확인한다.
- [x] 1.4 업무 전용 폴더만 비교하도록 수집을 변경한다. 업무 A·B가 서로 다른 파일 및 동일 파일을 수정할 때 A 결과에 B 변경이 포함되지 않는 테스트로 확인한다.

## 2. 완료 처리와 조회 API

- [x] 2.1 기존 완료 조건을 유지하며 동일 종료 스냅샷에 대해 검증 신선도를 확인하고 완료 결과와 업무 상태를 원자적으로 확정한다. 조건 불충족·저장 실패 롤백·중복 요청·재시도 테스트로 확인한다.
- [x] 2.2 진행 업무는 현재 비교, 완료·보관 업무는 저장 결과를 반환하도록 조회를 확장한다. 완료 후 프로젝트 파일 수정·삭제 및 보관 이후에도 결과가 같은지 테스트한다.
- [x] 2.3 기록 없는 과거 완료 업무와 유효한 변경 없음, Git 없는 프로젝트를 구분한다. 호환 API 테스트와 docs/API.md의 데이터·실패 응답 설명으로 확인한다.
- [x] 2.4 완료 요청과 구분되는 별도 사용자 요청에 따른 원본 반영, 경로별 충돌 검사·백업·반영 저널·복구를 구현한다. 미반영 상태의 완료 요청이 자동 반영하지 않는지와 다른 업무 파일 보존·동일 경로 충돌·부분 실패·재시작·반복 반영 테스트로 확인하고 API 문서에 반영한다.
- [x] 2.5 검증 결과·원본 반영 결과·완료 저장 결과의 해시 일치를 완료 조건에 연결한다. 미반영·충돌·반영 후 재수정 상태에서 완료가 차단되는 통합 테스트로 확인한다.

## 3. 결과 화면

- [x] 3.1 기존 결과 탭에 업무 연결 정보, 비교 시각, 현재/완료 결과 구분, 수집 제외 범위·격리 여부·원본 반영 동작과 충돌 상태를 표시한다. 화면 테스트로 각 출처·기록 없음·변경 없음·미반영·충돌 상태를 확인하고 한국어·영어 문구를 반영한다.
- [x] 3.2 `FileDiff`에 내용 가용성 상태를 전달하고 목록의 추가·수정·삭제 및 전후 줄 번호·문맥·전체 내용 보기를 유지한다. 빈 파일·삭제·추가·한쪽 내용 미수집·비교 계산 한도 테스트로 확인한다.
- [x] 3.3 docs/USAGE.md에 업무 전용 실행 공간, 원본 반영 요청과 충돌 복구, 완료 결과 보존, 과거 기록 한계와 수집 범위를 설명한다. 문서와 실제 화면 용어가 일치하는지 확인한다.

## 4. 통합 검증

- [x] 4.1 프로젝트 런타임으로 관련 백엔드·프런트엔드 테스트와 빌드를 실행하고 결과를 기록한다. 두 업무의 격리 실행부터 원본 반영·완료 결과 저장·재시작·보관 후 조회까지 통합 시나리오를 확인한다.
- [x] 4.2 OpenSpecBoard Windows 앱에서 완료 업무 파일 목록과 줄 단위 차이 및 완료 후 파일 변경에도 결과가 유지되는 흐름을 확인한다. 최신 빌드의 별도 검사 프로필에서 완료 시각·추가 및 수정 파일·전후 줄 번호와 차이를 확인했다. 검증 원본 수정·경로 이동 후 Codex 내장 브라우저 새로고침과 Windows 앱의 새 세션에서도 완료 결과가 유지됐다. 실제 실행 서버 반영은 진행·대기 업무 해소 후 별도 수행한다.

## Workflow follow-up

- 복구한 사용자 결정은 ‘기존 계획 유지’이며, 최신 `maintained_plan_review` 답변은 ‘문서 검토 완료’이다. 제안서·설계·명세·작업 목록의 재검토 답변을 기록하고 새 요구사항이나 구현 작업을 추가하지 않는다. 기존 17개 작업의 완료 기록을 유지한다. 실제 실행 환경 반영과 사용자 최종 결과 확인은 아직 남아 있다.
- 최신 검증 근거는 `verification.md`의 사용자 전달 결과와 후속 인계 검증 기록이다. Windows 검사 앱의 완료 시각·파일 목록·줄 단위 차이, 원본 수정·이동 이후 저장 결과 유지, 관련 테스트·빌드·OpenSpec strict 통과를 포함한다.
- 실제 13002/13003 실행 환경에는 아직 반영하지 않았다. 별도 세션에서 확인한 당시 상태는 실행 중 업무 2개와 대기 메시지 1개였다. 반영 전 모든 실행·질문·승인·대기 메시지가 해소됐는지 다시 확인하고, 해소된 뒤 별도 실행 단계에서 `scripts/restart.ps1 -Service session`으로 반영한다. 현재 계획 단계에서는 재시작하지 않는다.
- [review:confirm] 최신 검증 결과와 실제 실행 환경 반영 결과를 사용자가 최종 확인해야 한다. 화면 검증과 작업 체크만으로 업무를 자동 완료·보관하지 않으며, 완료 확인과 보관 요청은 별도 동작으로 받는다.
- 복구한 사용자 결정 ‘이 업무 변경만 표시’를 반영했다. 비교 기준 ‘완료 시점 보존’도 유지한다.
- 앞선 `revised_plan_review` 답변과 최신 `maintained_plan_review` 답변은 각각 해당 시점의 문서 검토 기록이다. 항목별 승인 상태를 만들지 않으며 문서 검토를 추가 구현 시작 지시로 간주하지 않는다.
- 결과 탭 유지, 업무별 독립 복사본 실행, 별도 원본 반영 요청과 충돌 검사, 기존 수집 규칙 유지 결정을 유지한다. 최신 문서 재검토 답변을 받았으므로 동일한 확인 질문을 반복하지 않는다. 이후 기능 계획을 수정하면 구현 전에 수정 문서를 다시 검토받는다.
- 최신 계획 문서에 대한 사용자 검토와 명시적인 구현 시작 요청 후 구현한다. 검토 목록 조회는 문서 검토 완료를 대신하지 않는다.
- 구현·검증 후 사용자 결과 확인을 받고 별도 보관 요청에 따라 처리한다.

# Proposal

## Why

완료된 업무에서 어떤 파일을 어떻게 수정했는지 나중에도 확인해야 한다. 현재 변경 파일 목록과 줄 단위 비교는 구현 시작 직전과 현재 파일을 비교하므로, 다른 작업으로 파일이 바뀌면 완료 당시 결과를 재현할 수 없다.

## What Changes

- 구현 시작 직전 기준 파일과 사용자 완료 확인 시점의 파일 차이를 업무별로 보존한다. 완료·보관 이후에는 저장된 결과를 조회한다.
- 이 업무의 실행·검증 전용 작업 폴더를 준비하고, 해당 폴더의 변경만 수집한다. 원본 프로젝트와 다른 업무의 병행 변경은 결과에 포함하지 않는다.
- 기존 파일 목록과 줄 단위 비교를 재사용해 추가·수정·삭제, 경로, 변경 전후 줄 번호를 제공한다.
- 비교 대상 업무, 시작·종료 시각, 비교 가능 여부와 수집 범위를 표시한다.
- Git 없는 프로젝트도 파일 스냅샷으로 지원하고, 과거 완료 업무의 기록이 없으면 복원할 수 없다고 안내한다.
- 변경 파일 영역은 기존 ‘결과’ 탭에 유지한다. 사용자가 이번 순차 검토에서 ‘기존 결과 탭 유지’를 선택했다.
- 업무 전용 복사본에서 실행·검증하고, 원본 반영 전에 충돌을 검사한다. 앞선 `revised_plan_review` 답변에서 확인한 실행 위치 변경과 반영 절차를 유지한다. 이번 문서 정리 후 최종 문서 검토는 별도 동작으로 받는다.

범위 밖: 변경 되돌리기, 자동 커밋, 커밋 선택 UI, 충돌 자동 병합, 바이너리 미리보기.

## Capabilities

### New Capabilities

없음.

### Modified Capabilities

- `development-execution`: 업무 실행 격리와 안전한 원본 반영, 업무 완료 시 변경 결과 보존, 완료·보관 업무의 변경 파일 조회 및 비교 불가 상태 요구사항을 추가한다.

## Impact

`backend/src/work/execution.service.ts`의 실행·스냅샷·변경 계산, `work.service.ts`의 구현 시작·원본 반영·완료 처리와 조회, `store.ts`의 기록 저장을 확장한다. `backend/src/codex/codex.service.ts`의 실행·재개 위치도 업무 전용 폴더로 전환한다. 프런트엔드 `WorkRoom.tsx`와 `FileDiff.tsx`, 관련 타입·다국어 문구·테스트·API 문서가 영향을 받는다. 새 외부 의존성은 계획하지 않는다.

## Review Context

- 복구한 최신 사용자 답변: `maintained_plan_review`는 ‘문서 검토 완료’이다. ‘기존 계획 유지’가 반영된 제안서·설계·명세·작업 목록의 재검토 답변을 받았다. 기능 요구사항과 기존 17개 작업 기록은 변경하지 않는다. 이는 추가 구현·서버 재시작·실제 환경 반영·업무 완료·보관 요청이 아니다. 이후 기능 계획이 변경되면 구현 전에 해당 최신 문서를 다시 검토받는다.
- 복구한 사용자 답변: `planning_revision_scope`는 ‘기존 계획 유지’이다. 확정한 기능 범위를 유지하고 새 요구사항을 추가하지 않는다. 이 답변은 수정된 문서의 검토 완료나 추가 구현 시작, 실제 서버 반영, 업무 완료·보관을 의미하지 않는다. 최신 문서 검토는 별도로 받는다.
- 사용자 답변: 비교 기준은 ‘완료 시점 보존’으로 선택했다. 이 답변은 전체 문서 검토 완료 또는 구현 시작을 의미하지 않는다.
- 복구한 사용자 답변: `change_attribution`은 ‘이 업무 변경만 표시’이다. 병행 변경 포함 허용 초안은 철회하며, 문서 재검토와 구현 시작 지시는 별도로 받는다.
- 사용자 재검토 답변: `revised_plan_review`에서 ‘문서 검토 완료’를 선택했다. 업무별 독립 복사본 실행·검증과 원본 반영 전 충돌 검사까지 포함한 수정 문서를 검토했다. 항목별 승인 상태를 만들지 않으며, 명시적인 구현 시작 지시는 아직 받지 않았다.
- 원본 아이디어는 보존하며 이전 문장에 검토 마커를 소급 적용하지 않는다. 검토 항목별 승인 상태는 저장하지 않는다.
- 이번 순차 검토 답변: 기존 결과 탭 유지, 완료 요청과 구분되는 별도 원본 반영 요청, 기존 수집 제외 규칙·텍스트 한도·tasks 체크박스 정규화 유지를 선택했다. 업무별 독립 복사본 실행과 원본 충돌 검사는 앞선 답변을 반영하여 재질문하지 않았다. 이 문서 정리는 최신 문서 검토 완료·구현 시작·업무 완료를 자동 처리하지 않는다.

# Spec Delta

## ADDED Requirements

### Requirement: 앱 내부 업무 복구

시스템은 복구가 필요한 업무에 원인과 가능한 후속 동작을 표시하고 ‘업무 복구’ 동작을 제공해야 한다(SHALL). 실제 대화 연결 성공 후에만 오류를 제거하고, 기존 대화·업무 단계·문서·검토 상태·사용자 초안을 유지해야 한다(MUST). 복구 자체로 AI 실행 또는 새 대화 생성을 시작해서는 안 된다(MUST).

#### Scenario: 격리 도입 전 업무의 복구
- **WHEN** 실행 경로와 격리 기준 기록이 없는 기존 업무에서 사용자가 업무 복구를 요청한다
- **THEN** 시스템은 등록된 원본 프로젝트 경로로 같은 대화를 재연결하며 원래 업무 단계를 유지한다
- **AND** 복구 성공을 표시하고 기존 연결 오류를 제거하며 AI 실행을 시작하지 않는다

#### Scenario: 정상 격리 업무의 복구
- **WHEN** 올바른 격리 기준과 식별 파일이 있는 업무의 복구를 요청한다
- **THEN** 시스템은 해당 격리 공간에서 같은 대화를 재연결한다

#### Scenario: 실제 격리 공간 누락 또는 식별 불일치
- **WHEN** 격리 이력이 있는 업무의 경로나 식별 검증이 실패한다
- **THEN** 시스템은 격리 공간 복구가 필요함을 안내하고 원본 프로젝트로 대체하거나 식별 파일을 자동 생성하지 않는다

#### Scenario: 다른 Codex가 대화를 점유
- **WHEN** 같은 대화가 다른 Codex에서 사용 중이어서 복구 요청이 거절된다
- **THEN** 시스템은 해당 대화의 점유를 해제한 뒤 재시도하도록 안내하고 대화 ID와 업무 자료를 유지한다
- **AND** 다른 앱의 대화를 강제로 종료하거나 보관하지 않는다

#### Scenario: 진행 중 업무의 복구 차단
- **WHEN** 실행·연결·질문·승인 대기 중인 업무에 복구 요청이 들어온다
- **THEN** 시스템은 중복 재연결을 차단하고 현재 작업을 먼저 마쳐야 함을 안내한다

#### Scenario: 실패 후 재시도와 초안 보존
- **WHEN** 복구에 실패한 사용자가 같은 화면에서 다시 복구를 시도한다
- **THEN** 시스템은 최신 상태를 다시 검사하며 새 대화를 생성하지 않고 입력 중인 대화와 문서 초안을 유지한다

#### Scenario: 복구할 대화 식별자가 없음
- **WHEN** 복구 필요 상태이나 기존 대화 ID를 확인할 수 없다
- **THEN** 시스템은 자동 복구가 불가능한 이유를 표시하고 새 대화를 조용히 생성하지 않는다

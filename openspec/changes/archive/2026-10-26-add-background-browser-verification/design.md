# Design

## Context
동기는 proposal.md에 기술했다. 기존 Codex 동적 도구와 검증 레코드, 업무 격리 경로를 재사용한다. 기존 작업공간에는 미커밋 기능이 많으므로 파일을 되돌리거나 대화를 새로 만들지 않는다.

## Goals / Non-Goals
로컬 HTTP 서버 하나, 동시 실행 하나, headless Chromium 하나로 시작한다. 개인 브라우저·데스크톱 입력·외부 로그인·운영 데이터·OS 알림 검증은 범위 밖이다. AI의 자유 탐색 대신 실행 단계와 실패 캡처를 구조화해 조회한다.

## Decisions
- 독립 MCP나 Edge 확장 대신 Playwright 라이브러리를 서버 내부에서 사용한다. 브라우저 컨텍스트는 매 실행 새로 생성한다.
- 사용자 API가 시나리오를 저장한다. 서버 명령은 node/npm과 인자 배열, 작업 경로 하위 cwd, 127.0.0.1의 명시적 비예약 포트로 제한한다. 실제 실행 경로는 FileResults에서 얻는다. 개인 환경변수·앱 인증 토큰은 전달하지 않는다. 테스트 데이터 경로는 실행별 임시 폴더로 지정한다. 등록 명령은 신뢰한 프로젝트의 테스트 서버여야 하며 OS 샌드박스를 대체하지 않는다.
- 실행 전 포트 점유를 검사하고 새 서버를 소유해 실행한다. 기존 서버를 종료하거나 재사용하지 않는다. 준비 중 프로세스 종료는 차단 사유다. 자식 트리 종료는 소유 PID에 한해 수행한다.
- 브라우저 HTTP/WebSocket 통신은 정확히 등록한 origin만 허용한다. 서비스 워커·팝업·다운로드·권한 요청은 차단하고 저장 경로를 모델에 노출하지 않는다. DOM은 신뢰하지 않는 자료로 취급한다.
- 단계는 goto/reload/fill/click/expectText/expectValue/expectURL/expectVisible이다. role+name 또는 testId로 정확히 하나의 요소만 선택한다. 최소 하나의 결과 검사가 필수다. 고정 sleep·force click·실패 단계 자동 재실행을 쓰지 않는다.
- 실행 중 전역 잠금으로 다른 검증을 막는다. 시나리오 해시와 시작/종료 코드 해시를 저장하며 중간 변경은 stale 처리한다. 브라우저 결과는 일반 명령 전체 통과와 구분하며 미실행은 성공으로 표시하지 않는다.
- 작업별 결과와 단계별 상태, 마지막 화면을 SQLite에 보존한다. 인증값을 입력할 수 있는 비밀번호 필드는 지원하지 않는다. 진단은 길이를 제한하고 서버 원문 로그·쿠키·네트워크 본문은 모델에 전송하지 않는다.
- 설치된 Codex의 실제 실험적 JSON 스키마를 조회한 결과 thread/resume은 dynamicTools를 지원하지 않았다. 새 대화는 동적 도구를 등록하고 기존 대화는 업무별 .tools/browser-verification 파일 통로의 CLI로 run/status/cancel을 요청한다. 원본 rollout과 대화 ID를 변경하지 않으며 별도 네트워크·MCP 권한을 추가하지 않는다. 실행 전에 .processing 마커를 배타적으로 생성하고 제출 파일을 .submitted로 이동하여 중복 요청과 재시작 후 자동 재실행을 막는다. 잘못된 요청과 중복 제출은 각각 격리하며 다른 업무 요청을 차단하지 않는다.
- 설치 경로는 프로젝트 .tools/browser-runtime 또는 배포 service/browser-runtime이다. 자동 다운로드하지 않고 별도 준비 명령과 패키징 검사를 제공한다.
- HTTP 리다이렉트 후속 요청은 Playwright route만으로 통제하지 않는다. 실행기 내부의 스트리밍 HTTP 프록시가 정확한 origin으로만 전달하며 로컬 주소 우회와 DIRECT fallback을 사용하지 않는다. WebSocket CONNECT도 정확한 등록 host:port로만 연결한다. Chromium 자체 배경 통신은 차단하되 페이지의 실패로 오인하지 않는다.
- Windows Job Object 가드가 실행기와 독립적으로 작업자·호스트 종료를 감시한다. 작업자에게 시나리오를 보내기 전에 소유권 등록을 확인한다. 가드 종료 후에만 실행 잠금을 해제한다. PowerShell 실행 정책은 변경하지 않고 로컬 .NET 컴파일러로 준비한 가드 실행 파일을 배포한다.

## Risks / Trade-offs
- 포트 경합 → 실행 전 점유 거부, 시작 프로세스 생존 확인. 악성 로컬 프로세스에 대한 강한 격리는 제공하지 않는다.
- 테스트 서버가 운영 DB에 연결 → 등록 안내와 실행별 환경/데이터 분리. 프로젝트의 하드코딩된 운영 연결은 자동 안전화할 수 없다.
- 백그라운드와 실제 OS 동작 차이 → 결과에 Chromium/화면 크기를 기록하고 OS 검증을 대신하지 않는다.
- 기존 자동 완료 조건 → 브라우저 시나리오가 등록되면 최신 통과 결과가 없는 완료를 차단한다.

## Migration Plan
기존 Edge API는 호환을 위해 보존하지만 업무 화면에서는 새 검증 패널을 사용한다. 설치·무설치 패키지는 Chromium 런타임을 포함한다. 세션 서버 배포 재시작은 사용자 업무가 멈춘 뒤 수행하며 현재 턴에서 실행하지 않는다.

# Verification

## 검증 범위
2026-10-26, 프로젝트 전용 Node 24.15.0과 고정 Playwright 1.64.1 / Chromium 156.0.8078.4, Windows x64에서 확인했다. 기존 개발 서버·세션 서버·개인 브라우저를 종료하거나 재시작하지 않았다.

## 실제 브라우저와 프로세스
- 실제 headless Chromium으로 입력·저장·새로고침 후 값 유지와 화면 캡처를 확인했다.
- 잘못된 예상값과 모호한 버튼이 실패하고 후속 입력을 수행하지 않음을 확인했다.
- 외부 하위 리소스와 HTTP 리다이렉트를 차단했다. 다른 로컬 서버에서 받은 요청 수가 0인지 검사했다.
- 허용 origin의 SSE·WebSocket 통신과 첫 이벤트 전 SSE 헤더 전달을 확인했다.
- 점유한 포트를 재사용하지 않았다. 사용자 중단과 실행기 강제 종료가 통과로 기록되지 않았고, Job Object 가드가 남은 서버를 정리해 포트를 다시 사용할 수 있었다.
- 기존 대화용 파일 CLI의 실제 status/run과 화면 imagePath 전달을 확인했다. 기존 대화 ID는 유지했다. 70개의 처리 이력이 있어도 새 요청을 처리하는 회귀 시험을 통과했다.

## API와 대화 호환
- 시나리오 검증, 업무 경계, 실행 중복 차단, 질문·승인 대기 중 거절, 최신성 무효화, 종료·업데이트 가드를 검사했다.
- 설치된 Codex의 `app-server generate-json-schema --experimental` 결과 thread/start에는 dynamicTools가 있지만 thread/resume에는 없었다. 지원하지 않는 재개 인자를 제거하고 기존 대화에는 파일 통로를 사용한다.
- Codex RPC 도구 응답·동일 대화 유지 시험은 프로토콜 fixture로 수행했다. 실제 모델의 새 유료 턴을 실행하거나 사용자 대화를 변경하지 않았다.

## 실행한 명령
- `./scripts/npm.ps1 run build --workspace backend`: 통과.
- `./scripts/npm.ps1 run build --workspace frontend`: 통과. 기존 번들 크기 경고는 남아 있다.
- 프런트 BrowserVerification/WorkRoom/WorkTests/i18n 관련 8개 파일, 83개 테스트: 통과.
- `./scripts/npm.ps1 run desktop:test`: 144개 테스트 통과.
- 브라우저·업무·정책·네트워크·Codex 관련 22개 테스트: 통과. 이후 기존 대화용 CLI 시험과 누적 요청 회귀 시험을 추가했다.
- 백엔드 최종 범위: 44개 파일의 299개 시험 중 297개 통과, Windows 서버 실행 수동 검증 2개 건너뜀. 기본 forks 전체 실행은 283개 통과 뒤 Codex 업무 시험의 Vitest 작업자 종료 오류가 1회 발생했다. 해당 파일을 개별 실행하여 25개 통과를 확인했고, 이미 통과한 project-git/project-development-flow/project-api 3개 파일(48개 시험)을 제외한 나머지를 `--pool=threads --maxWorkers=1`로 재실행하여 40개 파일 249개 통과·2개 건너뜀·실행기 오류 0개를 확인했다. 단일 forks 실행의 전체 성공이라고 보고하지 않는다.
- `openspec validate add-background-browser-verification --strict`: 통과.
- 관련 추적 파일 `git diff --check`: 오류 없음. 저장소의 LF/CRLF 변환 안내만 표시된다.

## 배포 준비
`./scripts/setup-browser.ps1`을 실행하고 전용 Chromium과 Windows 프로세스 가드 실행 파일을 준비했다. 별도 `.tools/desktop-stage-browser-verification` 스테이징에 Playwright 1.64.1, Chromium, 가드, 기존 대화용 CLI와 컴파일된 메일박스가 포함되는지 확인했다. 기본 실행 폴더는 교체하지 않았다.

## 발견 후 수정한 결함
- route.continue만으로 후속 리다이렉트 통신을 통제하지 못하는 문제 → 고정 목적지 스트리밍 프록시와 외부 요청 0회 회귀 시험.
- AI 소유 실행 중 일반 중단이 AI 턴을 멈추지 않던 문제 → 소유자별 중단 처리와 API 시험.
- 실행기 충돌 때 하위 프로세스가 남을 가능성 → 독립 Windows Job Object 가드와 강제 종료 시험.
- PowerShell 스크립트 실행 정책에 막히던 가드 → 정책 변경 없이 컴파일한 전용 실행 파일 사용.
- SSE의 첫 데이터 전 헤더가 지연되던 문제 → 헤더 즉시 전달과 회귀 시험.
- 브라우저 종료 응답 지연 → 컨텍스트·열린 스트림을 먼저 정리한 뒤 브라우저 종료 확인. 최초 전체 회귀의 관련 실패를 수정하고 재검증했다.
- Playwright 드라이버 핸들 때문에 실행기 종료 확인이 지연되던 문제 → 정리를 끝내고 결과를 전달한 뒤 작업자가 명시적으로 종료하여 독립 가드가 남은 소유 핸들을 정리하게 했다.
- 기존 Codex의 재개 도구 갱신 미지원 → 업무별 파일 CLI로 호환.
- 처리 마커 64개 누적 시 요청 누락 → 처리 가능한 요청부터 제한하도록 수정.
- 루트가 같은 origin으로 리다이렉트할 때 서버 준비가 끝나지 않던 문제 → 준비 조회는 리다이렉트를 따라가지 않고 2xx/3xx 응답으로 기동만 확인한다. 실제 이동은 브라우저 경계에서 검사하며 로컬 이동 통과·외부 이동 차단을 각각 확인했다.

## 남은 운영 확인
설치형 NSIS·무설치 ZIP의 새 배포물을 생성·설치하거나 사용자의 실행 중 세션에 반영하지 않았다. 업무와 질문·승인이 모두 끝난 뒤 세션 서버를 명시적으로 재시작해야 한다. OS 알림·트레이·네이티브 파일 대화상자·실제 모바일·외부 로그인은 이 검증의 범위가 아니다. 프로젝트가 하드코딩한 운영 DB 연결이나 오래된 dist 제공까지 자동으로 안전화하지는 않으며, 등록하는 테스트 서버 스크립트에서 테스트 데이터와 최신 빌드를 보장해야 한다.

## 두 미완료 변경 재개 채팅의 추가 검증

- 브라우저 정책·실행기·서비스·API 4개 파일 18개 테스트를 별도로 재실행하여 통과했다(57.46초).
- 독립 검토에서 같은 요청 ID 재제출 시 중복 실행과 과거 응답 오인, `null` 요청이 전체 처리를 막는 결함을 발견했다. 각각 실패하는 테스트를 먼저 실행한 뒤 수정했다. 처리·결과 기록 중복을 거부하고 `wx` 독점 마커를 실행 전에 만들며, 요청별 형식 오류를 격리한다. 누적 처리 기록 64개 뒤 새 중단 요청을 포함한 회귀 3개가 통과했다. 수정 후 재검토에서 추가 중요 문제는 없었다.
- CLI·메일박스·실행기·서비스·API·정책 6개 파일을 함께 실행했을 때 24개 통과·1개 실패였다. 실패는 SSE 사례의 Chromium 시작 10초 제한 초과였으며, 이후 실행기 전체 6개를 다시 실행하여 모두 통과했다(47.13초). 이 한 번의 시작 시간 초과를 전체 검사 통과로 감추지 않는다.
- 최신 백엔드 TypeScript 빌드가 통과했다. 독립 `.tools/desktop-stage-two-change-followup`에도 Chromium·Windows 가드·CLI·최신 메일박스와 실행기 코드를 복사하고 빌드 파일과 바이트 단위로 대조했다. 소유권 가드와 실제 프로세스 정리 검사는 테스트 프로세스 실행 제한을 해제한 별도 실행에서 수행했고 OS 보안 설정이나 샌드박스 정책은 변경하지 않았다.
- 근거 요약은 `.data/two-change-followup-evidence.json`에 보존했다. 실제 사용자 대화·설정·서버의 배포 재시작은 수행하지 않았다.

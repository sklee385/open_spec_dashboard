# Spec Delta

## Purpose
사용자의 PC 입력과 브라우저 작업을 방해하지 않고, 업무별 로컬 테스트 환경에서 정해진 웹 시나리오를 실행하여 실제 결과와 화면 증거를 보존하고 실패와 미실행을 정확히 구분한다.

## ADDED Requirements

### Requirement: 백그라운드 시나리오 실행
시스템은 사용자가 등록한 로컬 테스트 시나리오를 전용 브라우저로 실행해야 한다(SHALL). 실행은 동시에 하나이며 개인 브라우저나 OS 입력을 조작해서는 안 된다(MUST).
#### Scenario: 사용자가 다른 앱을 사용하는 중 실행
- **WHEN** 사용자가 업무의 시나리오 실행을 요청한다
- **THEN** 창 활성화 없이 관찰·입력·결과 확인을 진행하고 단계별 결과와 화면을 제공한다
#### Scenario: 동시 실행 요청
- **WHEN** 다른 검증이 진행 중이다
- **THEN** 새 실행을 거부하며 기존 실행을 유지한다

### Requirement: 실행 및 통신 경계
시스템은 업무 격리 경로의 새 테스트 서버와 등록한 로컬 origin만 사용해야 한다(MUST). 기존 포트·개인 인증·외부 사이트를 자동 재사용해서는 안 된다(MUST).
#### Scenario: 포트 점유 또는 외부 통신
- **WHEN** 지정 포트가 점유됐거나 페이지가 허용하지 않은 통신을 시도한다
- **THEN** 해당 검증을 차단 상태로 남기고 기존 서버를 종료하지 않는다
#### Scenario: 서버가 준비되지 않음
- **WHEN** 새 서버가 종료되거나 준비 시간 내 응답하지 않는다
- **THEN** 검증을 통과로 표시하지 않고 소유 자원을 정리한다

### Requirement: 결과 검사와 최신성
시스템은 최소 하나의 명시적 결과 검사를 요구하며 코드와 시나리오 버전에 연결한 결과를 저장해야 한다(SHALL).
#### Scenario: 저장 결과 검증
- **WHEN** 입력·저장·새로고침 후 예상값 유지 검사를 실행한다
- **THEN** 실제 값이 맞아야 통과하고 불일치와 모호한 요소는 실패한다
#### Scenario: 검증 이후 코드 또는 시나리오 변경
- **WHEN** 통과 후 코드나 시나리오가 변경된다
- **THEN** 과거 결과를 현재 통과로 사용하지 않고 완료를 막는다

### Requirement: 중단과 복구
시스템은 사용자 중단·실행기 종료·서버 재시작을 통과와 구분하고 소유한 서버와 브라우저를 정리해야 한다(MUST).
#### Scenario: 저장 후 연결 끊김
- **WHEN** 조작 결과가 불명확해진다
- **THEN** 입력을 자동 반복하지 않고 실패 또는 중단 결과를 남긴다

### Requirement: 기존 대화와 배포 지원
시스템은 기존 업무 대화를 보존하며 AI의 등록 시나리오 실행·조회·중단을 지원해야 한다(SHALL). 설치본과 무설치본의 브라우저 준비 오류를 표시해야 한다(SHALL).
#### Scenario: 기존 대화에서 검증 요청
- **WHEN** 기존 업무의 AI가 브라우저 검증을 요청한다
- **THEN** 같은 대화 ID와 질문 도구를 유지하며 사용 가능한 도구 또는 업무 전용 파일 통로로 등록 시나리오를 실행한다
#### Scenario: 런타임 누락
- **WHEN** 배포 또는 개발 환경의 브라우저 실행 파일이 없다
- **THEN** 준비 필요 오류를 표시하고 다운로드나 PC 제어로 자동 대체하지 않는다

# Proposal

## Why

현재 OpenSpec UI에서는 진행 상황을 확인한 뒤 문서 수정과 AI 대화·개발을 위해 다른 도구로 이동해야 한다. 아이디어부터 개발 완료까지 동일한 업무 세션에서 대화와 결정 사항을 유지하며 작업할 수 있는 공간이 필요하다.

## What Changes

- 프로젝트의 아이디어를 업무로 전환하고, 요구사항 구체화 → 제안·설계·명세·작업 목록 → 구현 → 검증·완료를 한 화면에서 진행한다.
- 하나의 업무 세션을 하나의 영속 Codex 대화에 연결하여 단계 변경, 화면 새로고침, 서버 재시작 후에도 같은 대화를 이어간다.
- 아이디어·문서 작성·구현·검증·완료 검토의 모든 단계에서 AI와 문답하며 문서나 결과물을 반복 수정한다. 문서 직접 편집과 AI 수정의 충돌도 처리한다.
- 불명확한 요구사항에 대한 AI 질문을 화면에 표시하고 답변을 문서와 이후 작업에 연결한다.
- 업무 화면에 OpenSpec 산출물 상태·의존성과 차단 원인, 다음 작성 단계, 워크플로 정보, 기준 명세·변경 명세 비교, 검증 결과 및 관계 진단을 제공한다.
- UI에서 Codex 실행과 추가 지시, 진행 상황·코드 변경·검증 결과 확인, 완료 및 OpenSpec 보관을 처리한다.
- 백엔드는 NestJS/TypeScript로 구현하고, 원본 Rust/Axum 서버의 프로젝트 설정·아이디어 CRUD·OpenSpec 조회·파일 감시·SSE 계약을 이식한다.
- 출처 아이디어 4개는 이 변경의 `source-ideas/`에 보존하고 모니터링에서는 하나의 Todo로 전환한다.
- 제외 범위: AI 도구 선택, 다중 AI 실행, 팀 협업·클라우드 배포, 자동 배포·병합. 기본 도구는 Codex다.

## Capabilities

### New Capabilities

- `work-sessions`: 프로젝트·아이디어·OpenSpec 변경·Codex 대화가 연결된 업무 세션과 단계별 작업 화면, 재연결.
- `artifact-editing`: OpenSpec 문서 조회·직접 편집·AI 수정 요청과 변경 충돌 처리.
- `requirement-clarification`: 업무에 연결된 AI 확인 질문, 사용자 답변, 결정 사항 반영과 대기 상태.
- `development-execution`: Codex 실행·추가 지시·중단과 재개, 결과 확인·검증·완료·보관.

### Modified Capabilities

없음. 현재 프로젝트에 기존 기능 명세가 없다.

## Impact

- 현재 폴더에는 OpenSpec 설정과 아이디어만 있고 애플리케이션 소스는 없다. 실행 중인 기존 모니터링 서버는 별도 설치 프로그램이다.
- 구현 단계에서 ToruAI/openspec-ui의 React/TypeScript 프런트엔드를 재사용하고, 백엔드는 NestJS/TypeScript로 새로 구현하여 작업 화면과 세션 API를 제공한다. 원본 서버의 기존 API·파일 형식과 모니터링·아이디어·프로젝트 설정 기능을 호환시키고 재사용 코드의 MIT 고지를 보존한다.
- 로컬 Codex app-server 연결, 업무 상태 저장소, 문서 쓰기 API 및 실행 이벤트 전송이 추가된다. OpenSpec Markdown/YAML 파일은 명세의 기준으로 유지한다.
- 계획 검토 후 사용자의 ‘다음 단계 진행’ 지시에 따라 애플리케이션 구현을 진행한다. 별도 개발 포트에서 검증하며 실행 중인 13000 설치본 교체는 포함하지 않는다.

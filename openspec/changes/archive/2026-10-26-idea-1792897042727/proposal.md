# Proposal

## Why

여러 업무를 동시에 진행하면 AI가 질문하거나 실행 승인을 요청한 사실을 놓치기 쉽다. Windows 프로그램의 백그라운드 업무 서버가 Windows 알림과 기본 알림음으로 이를 알리고, 클릭하면 프로그램의 해당 업무·질문 위치로 이동하게 한다.

## What Changes

- 화면 내 알림과 Windows 알림을 함께 제공한다. 화면 내 목록은 열린 대시보드에서, Windows 알림은 브라우저와 독립된 세션 서버에서 제공한다.
- 기존 웹 실행 호환 범위에서는 `closed_browser_scope` 답변인 **Edge 완전 종료도 포함**을 유지한다. 데스크톱 프로그램에서는 창을 닫아 트레이에 있는 동안 소유 업무 서버가 새 질문·승인 알림을 발행한다.
- Windows 알림은 기본 알림음을 한 번 요청한다. 반복 독촉과 반복 재생은 추가하지 않는다.
- 데스크톱 프로그램에서 발생한 알림 클릭은 앱 전용 링크로 기존 프로그램 창을 복원하고 해당 업무·질문으로 이동한다. 앱을 완전히 종료한 뒤 기존 알림을 클릭하면 앱을 다시 실행해 이동한다. 새 창·중복 업무 서버를 만들거나 화면을 새로고침해 초안을 잃지 않게 한다. 화면 이동을 답변·실행 승인·문서 검토 완료·구현 시작으로 처리하지 않는다.
- Windows 알림은 처음부터 켜짐을 기본으로 하며 제품 시작 시 네이티브 등록·활성화를 시도한다. 사용자가 설정에서 끌 수 있고, 저장한 꺼짐 설정은 재시작 후에도 유지한다. 등록·주소 오류로 활성화하지 못하면 그 상태를 표시하며 브라우저 알림 권한과 탭의 실행 여부에 의존하지 않는다.
- 모든 등록 업무를 대상으로 질문과 승인을 구분하고, 화면 내 목록에서 대기 요청 수·발생 시각을 제공한다. 응답·만료 요청은 다음 갱신에서 제외한다.
- Windows 알림은 같은 요청당 자동 발행을 한 번만 시도한다. 전송 실패·결과 불명에도 자동 재시도하지 않고 상태를 표시한다. 발행 시도 기록은 서버에 보존하여 여러 탭·브라우저 데이터 삭제·세션 서버 재시작으로 같은 요청을 반복 발행하지 않는다.
- 사용자는 `review_local_runtime_scope` 질문에서 “현재 범위로 진행”을 선택했다. 같은 Windows 사용자가 로그인한 로컬 PC에서 세션 서버가 실행 중인 경우를 대상으로 한다.
  로그아웃·PC 종료·세션 서버 종료 중의 전달, 다른 PC·휴대전화 전송, 외부 Push 서비스는 범위에서 제외한다. Windows 알림 차단·방해 금지·음소거·스피커 음량은 앱이 강제로 변경하지 않는다.

## Capabilities

### New Capabilities

- `attention-notifications`: 브라우저 독립 Windows 알림·기본 알림음, 화면 내 대기 목록, 중복 방지와 업무·질문 이동.

### Modified Capabilities

없음. 기존 `requirement-clarification`의 질문·승인 구분과 `work-sessions`의 업무 격리를 유지하면서 알림 경로를 추가한다.

## Impact

기존 프런트엔드 `App`, `Header`, `WorkRoom` 및 알림 관리자에 더해 세션 서버의 알림 전달 서비스, Windows 네이티브 어댑터·사용자 범위 등록 도우미, 설정·상태 API와 서버 중복 방지 기록이 필요하다. 현재 브라우저 `Notification` 발행은 제거하고 Windows 알림을 서버 한 곳에서 발행한다. 외부 서비스는 도입하지 않으며 프로젝트 런타임과 같은 Windows 사용자 세션에서 동작한다.

사용자는 `review_final_workflow_boundary` 질문에 “원칙 유지”라고 답했다. 이 수정본의 제안서·설계·명세·작업 목록에 대한 최종 문서 검토 완료와 구현 시작은 사용자의 별도 동작으로 진행한다. 이번 원칙 확인 답변 자체로 두 동작을 수행하지 않는다.

이전 구현과 `verification.md`의 테스트 결과는 열린 탭에서 동작하는 이전 범위의 기록이며 새 범위의 구현·검증 완료를 의미하지 않는다. 항목 목록 조회·문서 검증·기존 작업 체크는 사용자 문서 검토 완료나 구현 시작을 대신하지 않으며 항목별 승인 상태도 추가하지 않는다.

## Verification disposition

- 사용자는 구현 후 “검증 완료 안된건 패스하고 진행 해라”라고 명시했다. 이에 따라 남아 있던 작업 5.2의 실제 Windows·Edge 검증을 이번 진행의 필수 작업에서 제외하고 생략으로 기록한다. 검증 통과로 처리하거나 기능 요구사항을 삭제하지 않는다. 자동 테스트·빌드·엄격 검증의 통과 근거는 유지한다. 운영 세션 서버 재시작과 업무 완료·보관을 자동 처리하는 지시로 해석하지 않는다.

## Desktop activation revision

- 사용자는 웹에서 Windows 프로그램으로 사용 방향을 바꾸었으며, 구조화 질문 `desktop_notification_activation`에 “추천안대로 진행”이라고 답했다. 기존 창·트레이 복원과 완전 종료 후 기존 알림 클릭에 의한 재실행을 포함한다. 앱 전용 프로토콜과 최초 실행 인자·단일 인스턴스 전달, 제한된 렌더러 연결을 사용한다. 앱 완전 종료 중 새 알림 수신은 제외한다.
- 데스크톱 실행에서는 고정된 앱 전용 링크를 사용하고 임시 HTTP 포트·브라우저 주소·인증 토큰을 알림에 넣지 않는다. 웹 실행의 기존 Edge 연결은 호환용으로 남긴다. 데스크톱과 웹의 알림 등록 ID를 분리해 서로의 등록을 덮어쓰지 않는다.
- 이번 수정은 위 사용자 답변으로 설계 방향을 확인하고 구현한다. 실제 프로그램을 종료하거나 진행 중인 앱·서버를 재시작하지 않는다. 이전 실제 검증 생략을 통과로 바꾸지 않는다.

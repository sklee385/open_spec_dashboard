# Spec Delta

## Purpose

여러 업무를 동시에 진행하는 사용자가 AI의 확인 질문이나 실행 승인 요청을 놓치지 않도록 화면 내 알림과 Windows 알림·기본 알림음을 제공한다. 세션 서버가 실행 중이면 Edge 완전 종료 중에도 알리고, 클릭하면 정확한 업무·요청으로 이동하면서 현재 상태와 기존 문답 흐름을 보존한다.

## ADDED Requirements

### Requirement: 데스크톱 프로그램으로 알림 이동

시스템은 Windows 프로그램에서 발생한 알림 클릭을 프로그램의 해당 업무·질문으로 연결해야 한다(SHALL). 데스크톱 모드에서 Edge나 외부 브라우저로 대체하거나 임시 HTTP 주소·인증 토큰을 알림에 노출해서는 안 된다(MUST). 기존 Edge 관련 시나리오는 웹 실행 호환 모드에만 적용한다.

#### Scenario: 기존 창·트레이·최소화 상태
- **WHEN** 프로그램이 실행 중인 상태에서 Windows 알림을 클릭한다
- **THEN** 기존 창을 복원해 최신 업무·질문으로 이동하며, 새 인스턴스·페이지 새로고침·자동 재연결 없이 미저장 입력을 보존한다

#### Scenario: 완전 종료 후 기존 알림 클릭
- **WHEN** 이미 발행된 알림을 프로그램 완전 종료 후 클릭한다
- **THEN** 설치된 프로그램을 다시 실행해 최근 업무 복원 전에 해당 업무·질문으로 이동한다

#### Scenario: 프로그램 준비 전 클릭·잘못된 링크
- **WHEN** 시작 중 링크가 전달되거나 앱 전용 URI가 잘못되었다
- **THEN** 유효 링크는 화면 준비 후 전달하고, 잘못된 링크는 오류로 표시하며 임의 URL·명령·파일·다른 업무를 열지 않는다

#### Scenario: 앱 연결 등록 실패
- **WHEN** 앱 전용 프로토콜 등록을 확인하지 못했다
- **THEN** 알림 사용 의도와 실제 비활성·연결 오류를 구분하고 Edge로 자동 대체하지 않는다

#### Scenario: 앱 완전 종료 중 새 요청
- **WHEN** 프로그램과 소유 업무 서버가 완전히 종료되어 있다
- **THEN** 새 알림 전달을 보장하지 않으며 이미 발행된 알림의 클릭에 의한 재실행만 지원한다

### Requirement: 모든 업무의 대기 요청 감지

시스템은 같은 Windows 사용자 세션의 서버가 실행 중인 동안 브라우저·대시보드 탭 실행 여부와 프로젝트 필터에 관계없이 등록된 모든 업무의 대기 요청을 감지해야 한다(SHALL). 확인 질문과 실행 승인을 구분하고 한 요청에 포함된 복수 질문은 알림 한 건으로 다뤄야 한다(SHALL).

#### Scenario: Edge 완전 종료 중 새 질문
- **WHEN** Windows 알림이 활성화되고 세션 서버가 실행 중인 상태에서 모든 Edge 창·탭을 종료한 뒤 새 확인 질문이 저장된다
- **THEN** 대시보드 재접속 없이 해당 요청의 Windows 알림 발행을 시도한다

#### Scenario: 연속된 승인 요청
- **WHEN** 같은 업무에서 기존 요청과 식별자가 다른 실행 승인 요청이 발생한다
- **THEN** 업무 상태가 계속 승인 대기여도 새 요청을 별도 알림으로 감지한다

### Requirement: 화면 내 알림과 대기 목록

시스템은 열린 대시보드의 공통 화면에서 대기 요청 수·목록·새 요청 안내를 제공해야 한다(SHALL). 각 항목에는 업무·프로젝트·종류·발생 시각을 표시해야 한다(SHALL). 전송·복구·결과 확인 중인 요청과 응답·만료된 요청은 대기 수에서 제외해야 한다(MUST). 조회 실패를 빈 목록으로 처리해서는 안 된다(MUST).

#### Scenario: 요청 처리 후 목록 갱신
- **WHEN** 대기 요청이 응답 완료나 만료 상태가 되고 다음 조회가 성공한다
- **THEN** 해당 요청은 대기 목록과 수에서 제거된다

#### Scenario: 최초 접속과 새로고침
- **WHEN** 기존 대기 요청이 있는 상태에서 대시보드를 열거나 새로고침한다
- **THEN** 현재 대기 요청을 모두 목록에 표시한다

#### Scenario: 조회 연결 실패
- **WHEN** 알림 목록 조회가 실패한다
- **THEN** 마지막 목록을 보존하고 연결 상태를 표시하며 대기 요청이 없다고 단정하지 않는다

### Requirement: 사용자 허용에 따른 Windows 알림

시스템은 저장된 설정이 없는 최초 제품 시작에 Windows 알림을 기본 켜짐으로 초기화하고 등록·활성화를 시도해야 한다(SHALL). 사용자 켜기·끄기를 저장하고 저장된 꺼짐을 재시작으로 바꾸어서는 안 된다(MUST). 활성화되면 브라우저와 독립적으로 업무명·요청 종류만 알리며 질문 원문·실행 명령·경로를 노출해서는 안 된다(MUST). 브라우저 알림 권한을 필수 조건으로 삼아서는 안 된다(MUST).

#### Scenario: 최초 시작의 기본 켜짐
- **WHEN** 저장된 알림 설정 없이 제품을 처음 시작한다
- **THEN** 대시보드에서 켜기를 누르지 않아도 Windows 알림 등록·활성화를 시도하며 사용자는 설정에서 끌 수 있다

#### Scenario: 현재 업무 또는 다른 창 사용 중 새 요청
- **WHEN** Windows 알림을 켠 상태에서 아직 발행을 시도하지 않은 유효한 대기 요청을 감지한다
- **THEN** 현재 업무를 보고 있거나 다른 창을 사용 중이거나 Edge가 종료되어 있어도 Windows 알림 발행을 시도한다

#### Scenario: 알림 끄기
- **WHEN** 사용자가 Windows 알림을 끈다
- **THEN** 이후 새 Windows 알림 발행을 중단하고 화면 내 대기 목록을 유지한다

#### Scenario: 미지원·등록·표시 실패
- **WHEN** Windows 알림을 지원하지 않거나 제품 등록·토스트 제출에 실패한다
- **THEN** 실패·미지원 상태와 설정 안내를 제공하고 화면 내 목록과 질문 응답 기능을 유지한다

#### Scenario: 설정상 켜짐이지만 등록 실패
- **WHEN** 기본 또는 저장된 사용 설정은 켜짐이지만 등록이나 직접 연결 주소 확인에 실패한다
- **THEN** 저장된 사용 의도와 실제 비활성 상태·오류를 구분하여 표시하고 전달 가능 상태로 오인시키지 않는다

### Requirement: 기본 알림음

시스템은 새 Windows 알림 발행 시 기본 시스템 알림음의 한 번 재생을 요청해야 한다(SHALL). 앱 자체에서 무음을 강제하거나 별도의 브라우저 소리를 중복 재생해서는 안 된다(MUST). Windows 음소거·방해 금지·알림 차단 설정을 임의 변경해서는 안 된다(MUST).

#### Scenario: 정상 음향 설정에서 알림
- **WHEN** Windows 알림·소리가 허용되고 새 대기 요청의 토스트가 표시된다
- **THEN** 기본 알림음이 한 번 재생되며 반복 재생이나 별도 브라우저 소리가 발생하지 않는다

#### Scenario: Windows가 소리를 차단
- **WHEN** Windows 설정이나 오디오 장치 상태가 소리를 차단한다
- **THEN** 앱은 이를 강제로 해제하지 않고 화면 내 대기 목록을 유지하며 음향 출력 성공으로 단정하지 않는다

### Requirement: 동일 요청의 중복 알림 방지

시스템은 같은 업무·요청의 Windows 알림 자동 발행 시도를 서버 저장소에 기록하여 최대 한 번으로 제한해야 한다(MUST). 여러 탭·브라우저 데이터 삭제·서버 재시작에도 기록을 유지해야 한다(MUST). 화면 내 일시 안내는 같은 브라우저 프로필·출처에서 중복을 방지하고 대기 목록은 항상 현재 요청을 표시해야 한다(SHALL).

#### Scenario: 여러 탭과 브라우저 데이터 삭제
- **WHEN** 여러 탭이 같은 요청을 조회하거나 브라우저 데이터를 삭제한 뒤 다시 접속한다
- **THEN** 서버가 이미 발행을 시도한 Windows 알림은 재발행하지 않으며 각 화면의 대기 목록은 현재 상태를 표시한다

#### Scenario: 서버 재시작 후 기존 요청
- **WHEN** 발행 시도 기록이 있는 요청을 서버 재시작 후 다시 감지한다
- **THEN** 요청이 여전히 대기 중이어도 같은 Windows 알림을 자동 재발행하지 않는다

#### Scenario: 서버 발행 기록 저장 실패 또는 결과 불명
- **WHEN** 발행 권한을 안전하게 저장할 수 없거나 OS 제출 결과를 확인할 수 없다
- **THEN** 무조건 발행·자동 재시도하지 않고 실패 또는 확인 필요 상태와 대기 목록을 보존한다

#### Scenario: 명확한 전송 실패 후 반복 조회
- **WHEN** Windows가 알림을 수락하지 않았음이 확실한 전송 실패 후 같은 대기 요청을 다시 조회하거나 서버를 재시작한다
- **THEN** 실패 상태를 보존하고 같은 요청을 자동으로 재전송하지 않으며 화면 내 대기 목록은 유지한다

#### Scenario: 브라우저 중복 방지 저장소 사용 불가
- **WHEN** 화면 내 일시 안내의 중복 방지 저장소를 사용할 수 없다
- **THEN** 해당 오류를 안내하고 대기 목록을 유지하며 서버의 Windows 알림 발행은 독립적으로 계속한다

### Requirement: 알림에서 해당 요청으로 이동

시스템은 알림 클릭 시 해당 업무를 열고 대화 영역의 대상 요청을 보여야 한다(SHALL). 데스크톱 모드는 프로그램으로, 웹 호환 모드는 Edge로 이동해야 한다(SHALL). 종료 상태의 기존 알림 클릭은 해당 실행 대상을 다시 열어야 한다(SHALL). 업무 간 이동 시 미저장 입력을 보존하고 클릭을 답변·승인·문서 검토 완료·구현 시작으로 처리해서는 안 된다(MUST).

#### Scenario: 종료된 Edge에서 알림 클릭
- **WHEN** 모든 Edge 창을 닫은 후 새 Windows 알림을 클릭한다
- **THEN** Edge의 대시보드에서 최신 업무를 확인하고 대상 질문에 스크롤·포커스를 이동하며 새 대화 생성·자동 재연결 요청은 보내지 않는다

#### Scenario: 알림 센터에서 나중에 클릭
- **WHEN** 알림 생성에 사용한 도우미가 종료된 뒤 Windows 알림 센터의 항목을 클릭한다
- **THEN** 생성 당시 브라우저 탭·도우미 콜백에 의존하지 않고 Edge에서 같은 업무·요청을 연다

#### Scenario: 다른 프로젝트의 질문 열기
- **WHEN** 화면 내 알림으로 다른 프로젝트의 업무를 연다
- **THEN** 현재 입력 초안을 보존하고 필터와 무관하게 해당 업무의 대상 질문을 보여준다

#### Scenario: 현재 업무의 새 질문 열기
- **WHEN** 현재 업무 화면이 아직 조회하지 않은 새 질문의 알림을 클릭한다
- **THEN** 최신 상세를 확인한 뒤 대상 요청에 포커스를 이동하고 기존 입력과 응답 상태를 유지한다

#### Scenario: 초안 저장 실패
- **WHEN** 같은 탭에서 다른 업무로 이동하기 위한 초안 저장이 실패한다
- **THEN** 현재 화면과 입력을 유지하고 이동 실패 및 재시도를 안내한다

### Requirement: 오래된 알림과 복구 처리

시스템은 알림 클릭 시 요청의 현재 상태를 확인해야 한다(SHALL). 이미 응답·만료된 요청은 해당 상태를 안내하고 자동 응답·승인·대화 복구를 수행해서는 안 된다(MUST). 업무·프로젝트가 없거나 직접 연결 인자가 잘못되면 다른 업무로 대체하지 않고 이동 실패를 알려야 한다(MUST).

#### Scenario: 이미 처리된 알림 클릭
- **WHEN** 다른 탭에서 답변을 마친 뒤 Windows 알림을 클릭한다
- **THEN** 해당 업무에서 처리된 요청임을 안내하며 다른 대기 질문으로 응답을 연결하지 않는다

#### Scenario: 연결 종료로 만료된 질문
- **WHEN** 세션 연결 종료로 질문이 만료된 후 기존 알림을 클릭한다
- **THEN** 만료 상태와 기존 복구 경로를 안내하고 사용자 조작 전에는 복구 답변을 전송하지 않는다

#### Scenario: 대상 제거 또는 잘못된 직접 연결
- **WHEN** 대상 업무·프로젝트를 찾을 수 없거나 직접 연결 식별자가 누락·잘못되었다
- **THEN** 이동 실패를 안내하고 기존 화면·초안을 보존하며 임의의 업무를 생성·재연결하지 않는다

### Requirement: 알림 설정과 직접 연결 주소

시스템은 Windows 알림의 저장된 켜짐·꺼짐, 등록·오류 상태 및 실제 대시보드 주소를 조회·수정할 수 있게 해야 한다(SHALL). 직접 연결 주소는 로컬 대시보드로 제한하고 임의 외부 URL·명령·파일 경로를 실행해서는 안 된다(MUST). 제품 등록·해제는 제품 전용 사용자 범위만 대상으로 해야 한다(MUST).

#### Scenario: 저장된 설정과 재시작
- **WHEN** 사용자가 알림 사용 설정을 저장한 뒤 브라우저나 세션 서버를 재시작한다
- **THEN** 저장된 켜짐·꺼짐을 복원하고 브라우저 권한 요청을 반복하지 않으며 꺼짐을 기본 켜짐으로 덮어쓰지 않는다

#### Scenario: 브라우저 접속 전 주소 준비
- **WHEN** 제품이 최초 기본 켜짐으로 시작하고 대시보드 탭은 아직 열리지 않았다
- **THEN** 배포 설정 또는 문서화된 기본 대시보드 주소로 직접 연결을 준비하며 잘못된 설정 주소는 오류로 알려 발행을 중단한다

#### Scenario: 대시보드 포트 변경
- **WHEN** 사용자가 새 로컬 대시보드 주소로 설정을 갱신한다
- **THEN** 이후 생성하는 Windows 알림은 갱신한 주소로 이동한다

#### Scenario: 잘못된 주소와 제품 등록 해제
- **WHEN** 사용자가 외부 URL·명령 형태의 주소를 저장하려 하거나 제품 알림 등록을 해제한다
- **THEN** 잘못된 주소는 거부하고 등록 해제는 제품 전용 항목만 제거하며 업무·질문·다른 앱 등록을 유지한다

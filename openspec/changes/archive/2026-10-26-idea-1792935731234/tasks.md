# Tasks

사용자가 문서 검토를 완료하고 구현 시작을 지시했다. 체크박스는 구현 진행용이며 항목별 승인 상태가 아니다.

## 1. 소스 관리 컴포넌트 분리

- [x] 1.1 `SourceManagementModal`로 소스 목록·추가·등록 해제 UI와 상태를 옮기고 `SettingsModal`에 AI 도구 설정을 유지한다. 컴포넌트 테스트로 두 창의 영역 분리와 AI 도구 설정 회귀를 확인한다.
- [x] 1.2 조회·저장 중 입력 차단, 조회 재시도, 저장 응답 목록 반영, 실패 후 재조회와 늦은 응답 처리를 구성한다. 정상 추가·등록 해제, 중복 요청, 조회·저장·복구 조회 실패 테스트로 확인한다.
- [x] 1.3 요청한 소스가 저장 응답에서 제외된 경우 완료 안내 대신 미등록 안내를 표시한다. 서버가 해당 소스를 제외한 응답을 반환하는 테스트로 확인한다.
- [x] 1.4 소스 관리 전용 제품 문구와 접근성 이름의 한국어·영어 번역을 정리한다. 번역 계약 테스트와 사용자 이름·경로 원문 유지 테스트로 확인한다.

## 2. 진입점과 데이터 갱신 연결

- [x] 2.1 `App`에 독립 창 상태와 `Header` 콜백을 연결하고 헤더·모바일 메뉴에 소스 관리를 제공한다. 각 진입점에서 창이 열리고 모바일 메뉴가 닫히며 설정 창과 중첩되지 않는 통합 테스트로 확인한다.
- [x] 2.2 저장 성공 시 소스·변경·명세·아이디어 재조회 흐름을 연결한다. 현재 선택 소스 등록 해제 시 전체 프로젝트 전환과 저장 선택값 정리, 다른 소스 변경 시 선택 유지 테스트로 확인한다.
- [x] 2.3 기존 키보드 닫기 처리와 새 창의 초점 복원을 연결한다. 키보드 탐색·닫기 테스트와 Codex 내장 브라우저 실화면 확인으로 검증한다.
- [x] 2.4 구현 후 `docs/USAGE.md`의 소스 등록·설정 안내를 새 진입점에 맞춘다. 안내 순서로 소스 관리와 AI 도구 설정에 각각 도달하는지 확인한다.

## 3. 통합 검증

- [x] 3.1 프로젝트 런타임으로 프런트엔드 테스트와 빌드를 실행하고 결과를 기록한다: `./scripts/npm.ps1 run test:run --workspace frontend`, `./scripts/npm.ps1 run build --workspace frontend`.
- [x] 3.2 Codex 내장 브라우저에서 헤더·모바일 진입, 추가·등록 해제, 빈 목록·오류, AI 도구 설정, 한국어·영어, 키보드 초점을 확인한다. 내장 브라우저에 접근할 수 없으면 미검증으로 기록하고 사용자 검토를 대체하지 않는다.

## Workflow follow-up

- 검증 근거는 `verification.md`에 기록했다. 최신 사용자 지침에 따라 Codex 내장 브라우저에서 실제 검증을 완료하여 2.3·3.2를 완료 처리했다. 과거 브라우저 접근 실패 기록은 보존한다. 이번에는 실제 화면에서 모바일 오류 내용의 가로 넘침을 발견하여 수정하고 같은 화면 크기로 재검증했다.
- 문서 검토 완료, 구현 시작, 사용자 완료 확인은 별도 절차다. 자동 검증이나 체크박스 완료만으로 대체하지 않는다.

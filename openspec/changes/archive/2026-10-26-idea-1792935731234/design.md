# Design

## Context

동기는 `proposal.md`의 Why를 따른다. 현재 `SettingsModal.tsx`는 `AiToolSettings`와 소스 조회·추가·삭제 상태를 모두 소유한다. `Header.tsx`는 데스크톱 설정 버튼과 모바일 메뉴를 제공하고, `App.tsx`가 설정 창 열림 상태를 관리한다.

소스는 `getConfig()`와 `updateSources()`로 읽고 저장한다. 백엔드는 설정 파일의 소스 목록을 갱신한 뒤 파일 감시를 재설정하고 SSE를 발행한다. `App.tsx`는 SSE 수신 시 소스·변경·명세·아이디어를 재조회한다. 서버는 존재하지 않는 경로를 저장 목록에서 제외하므로 요청 내용만으로 성공 목록을 추정하면 안 된다.

## Goals / Non-Goals

**Goals:** 소스 관리와 프로그램 설정의 UI 책임을 분리하고 기존 저장 계약을 활용한다. 구현 대상은 `specs/source-management/spec.md`의 동작이며, 초안 검토 항목은 아래에 명시한다.

**Non-Goals:** 소스 저장 형식 변경, 백엔드 검증 정책 재설계, 폴더 선택기, 소스 이름·경로 편집, 설정 항목 신설, 독립 라우트 추가.

## Decisions

### 독립 창과 직접 진입점

사용자가 별도 ‘소스 관리’ 창을 선택했다. 헤더와 모바일 메뉴에 설정과 구분되는 진입점을 추가한다. 독립 화면은 라우팅·뷰 전환 범위가 커지고, 소스 선택 메뉴 안에만 배치하면 발견하기 어려워 이번 구성에서 제외한다.

### 컴포넌트와 상태 소유권

`SourceManagementModal`을 추가해 기존 소스 UI와 조회·저장 상태를 옮긴다. `SettingsModal`은 `AiToolSettings`와 설정 컨테이너에 집중한다. `App`에서 두 창의 열림 상태와 콜백을 관리하고 동시에 두 창이 열리지 않도록 한다. 모바일 진입은 메뉴를 먼저 닫는다. 기존 Dialog를 재사용하고 키보드·초점 복원을 확인한다.

### 저장 결과와 갱신

- 기존 API와 저장 파일을 유지하며 화면 분리에 필요한 프런트엔드 변경으로 한정한다. 소스 제거는 원본 폴더 삭제가 아닌 등록 해제다.
- 입력 후 즉시 저장하는 기존 방식을 유지한다. 별도 일괄 저장·취소 절차는 추가하지 않는다.

조회 성공 전에는 추가·등록 해제를 막고 오류 시 재시도 수단을 제공한다. 저장 응답의 `sources`를 권위 있는 목록으로 반영한다. 요청한 새 소스가 응답에 없으면 추가 완료로 안내하지 않고 저장되지 않았음을 알린다. 저장 중 중복 요청을 차단하고 실패 시 재조회해 서버 상태를 복구한다. 이전 창 열기의 늦은 응답이 새 조회 결과를 덮지 않도록 요청 수명을 관리한다.

성공 콜백에서 `App`의 소스·변경·명세·아이디어 재조회 흐름을 호출해 SSE 도착 전에도 화면을 갱신한다. 최신 소스 목록에 선택 중인 ID가 없으면 전체 프로젝트로 복귀하고 `openspec-selected-source`도 정리한다. 기존 업무 연결이나 대화 데이터를 변경하지 않는다.

사용자 결정: 복구된 `removed_source_filter` 질문의 답변은 ‘전체 프로젝트로 전환 (권장)’이다. 선택 중인 소스의 등록 해제 후 전체 프로젝트로 전환하며 원본 폴더와 파일은 유지한다. 이 답변은 해당 동작에 관한 결정이며 계획 문서 전체 검토 완료나 구현 시작 지시를 의미하지 않는다.

### 번역과 검증

새 메뉴·제목·오류·입력·접근성 이름은 기존 i18n 체계를 사용한다. 기존 `settings.*` 중 소스 관리 문구는 별도 소스 관리 영역으로 정리하고 AI 도구 문구와 분리한다. 소스 이름·경로는 번역하지 않는다. 자동 검증은 진입점 연결·설정 영역 제거·API 성공/실패·필터 갱신을 중심으로 한다.

## Risks / Trade-offs

- 잘못된 경로가 서버에서 제외될 수 있음 → 저장 응답을 확인하고 미등록을 성공으로 안내하지 않는다.
- 선택 소스 등록 해제 후 필터가 남을 수 있음 → 최신 목록과 비교해 전체 프로젝트로 전환한다.
- 소스 창 분리 중 AI 도구 설정이 손상될 수 있음 → 설정에서 도구 선택·저장 회귀를 검증한다.
- Codex 내장 브라우저 연결을 사용할 수 없을 수 있음 → 실화면 검증 미수행으로 기록한다. 최신 전역 사용자 지침에 따라 남은 실화면 검증은 Codex 내장 브라우저로 수행하며, 이전 Edge 테스트 지시는 대체한다. Edge 확장이나 별도 브라우저 MCP 서버는 사용하지 않는다.

## Migration Plan

프런트엔드 컴포넌트와 번역 변경을 함께 반영한다. 데이터 이전은 필요 없다. 문제가 생기면 UI 변경을 되돌려 기존 설정 내 소스 관리로 복귀할 수 있다. 세션 서버 재시작은 이 UI 분리 작업의 절차에 포함하지 않는다.

## Review Record

사용자는 `planning_document_review` 질문에 ‘계획 문서 검토 완료’로 답했다. 검토 대상은 제안서·설계·명세·작업 목록 전체이며, 기존 API·즉시 저장 유지와 폴더 선택기·소스 편집 제외를 포함한다. 이 기록은 사용자 답변에 근거하며 항목별 승인 상태를 만들지 않는다.

사용자가 최신 문서 검토 완료 후 구현 시작을 명시적으로 요청하여 구현 단계로 전환했다. 문서 검토 완료나 검증 성공만으로 사용자 완료 확인을 대신하지 않는다.

2026-10-26 사용자 검토 항목 정리: 제공된 자료와 최신 원문의 버전을 대조하여 `proposal.md` 14행, `design.md` 27~28행의 세 항목을 순서대로 확인했다. 기존 `planning_document_review` 질문에서 기존 API·즉시 저장 유지, 폴더 선택기·소스 편집 제외를 포함한 전체 계획을 제시했고 사용자는 ‘계획 문서 검토 완료’로 답했다. 원본 폴더·파일 유지는 `removed_source_filter` 질문의 ‘전체 프로젝트로 전환 (권장)’ 답변에서도 확인했다. 이에 세 항목은 다시 질문하지 않고 기존 결정 내용으로 유지하며 가정 표기를 제거했다. API·저장 형식 유지 내용의 중복은 각 문서의 설명으로 유지한다.

위 검토 항목 정리 요청은 계획 단계에서 진행했다. 이 기록은 항목별 승인 상태를 만들지 않으며, 변경된 최신 문서의 최종 검토 완료·구현 시작·업무 완료를 자동 처리하지 않았다.

이후 사용자는 `continue_scope` 질문에 ‘남은 구현·검증 재개’로 답하여 남은 작업의 재개를 명시적으로 요청했다. 해당 답변에 따라 남은 실화면 검증을 재개하되, 새 문서 검토 완료나 업무 완료를 자동 처리하지 않는다.

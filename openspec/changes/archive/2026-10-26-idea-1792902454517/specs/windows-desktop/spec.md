# Spec Delta

## Purpose

현재 OpenSpecBoard의 화면과 로컬 업무 기능을 Windows 설치형 앱에서 제공한다. 설치와 실행을 단순화하면서 업무 데이터, 기존 대화와 사용자의 프로젝트를 보존한다.

## ADDED Requirements

### Requirement: 무설치 Windows 실행과 보존

앱은 Windows x64에서 배포 ZIP 전체를 풀고 OpenSpecBoard.exe를 실행해 설치기 없이 사용할 수 있어야 한다(SHALL). 런타임과 리소스를 포함하고 업무·설정·로그는 실행 폴더 밖의 기존 사용자 데이터에 보존해야 한다(MUST).

#### Scenario: 무설치 ZIP 첫 실행
- **WHEN** 사용자가 ZIP 전체를 별도 폴더에 풀어 실행한다
- **THEN** 설치기를 실행하지 않고 동봉 런타임으로 대시보드를 준비하며 기존 앱·서버를 강제로 종료하지 않는다

#### Scenario: 무설치 실행 폴더 업데이트
- **WHEN** 유휴 상태에서 검증된 새 ZIP으로 실행 폴더를 교체한다
- **THEN** 외부 사용자 데이터와 프로젝트를 보존하고 교체 전 폴더 백업과 진단 결과를 남긴다

### Requirement: 설치 후 대시보드 실행

앱은 설치 후 바로 현재 대시보드를 열고 필요한 로컬 서비스를 준비해야 한다(SHALL). 서비스 준비 실패 시 오류와 재시도를 표시해야 한다(SHALL).

지원 대상은 Windows x64 사용자별 설치이며 앱용 Windows x64 Node 런타임을 동봉한다. AI CLI와 인증은 별도 사용자 환경을 이용한다.

- 지원 범위는 Windows 10 이상 x64다. macOS와 Windows arm64는 이번 배포 대상에서 제외한다.

#### Scenario: 개발 환경 없는 PC에서 실행
- **WHEN** 지원 Windows x64 PC에 앱을 설치하고 실행한다
- **THEN** 소스 체크아웃, 개발 서버 또는 별도 시스템 Node 설치 없이 대시보드가 열리고 AI 도구 미설치·미인증은 준비 필요 상태로 표시된다

#### Scenario: 서비스 시작 실패
- **WHEN** 앱의 로컬 서비스를 준비할 수 없다
- **THEN** 준비 실패 원인과 재시도를 표시하고 업무 데이터는 유지한다

#### Scenario: 지원 아키텍처의 배포 파일 선택
- **WHEN** 사용자가 Windows x64용 앱을 설치한다
- **THEN** Windows x64 설치 파일과 동봉 런타임으로 실행된다

### Requirement: 데이터와 프로젝트 보존

앱은 업무 DB·설정·로그를 교체 가능한 설치 파일과 분리해야 한다(MUST). 사용자 프로젝트의 OpenSpec 문서는 원래 프로젝트 경로에서 관리하고 앱 업데이트 시 덮어써서는 안 된다(MUST).

#### Scenario: 앱 재설치 및 업데이트
- **WHEN** 같은 사용자에게 앱을 재설치하거나 새 버전을 설치한다
- **THEN** 기존 업무·대화 식별자·도구 설정·프로젝트 연결 및 프로젝트 문서가 유지된다

#### Scenario: 첫 실행 시 프로젝트 미등록
- **WHEN** 프로젝트가 없는 새 사용자 프로필에서 실행한다
- **THEN** 설치 디렉터리를 작업 프로젝트로 자동 등록하지 않고 프로젝트 등록을 안내한다

### Requirement: 기존 환경과 프로세스 격리

앱은 기존 웹 개발 서버와 다른 앱의 포트를 강제 점유하거나 프로세스를 종료해서는 안 된다(MUST). 같은 데이터 저장소를 사용하는 앱 인스턴스와 세션 소유자는 중복 생성하지 않아야 한다(MUST).

#### Scenario: 개발 서버와 동시 실행
- **WHEN** 기존 13001~13003 개발 서버가 실행 중인 상태에서 앱을 연다
- **THEN** 기존 서버와 데이터에 간섭하지 않는 앱 전용 주소 및 데이터 저장소로 실행한다

#### Scenario: 앱 중복 실행
- **WHEN** 같은 사용자 프로필의 앱을 다시 실행한다
- **THEN** 기존 창을 표시하고 같은 저장소의 세션 서버를 추가 생성하지 않는다

### Requirement: 진행 중 업무의 수명 보호

앱은 실행·연결·질문·승인 대기를 창 닫기와 자동 재시작으로 중단해서는 안 된다(MUST). 백그라운드 유지 상태와 종료가 보류된 이유를 사용자가 확인할 수 있어야 한다(SHALL).

#### Scenario: 질문 대기 중 창 닫기
- **WHEN** 미답변 질문이 있는 상태에서 창을 닫는다
- **THEN** 세션은 백그라운드에서 유지되고 앱을 다시 열어 같은 질문에 답할 수 있다

#### Scenario: 사용자의 명시적 종료 요청
- **WHEN** 진행 중 업무가 있는 상태에서 앱 종료를 요청한다
- **THEN** 종료를 보류하고 기존 업무의 중단·답변·승인 처리 방법을 안내한다

### Requirement: 로컬 앱 접근 경계

앱은 서비스 접근을 로컬로 제한하고 앱이 제공하는 권한을 신뢰할 수 없는 페이지에 노출해서는 안 된다(MUST). 외부 링크는 허용한 방식으로 시스템 브라우저에 열어야 한다(SHALL).

#### Scenario: 외부 페이지 탐색 요청
- **WHEN** 화면 콘텐츠가 외부 페이지 이동이나 임의의 시스템 실행을 요청한다
- **THEN** 앱의 권한을 전달하지 않고 허용된 링크만 시스템 브라우저로 연다

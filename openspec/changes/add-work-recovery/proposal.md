# Proposal

## Why

격리 공간 도입 전 원본 프로젝트에서 진행하던 업무가 재연결할 때 격리 공간 식별 검증에 실패한다. 사용자가 데이터베이스를 수동으로 수정하지 않고 앱 안에서 원인을 확인하고 같은 대화를 복구할 수 있어야 한다.

## What Changes

- 업무 화면에 진단 결과와 함께 사용할 수 있는 ‘업무 복구’ 동작을 제공한다.
- 기존 공유 폴더 업무와 정상 격리 업무를 구분하여 원래 경로의 같은 대화를 재연결한다. 복구는 AI 실행을 시작하지 않는다.
- 격리 폴더 누락·식별 불일치, 다른 Codex의 대화 점유, 미확인 대화 생성은 각각 원인과 다음 동작을 안내한다.
- 대화·문서·검토·단계를 유지하고 복구 이력을 남긴다. 실제 격리 폴더를 잃은 업무를 원본 경로로 대체하거나 새 대화를 자동 생성하지 않는다.
- 검증한 Windows x64 설치형과 무설치판을 새 버전 v0.1.3으로 GitHub Releases에 게시한다.

## Capabilities

### New Capabilities

없음.

### Modified Capabilities

- `work-sessions`: 앱 내부의 진단·복구 동작과 기존 공유 폴더 업무의 대화 재연결 계약을 확장한다.

## Impact

백엔드 Codex 재연결과 업무 API, 프런트엔드 WorkRoom 및 한국어·영어 문구, 회귀 테스트, 운영 문서, Windows 배포 버전과 산출물이 영향을 받는다. 새 외부 의존성은 추가하지 않는다. 다른 앱 강제 종료·대화 점유 강탈·데이터 삭제·자동 검토 완료는 범위에서 제외한다.

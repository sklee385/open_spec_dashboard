# Proposal

## Why

현재 업무 생성·대화·질문·개발 실행은 Codex 연결을 전제로 구성되어 있다. 기본 Codex 흐름을 유지하면서 사용자가 자신의 개발 환경에 맞는 다른 AI 개발 도구를 선택할 수 있도록 별도 변경으로 구체화한다.

## What Changes

- 기본 AI 개발 도구를 Codex로 유지하고 설정 메뉴에서 등록된 다른 AI 개발 도구를 선택·저장할 수 있게 한다. 선택은 새 업무의 전역 기본값으로 적용하고 기존 업무의 도구 연결은 유지한다.
- 도구별 연결 가능 상태를 확인하고 사용할 수 없을 때 원인과 사용자가 취할 조치를 표시한다.
- 업무와 선택한 도구·대화의 연결을 명시적으로 관리하여 도구 선택 때문에 기존 대화가 조용히 교체되거나 업무 맥락이 유실되지 않게 한다.
- 도구마다 대화, 질문·승인, 중단·재개 지원 여부를 구분하고 지원하지 않는 동작을 가능한 것으로 표시하지 않는다.
- 기존 Codex 업무와 저장된 대화의 호환성을 유지한다.
- 제외 범위: 여러 AI의 동시 실행·자동 분배, 자동 도구 전환, 서비스 계정의 신규 발급 및 클라우드 배포.

## Capabilities

### New Capabilities

- `ai-tool-selection`: 기본 Codex 및 추가 지원 AI 도구의 선택, 연결 상태와 지원 기능 표시, 업무별 도구 연결 및 전환 규칙.

### Modified Capabilities

없음. 현재 기본 명세 목록은 비어 있다. 진행 중인 `unified-codex-work-session`은 기본 Codex 사용과 동일 대화 유지를 요구하며 AI 도구 선택을 명시적으로 제외한다. 해당 변경의 범위를 바꾸지 않고 후속 변경으로 다루며, 그 명세가 기본 명세로 반영된 뒤 설계 시점에 관련 수정 명세 필요 여부를 재확인한다.

## Impact

- 백엔드: `backend/src/codex/codex.service.ts`, `client.ts`의 Codex 직접 연결과 업무·실행 서비스의 결합, `backend/src/work/store.ts`의 업무 저장 형식.
- 프런트엔드: 도구 설정 및 업무 화면의 도구·연결 상태 표시. 현재 `WorkRoom.tsx`는 Codex 명칭과 상태를 직접 표시한다.
- 사용자 결정은 기본 Codex 유지와 설정 메뉴의 다른 도구 선택이다. 설계는 내장 Codex 어댑터 및 비대화형 외부 CLI 등록을 제공하고 기존 업무 중 도구 전환은 지원하지 않는다.
- 외부 CLI는 저장 대화·최신 문서 맥락을 입력으로 전달하며 고유 세션 재개·구조화된 질문·승인은 지원하지 않는 것으로 표시한다. 특정 추가 제품의 독자 프로토콜이나 자동 대화 이전은 범위에 포함하지 않는다. 상세 실행 계약과 제한은 design.md 및 specs/ai-tool-selection/spec.md를 따른다.

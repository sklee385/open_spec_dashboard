# Tasks

구현은 사용자가 계획 문서를 검토한 뒤 명시적으로 요청할 때 시작한다. 기본 Codex·설정 메뉴 선택이라는 사용자 결정을 기준으로 하며 아래 항목은 모두 미구현 작업이다.

## 1. 도구 설정과 기존 데이터 호환

- [x] 1.1 ai-tools.json 설정 모델과 조회·버전 기반 원자 저장 API를 구현하고 기본 Codex·중복 ID·유효하지 않은 실행 인자·손상 파일·동시 저장 충돌을 테스트한다.
- [x] 1.2 업무 생성 시 도구·설정·기능 스냅샷을 저장하고 기존 도구 정보 없는 업무의 Codex 해석 및 참조 중 도구 삭제 거부를 백엔드 테스트로 검증한다.
- [x] 1.3 설정 변경 후 기존 threadId·검토 버전·이벤트가 유지되고 새 업무에만 기본값이 적용되는지 호환 테스트를 추가한다. 설정 파일과 롤백 제한을 운영 문서에 기록한다.

## 2. 실행 연결과 외부 CLI

- [x] 2.1 AiToolService·registry·CodexAdapter를 연결하고 기존 메시지·질문·승인·중단·재개 테스트가 통과하며 잘못된 도구 라우팅이 거부되는지 검증한다.
- [x] 2.2 ExternalCliAdapter의 shell 없는 실행·stdin/인자 입력·출력 이벤트·종료 판정을 구현하고 테스트용 CLI로 정상 응답·누락 파일·실패·시간 초과·출력 제한을 검증한다.
- [x] 2.3 대화·최신 문서 맥락 전달과 입력 크기 제한을 구현하고 다른 업무 격리·256KiB 초과 거부·비밀정보 진단 제한을 테스트한다.
- [x] 2.4 프로세스 트리 중단·동시 실행 차단·재시작 복구 필요 상태와 자동 재실행 금지를 테스트한다. 계획 검토 없이 외부 구현을 실행할 수 없음을 검증한다.
- [x] 2.5 외부 CLI 호환 조건·인자 예제·인증 방식·미지원 기능과 권한 차이를 사용자 문서에 작성하고 문서의 입력·출력 예제가 테스트 fixture와 일치하는지 확인한다.

## 3. 설정 UI와 업무 표시

- [x] 3.1 SettingsModal에 기본 도구 선택·외부 도구 등록·편집·삭제를 연결하고 저장 성공·오류·충돌·미설치 상태를 프런트엔드 테스트로 검증한다.
- [x] 3.2 WorkRoom의 도구 이름·지원 기능 표시와 미지원 동작 비활성화를 구현하고 기본값 변경 후 기존 업무 표시가 유지되는지 테스트한다.

## 4. 통합 검증

- [x] 4.1 npm test와 npm run build를 실행하고 Microsoft Edge의 ChatGPT 확장에서 설정 저장→새 업무 선택 적용→기존 Codex 업무 유지 흐름을 테스트용 CLI로 확인한다. 확장에 접근할 수 없으면 미검증으로 기록한다.

# 구현·검증 기록

검증 일자: 2026-10-25 (KST). 사용자 승인된 계획에 따라 구현했다. 이후 사용자가 같은 대화에서 “커밋 및 완료 처리”를 명시적으로 요청하여 최종 결과 확인과 완료 처리 의사를 전달했다. 보관은 요청 범위에 포함하지 않는다.

## 구현 내용

- `backend/src/ai-tools/`: 별도 ai-tools.json 설정과 버전 충돌·원자 저장 API, 설정 스냅샷, registry·CodexAdapter·ExternalCliAdapter, 기능 제한 및 준비 상태.
- 업무 생성·메시지·계획 작성·구현 요청·질문·승인·중단·재개를 공통 도구 서비스에 연결했다. 기존 도구 필드 없는 업무는 Codex로 해석하며 기존 DB를 일괄 재작성하지 않는다.
- 외부 실행은 shell 없이 프로젝트 디렉터리에서 수행한다. stdin/단독 인자, 저장 대화·최신 문서 전달, 입력 256KiB·출력 2MiB·제한 시간, 분류된 진단, 동시 실행 차단, 프로세스 트리 중단과 복구 필요 상태를 구현했다.
- 설정 메뉴의 기본 도구·외부 도구 등록·편집·삭제, 미설치·저장 오류·충돌 및 초안 보존을 연결했다. 업무 화면은 저장 도구 이름과 기능 제한을 표시하며 미지원 질문·승인·고유 재개를 실행하지 않는다.
- 사용법·인증·실행 권한·입출력 예제·설정 위치·롤백 제한은 `docs/AI-TOOLS.md`에 기록했다. 예제의 echo(stdin)·argument 모드를 fixture의 실제 구현 및 테스트와 대조했다.

## 자동 검증

프로젝트 전용 런타임으로 실행했다.

| 명령 | 결과 |
| --- | --- |
| `./scripts/npm.ps1 test` | 종료 코드 0. 프런트엔드 28개 파일/149개 테스트, 백엔드 15개 파일/86개 테스트 통과. 합계 235개. |
| `./scripts/npm.ps1 run build` | 종료 코드 0. 프런트엔드 TypeScript·Vite, 백엔드 TypeScript 빌드 통과. Vite의 500KiB 초과 청크 안내는 남아 있다. |
| `git diff --check` | 종료 코드 0. 기존 작업을 포함해 공백 오류 없음. |

기능별 검증 근거:

- `backend/test/ai-tools.test.ts`: 최초 Codex, 버전 충돌, 중복 ID·잘못된 인자·손상 파일, 업무별 스냅샷, 참조 도구 삭제 거부, 기본값 변경 전후의 threadId·검토 버전·이벤트 보존, 기존 데이터의 메모리상 Codex 해석.
- `backend/test/external-cli.test.ts` 및 `fixtures/external-cli.cjs`: 실제 로컬 프로세스로 stdin/인자·stdout, shell 기호 보존, 문서 최신 내용·대화·업무 격리, 입력 초과, 미설치·인증 실패·시간 초과·출력 제한, stderr 비밀 원문 미보존, 동시 실행·검토 경계, 자식 프로세스 종료, 재시작 시 자동 실행 금지.
- `backend/test/codex-work.test.ts`: 동일 대화·원래 질문 응답·승인·중단·재개·대기열·검토 경계 등 기존 Codex 회귀 17개와 providerSessionId 저장.
- `frontend/src/components/AiToolSettings.test.tsx`: 설정 등록·편집·선택·저장·삭제, 미설치, 충돌 시 초안 보존.
- `frontend/src/components/WorkRoom.test.tsx`: 업무 스냅샷 이름·기능 제한, 미지원 승인·자동 재개 방지 및 기존 업무 동작. i18n 계약 테스트도 통과했다.

테스트는 기능 미구현 실패를 먼저 확인한 후 구현했다. 별도 코드 리뷰에서 Windows 인자 길이가 256KiB보다 작은 OS 제한에 걸리면 spawn의 동기 예외가 업무를 running에 남기는 결함을 발견했다. 40,000자 입력 회귀 테스트로 재현하고 `argument-limit` 실패로 복구하도록 수정했으며 최종 전체 테스트에 포함해 통과했다.

검증 중 `taskkill`은 샌드박스에서 Access denied, 일반 권한에서는 20초 이상 지연됐다. WMI에 의존하지 않는 Windows Toolhelp 목록으로 자식부터 종료하도록 변경한 후 샌드박스 안에서도 실제 fixture 자식 종료를 확인했다. 일시적 테스트 워커 메모리 오류는 검증을 순차 실행하여 해소했다. 별도 알림 작업에서 발생했던 타입 오류도 최종 전체 빌드 시점에는 해소되어 있었다.

## Microsoft Edge 확인

사용자가 설치한 ChatGPT 확장에 연결된 Edge에서 확인했다. 브라우저 MCP 서버를 추가하지 않았다. 실행 중인 13003 세션 서버는 유지하고, 별도 임시 프로젝트·설정·DB를 사용하는 13021 테스트 서버에서 최종 빌드를 확인했다.

1. 설정에서 외부 도구 `browser-cli` / `테스트 외부 CLI`를 Node 실행 파일 및 `external-cli.cjs echo` 인자로 등록했다.
2. 새 업무 기본값으로 선택·저장하고 **AI 도구 설정을 저장했습니다**, **실행 파일 확인됨**을 확인했다. 저장만으로 도구는 실행되지 않았다.
3. `external-work`를 열어 도구 이름과 질문·승인·고유 재개 미지원 표시를 확인했다. 명시적으로 테스트 메시지를 전송하여 fixture의 stdout이 같은 업무 대화에 표시되고 대화 가능 상태로 돌아오는 것을 확인했다.
4. `legacy-work`를 열어 기존 **보존된 기존 Codex 대화**, **Codex legacy-browser-thread**, Codex 지원 기능 표시가 유지되는 것을 확인했다.

실제 제품별 외부 AI의 설치·인증·독자 프로토콜은 로컬 테스트 fixture 검증 범위에 포함하지 않았다. 외부 도구를 실제 등록한 사용자 환경에서 확인해야 한다.

## 후속 상태

커밋 전 재검증에서도 전체 테스트 235개와 빌드가 통과했다. 다른 업무의 미커밋 변경을 제외하도록 공유 파일의 관련 수정만 스테이징한 뒤 별도 폴더로 내보냈다. 해당 커밋 후보에서도 백엔드 61개·프런트엔드 77개 테스트(합계 138개), 양쪽 TypeScript 및 프런트엔드 Vite 빌드가 통과했다. 다른 업무의 변경은 작업 폴더에 보존한다.

- 사용자가 “커밋 및 완료 처리”를 명시적으로 요청했다. tasks 체크를 사용자 확인으로 간주하지 않고 해당 요청을 근거로 커밋·업무 완료 처리를 진행한다.
- 현재 요청을 수행하는 대화가 실행 중이므로 대화 종료 후 같은 업무의 검증 API에서 test·build를 실행하고, 최신 검증·계획 검토 조건을 만족할 때 완료 API를 호출한다. 결과는 `.logs/select-ai-development-tool-completion.json`에 기록한다. 조건 불충족 시 자동 완료하지 않는다.
- 운영 세션 반영은 모든 업무와 질문·승인 대기가 끝난 뒤 `./scripts/restart.ps1 -Service session`으로 명시적으로 수행한다. 검증 중 운영 세션은 재시작하지 않았다.

# 0.1.17 배포 전 수정과 검증 (2026-11-01)

- 정상 종료에서 실제 소유 Job 종료가 확인된 결과와 업무 idle 상태를 한 트랜잭션으로 보존한다. 미확인 종료는 성공/정상 종료로 추정하지 않는다.
- 완료·보관 업무의 실행 식별 없는 오래된 브라우저 running 이력은 보존하면서 종료를 허용한다. 실제 실행·소유 식별·cleanup 불명은 계속 차단한다.
- 준비 API 회귀 fixture는 서로 다른 거절 요청에 다른 requestKey를 사용한다. 후보 derived-commands fixture는 검사하려는 full 범위를 명시한다. 제품의 중복 요청/변경 차단을 완화하지 않았다.
- 사용자가 승인한 변경 범위 검증을 CI 기본값으로 반영한다. 전체 검사는 이유·장시간·예상 소요(모르면 미확인)를 안내하고 별도 승인한 수동 실행만 허용한다.

## 확인 결과

- 문서 준비·응답 유실 복구 등 기존 실패 항목 11개, 종료 상태 3개, 준비 API 1개: 15개 통과 (.tools/known-critical-regressions.json).
- 종료 기록 원자 저장 후 순차 실행·실패/중단·정상 종료/새 실행 3개 통과 (.tools/work-shutdown-atomic-proof.json).
- derived-commands 변경 차단 1개 통과 (.tools/editing-derived-plan-fix.json).
- 릴리스 게시 관련 10개 통과. backend build 통과. frontend source 불변으로 기존 성공 build 및 관련 UI 결과 재사용.
- 이전 변경 영향 관련 backend 19개·frontend 17개와 snapshot 15개 결과는 변경되지 않은 범위에서 재사용한다. 수치는 중복을 단순 합산한 전체 통과 수가 아니다.
- 현재 전체 suite는 실행하지 않았다. 정식 태그 CI에서 선택 검사·양쪽 빌드·실제 패키지/무설치 교체 smoke를 수행한 뒤 게시한다. 실제 사용 portable 교체와 데이터 대조는 게시 후 별도 수행한다.

## 반복 실패/지연 근거

- v0.1.15 전 단계에서 범위 선택 거절의 확정 응답 누락을 발견하여 수정했다.
- v0.1.16 전 단계에서 정상 종료 receipt 누락을 실제 회귀로 재현하여 수정했다.
- CI 41254864830의 integration-editing은 진행 기록상 약 38분 15초 후 38통과·1실패였다. 무응답만으로 교착으로 판단하지 않는다. 해당 실패 fixture를 수정하고 관련 한 건을 확인했다.
- 사용자가 기존 전체 CI 취소를 허용한 후 41249773899, 41253041144, 41254864830은 완료/cancelled를 확인했다. 실패 테스트를 삭제하거나 성공으로 바꾸지 않았다.
- 별도 일회 측정은 기존 conflict=false 사례 1개만 실행했다. 반복 경로/소유권 검사 호출이 관찰됐고, 중첩 시간은 합산하지 않는다. 임시 측정 테스트를 제거했으며 추가 프로파일링은 하지 않는다. 변경 확인 경계를 생략하지 않는다.
## CI 0.1.17 확정 실패 후 보완

CI 41261721257에서 업무 검증 9건·소유 Git Job 1건은 통과했고, HANDLE 신원 정상 경로 3건이 테스트의 로컬 전용 qa-head-runtime/browser-guard-v2 고정 경로로 실패했다. 신원 거부 검사의 넓은 오류 문구 조건도 실행 실패를 오인할 수 있었다. setup-browser.ps1이 실제로 준비한 browserDirectory()/guard/BrowserGuard.exe를 사용하고, PID 불일치는 HANDLE 신원 오류로만 통과하도록 강화했다. 제품 가드는 수정하지 않았다. 관련 4건을 로컬에서 통과했다. 정리 과정에서 잔존 fixture 변수를 고친 뒤 다시 통과를 확인했으며 전체 suite는 실행하지 않았다. 기존 v0.1.17 태그를 보존하고 수정된 0.1.18로 배포한다.

# Proposal

## Why

여러 업무의 변경이 섞이지 않도록 기존 복사 격리와 호환하면서 Git 이력을 이용한 안전한 병렬 개발과 순차 통합이 필요하다.
업무 공간의 저장 위치와 용량을 관리하고, 최신 통합 후보에서 검증한 결과만 사용자가 원본에 반영할 수 있게 한다.

## What Changes

- 새 Git 구현 업무에 업무별 브랜치·워크트리를 제공한다. 기존 복사 업무는 경로와 반영 방식을 유지하고 비Git·커밋 없는 프로젝트는 복사 격리를 사용한다.
- 초기 설정부터 경로 검사·저장·소유 식별을 구현한다. 설정 변경은 신규 공간에만 적용하며 이전 루트와 기존 업무를 유지한다.
- 선택한 안전한 기준 커밋과 해당 업무의 검토 문서로 시작하고, 원본의 미커밋 제품 코드는 제외 목록을 사용자가 확인한 뒤 제외하며 다른 업무 문서도 자동 유입하지 않는다.
- 전체·루트·업무별 용량과 잔여 공간을 표시하고 신규 생성 제한 및 사용자 확인 후 개별 정리를 제공한다.
- 사용자 승인 기본값은 동시 활성 업무 3개·최소 잔여 5 GiB·검증 자료 보존 14일이며 설정에서 조정할 수 있다. 기간 경과만으로 자동 삭제하지 않는다. 실제 폴더는 기능 구현 후 설정 화면에서 선택한다.
- 업무 공간 실행 잠금, 공유 Git 관리 잠금, 원본 통합 잠금을 분리한다.
- 통합 후보 생성·충돌 해결·최신 후보 재검증·사용자 확정·순차 fast-forward 반영과 장애 복구를 제공한다.
- 기존 백그라운드 브라우저 시나리오·단일 origin·전용 테스트 서버·기존 대화 CLI를 업무 및 통합 후보에 연결한다.
- CLI와 도구의 검증은 호스트가 소유한 별도 검증 사본에서 실행한다. 복사 전후·실행 종료 시 원본과 사본의 소스 식별을 확인하고 원본 변경은 stale로 무효화한다. 경계 확인 불가는 시작을 차단하며 같은 대화·턴·상태 조회·중단을 유지한다.
- 계획 검토, 구현 시작, 원본 반영, 완료, 보관은 기존의 명시적 사용자 동작을 유지한다.

## Capabilities

### New Capabilities

- `workspace-storage`: 저장 위치 설정, 루트 소유권, 고정 경로, 용량 집계·생성 제한·확인 후 정리.
- `worktree-integration`: 기준 문서 스냅샷, 업무 워크트리 생성, 통합 후보·검증·순차 반영·복구.

### Modified Capabilities

- `development-execution`: 복사/워크트리 격리와 원본 반영 분기, 기준 및 검증 근거.
- `project-git-workspace`: 공간별 잠금과 후보에서만 허용하는 병합 충돌 해결.
- `project-source-browser`: 원본·업무 공간·통합 후보 선택과 후보 접근 경계.
- `browser-verification`: 기존 실행 계약을 보존한 업무/후보 식별과 검증 최신성 확장.

## Impact

- 백엔드: `work/store.ts`, `file-results.ts`, `recovery.ts`, `execution.service.ts`, `work.service.ts`, 프로젝트 resolver/coordinator/Git 실행, 기존 설정 저장 서비스, AI 어댑터 및 `browser/*`.
- 프런트엔드: 설정, 업무·변경 결과·소스/Git·브라우저 검증 화면, API 타입과 번역. 데스크톱 폴더 선택 및 실행 스크립트의 환경 전달.
- 기존 Git 실행과 프로젝트 Node 런타임, 프로그램 전용 Playwright/Chromium을 재사용한다. 원격 push는 통합에 포함하지 않는다.
- 범위 밖: 기존 공간 자동 이전, dirty 원본 전체 가져오기, 자동 병합·자동 삭제, 범용 포트 관리 UI, 전용 3방향 병합 편집기, 중첩 저장소·submodule 자동 처리.
- 기존 변경은 보존하며 커밋·stash·reset·13003 세션 서버 재시작을 수행하지 않는다. 이전 초기 구현은 Git 메타데이터 없는 외부 관리 복사 공간에서 수행했으며 그 공간의 코드·검증 기록을 보존한다. 현재 작업 경로 변경만으로 기존 구현의 원본 반영이나 검증 환경 준비를 추정하지 않는다. 이번 수정은 사용자가 지정한 외부 OpenSpec 변경 문서에만 적용한다.
- 사용자 “추천하는데로 진행해” 답변과 복구 지시로 Q1~Q6 권장안이 확정됐으며 `design.md`의 Decision Record에 결정·근거를 보존한다. 초기 구현 6/54개 후 ‘검증 환경 준비 후 계속’ 결정을 반영해 문서를 재검토했고, 이후 별도 지시로 구현을 재개했다. 그룹별 선행 검증 조건을 유지한다. 당시 미완료였던 1.6은 이후 사용자의 실제 폴더 선택 반환과 그룹 1 회귀 96개 통과로 완료했으며 9.5는 여전히 미완료다. 그룹 1 완료 당시 진행률 7/54 기록을 보존하고 후속 구현을 재개했다.
- 문서 반영이나 strict 검증은 사용자 문서 검토 완료·구현 재개·원본 반영·완료·보관을 대신하지 않는다. 현재 재개 근거는 아래 별도 사용자 지시다.
- 2026-10-27 복구된 `review_updated_verification_environment_plan` 답변의 “문서 검토 완료” 선택과 `review_completed_answer_record` 답변의 “기록 반영본 검토 완료” 선택에 근거해 수정 문서의 사용자 검토와 기록 반영본 재검토 완료를 각각 기록한다. 이후 사용자가 “검토 완료 다시 구현 시작해라”라는 별도 지시를 내려 검증 환경 준비부터 재개했다. 기능 계획·검증 순서는 변경하지 않는다. 당시 6/54개·1.6 미완료 차단 이력과 이후 7/54개로 진행한 실제 선택 검증 기록을 구분해 보존하며 원본 반영·완료·보관은 별도다.

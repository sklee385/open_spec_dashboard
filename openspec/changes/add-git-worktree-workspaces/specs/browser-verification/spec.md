# Spec Delta

## MODIFIED Requirements

### Requirement: 실행 및 통신 경계
시스템은 검증된 업무 또는 소유 통합 후보 공간의 새 테스트 서버와 등록한 단일 로컬 origin만 사용해야 한다(MUST). 기존 시나리오를 유지하고 기존 포트·개인 인증·외부 사이트·다른 업무 서버를 자동 재사용해서는 안 된다(MUST). 환경과 실제 실행 경로·소스·빌드 출처·격리 데이터를 확인해야 한다(SHALL).

#### Scenario: 포트 점유 또는 외부 통신
- **WHEN** 지정 포트가 점유됐거나 페이지가 허용하지 않은 통신을 시도한다
- **THEN** 해당 검증을 차단 상태로 남기고 기존 서버를 종료하지 않는다

#### Scenario: 서버가 준비되지 않음
- **WHEN** 새 서버가 종료되거나 준비 시간 내 응답하지 않는다
- **THEN** 검증을 통과로 표시하지 않고 소유 자원을 정리한다

#### Scenario: 업무와 후보 구분
- **WHEN** 동일 시나리오를 업무와 통합 후보에서 각각 실행한다
- **THEN** 각 검증 대상의 경로·환경·소스·빌드·데이터·증거를 구분하고 후보는 새 서버에서 실행한다

#### Scenario: API와 오래된 빌드
- **WHEN** 여러 서비스 연결이 필요하거나 서버가 코드 출처를 확인할 수 없는 빌드를 제공한다
- **THEN** API는 신뢰된 테스트 프록시를 통해 단일 origin을 유지하고 빌드·환경 출처 미확인은 준비 불가로 표시하며 다른 origin을 자동 허용하지 않는다

### Requirement: 결과 검사와 최신성
시스템은 최소 하나의 명시적 결과 검사를 요구하며 업무/후보 ID·환경·커밋·실제 소스·계획·빌드·명령 설정·시나리오 버전에 연결한 결과를 저장해야 한다(SHALL). 후보 변경이나 대상 HEAD 변경 후 과거 통과를 새 후보의 완료 근거로 사용해서는 안 된다(MUST).

#### Scenario: 저장 결과 검증
- **WHEN** 입력·저장·새로고침 후 예상값 유지 검사를 실행한다
- **THEN** 실제 값이 맞아야 통과하고 불일치와 모호한 요소는 실패한다

#### Scenario: 검증 이후 코드 또는 시나리오 변경
- **WHEN** 통과 후 코드나 시나리오가 변경된다
- **THEN** 과거 결과를 현재 통과로 사용하지 않고 완료를 막는다

#### Scenario: 후보 재생성 또는 충돌 해결
- **WHEN** 대상 HEAD 변경으로 후보를 다시 만들거나 후보 소스를 수정한다
- **THEN** 필수 브라우저 검증을 후보에서 다시 실행하고 업무 단독 통과나 이전 후보 결과를 복사하지 않는다

#### Scenario: 검증 실행 중 변경
- **WHEN** 같은 공간에 AI 쓰기·수동 편집·정리·후보 재생성을 요청하거나 외부 수정이 발생한다
- **THEN** 충돌하는 앱 작업은 차단하고 실행 전후 버전 불일치 결과는 stale 또는 차단·중단으로 남기며 통과 처리하지 않는다

### Requirement: 기존 대화와 배포 지원
시스템은 기존 업무 대화와 시나리오 형식을 보존하며 등록 시나리오의 실행·조회·중단을 지원해야 한다(SHALL). 업무 전용 CLI와 새 대화 도구는 서버가 확인한 실행 컨텍스트에만 묶이고 임의 경로·다른 업무·후보 선택을 허용해서는 안 된다(MUST). 설치본·무설치본의 준비 오류와 실제 서버 반영 여부를 구분해야 한다(SHALL).

#### Scenario: 기존 대화에서 검증 요청
- **WHEN** 기존 업무의 AI가 브라우저 검증을 요청한다
- **THEN** 같은 대화 ID와 질문 도구를 유지하며 사용 가능한 도구 또는 기존 업무 전용 CLI의 run/status/cancel로 등록 시나리오를 실행한다

#### Scenario: 런타임 누락
- **WHEN** 배포 또는 개발 환경의 브라우저 실행 파일이 없다
- **THEN** 준비 필요 오류를 표시하고 다운로드나 PC 제어로 자동 대체하지 않는다

#### Scenario: 후보 전환과 처리 중 요청
- **WHEN** 검증 대상이 후보로 전환되거나 처리 중 CLI 요청이 재시작 후 발견된다
- **THEN** 이전 대상의 결과를 새 대상에 연결하거나 요청을 자동 반복하지 않고 실제 상태와 해당 대상의 결과를 조회하게 한다

#### Scenario: 운영 서버 미반영
- **WHEN** 새 코드의 검증 보고는 있으나 현재 서버 반영을 확인하지 못했다
- **THEN** 해당 상태를 따로 표시하며 코드 존재만으로 운영 가용을 선언하거나 질문·승인 대기 중 세션 서버를 재시작하지 않는다

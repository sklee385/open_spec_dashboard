# Spec Delta

## MODIFIED Requirements

### Requirement: 기존 merge/rebase 진행 상태의 안내
시스템은 원본·일반 업무의 기존 merge/rebase와 미병합 인덱스를 식별하고 Git 변경을 거부하며 외부 도구에서 정리하도록 안내해야 한다(MUST). 앱이 소유한 검증된 통합 후보에 한해서만 충돌 편집·stage·해결 완료를 제공해야 한다(SHALL). 일반 pull의 계속·중단 기능은 제공하지 않고 기존 영속 기록을 삭제하거나 실제 성공으로 추정해서는 안 된다(MUST).

#### Scenario: 이미 진행 중인 작업
- **WHEN** 원본 또는 일반 업무에서 이전 앱 정책 또는 외부 도구가 시작한 merge/rebase나 미병합 인덱스가 발견된다
- **THEN** 실제 상태와 대상 파일을 표시하고 Git 변경을 막으며 외부 해결 또는 중단 후 새로고침을 안내한다

#### Scenario: 미지원 계속 또는 중단 요청
- **WHEN** 클라이언트가 continue-pull 또는 abort-pull을 요청한다
- **THEN** 지원하지 않는 작업으로 거부하고 merge/rebase continue·abort·reset을 실행하지 않는다

#### Scenario: 외부 정리 후 재조회
- **WHEN** 사용자가 외부 도구에서 진행 작업을 해결 또는 중단하고 새로고침한다
- **THEN** 실제 저장소 상태로 변경 가능 여부를 재판정하며 과거 작업을 자동 재실행하거나 성공 처리하지 않는다

#### Scenario: 소유 통합 후보의 충돌
- **WHEN** 앱이 생성한 통합 후보의 소유 정보와 병합 의도가 일치한다
- **THEN** 후보에서만 충돌 파일 편집·명시적 stage·해결 커밋을 허용하고 기존 검증을 무효화하며 원본의 충돌 해결 허용으로 확대하지 않는다

### Requirement: 변경 작업 직렬화와 최신 상태 확인
시스템은 같은 공간의 AI 쓰기·파일 변경·검증·index/HEAD 변경을 상호 배제하고 독립 업무 공간의 실행은 병렬 허용해야 한다(MUST). 공유 Git 관리·ref 변경과 원본 통합·보관은 각각 저장소 범위에서 직렬화하며 사전 상태 불일치와 영향 범위의 미확인 작업을 차단해야 한다(MUST).

#### Scenario: 같은 프로젝트 AI 실행 중
- **WHEN** 같은 공간의 연결 업무가 실행·복구·답변·승인 대기 중에 소스 저장이나 충돌하는 Git 변경을 요청한다
- **THEN** 서버는 읽기는 유지하되 변경을 거부하고 해당 업무의 정리 또는 중단을 안내한다

#### Scenario: 두 탭의 동시 조작
- **WHEN** 두 탭에서 같은 저장소에 변경 작업을 요청한다
- **THEN** 시스템은 충돌하는 동시 실행과 같은 요청의 중복 실행을 막고 결과 상태를 다시 조회하게 한다

#### Scenario: 독립 업무와 공유 관리
- **WHEN** A가 실행 또는 질문 대기 중 B가 자기 워크트리에서 편집·테스트를 시작한다
- **THEN** 독립 실행은 허용하고 worktree 생성·제거·공유 ref 작업과 원본 통합은 필요한 공유 잠금으로 보호한다

#### Scenario: 종료 불명확한 Git 작업
- **WHEN** Git 작업 종료와 반영 여부를 확인할 수 없다
- **THEN** 해당 공간 또는 공유 자원의 차단을 유지하고 실제 상태 확인 전 자동 재실행하지 않는다

# Spec Delta

## Purpose

업무 및 통합 후보의 작업 전용 공간을 사용자가 지정한 안전한 위치에 저장하고, 기존 경로와 소유권을 유지하면서 용량 확인·생성 제한·확인 후 정리를 일관되게 제공한다.

## ADDED Requirements

### Requirement: 작업 공간 위치 설정
시스템은 최초 신규 공간 생성 전에 실행 호스트의 저장 위치를 검사하고 사용자 확인을 받아 저장해야 한다(SHALL). 환경 설정, 저장 설정, 최초 안내 순서의 우선순위와 실제 적용 경로를 표시하고 오래된 버전의 설정 저장을 거부해야 한다(MUST).

#### Scenario: 최초 설정과 재실행
- **WHEN** 사용자가 데스크톱 폴더 선택 또는 호스트 절대 경로 입력 후 검사·저장한다
- **THEN** 정규화 경로와 관리 하위 폴더를 보여주고 재실행 후에도 같은 설정으로 새 공간을 생성한다

#### Scenario: 환경 설정 우선
- **WHEN** 명시적 WORKSPACE_ROOT가 존재한다
- **THEN** 환경 고정 출처와 UI 편집 제한을 표시하고 최초 사용 전 검사·확인한 경로를 실제 생성에 사용한다

#### Scenario: 동시 설정 저장
- **WHEN** 다른 화면이 설정을 변경한 뒤 이전 버전으로 저장한다
- **THEN** 저장을 거부하고 초안을 보존하며 프로젝트·도구 등 다른 설정을 유실하지 않는다

### Requirement: 저장 경로 경계와 소유권
시스템은 절대 로컬 경로와 앱 프로필 소유 관리 하위 공간만 사용해야 한다(MUST). 원본·Git 관리·운영 데이터·설정·설치 영역과의 중첩, 드라이브 루트, UNC 및 링크에 의한 경계 우회를 거부하고 생성·정리 직전 다시 검사해야 한다(MUST).

#### Scenario: 위험한 경로
- **WHEN** 선택 경로가 보호 영역과 같거나 어느 방향으로든 포함하거나 junction으로 우회한다
- **THEN** 서버는 요청을 거부하고 기존 파일이나 시스템 권한을 변경하지 않는다

#### Scenario: 기존 폴더와 타 프로필
- **WHEN** 기존 파일이나 다른 프로필의 관리 공간이 있는 폴더를 선택한다
- **THEN** 기존 내용은 보존하고 자기 소유 관리 하위 폴더만 생성하며 타 프로필 공간을 재사용·정리하지 않는다

#### Scenario: 지원 경로와 권한 검사
- **WHEN** 한글·공백·다른 로컬 드라이브의 경로를 검사한다
- **THEN** 고유 검사 파일만으로 읽기·쓰기·삭제를 확인하고 실패 시 검사·저장을 성공으로 표시하지 않는다

### Requirement: 생성 당시 경로 유지
시스템은 공간의 루트 ID·소유 ID·생성 당시 절대 경로를 영속 저장하고 설정 변경 후에도 기존 공간을 같은 경로로 사용해야 한다(MUST). 경로 유실을 새 위치나 원본 실행으로 자동 대체해서는 안 된다(MUST).

#### Scenario: A 실행 중 위치 변경
- **WHEN** A가 실행 또는 질문·승인 대기 중에 위치를 변경하고 B를 시작한다
- **THEN** A의 경로·대화·검증 자료를 유지하고 B와 새 후보에만 새 설정을 적용하며 서버를 재시작하지 않는다

#### Scenario: 이전 루트와 드라이브 유실
- **WHEN** 이전 루트가 남아 있거나 드라이브가 분리된다
- **THEN** 이전 공간을 조회·용량·개별 정리 대상으로 유지하고 유실 공간은 복구 필요로 표시한다

### Requirement: 용량 표시와 신규 준비 제한
시스템은 전체·루트·업무·후보 사용량, 잔여 용량, 집계 시각과 부분 집계 여부를 제공해야 한다(SHALL). 사용자가 확정한 활성 업무 한도·최소 잔여 정책으로 준비를 제한하고 미확인 용량을 0 또는 충분함으로 처리해서는 안 된다(MUST).

#### Scenario: 용량과 한도 부족
- **WHEN** 활성 업무 한도를 넘거나 새 공간의 잔여 용량이 미확인·부족이다
- **THEN** 업무 한도는 시작 대기, 용량은 준비 차단으로 구분하고 기존 공간을 삭제하지 않는다

#### Scenario: 준비 중 용량 소진
- **WHEN** 복사·의존성 설치·빌드 전후 검사에서 공간 부족 또는 실패가 발생한다
- **THEN** 실패와 잔여 파일을 기록하고 복구·정리 대상으로 표시하며 준비 완료나 AI 실행으로 진행하지 않는다

#### Scenario: 집계 범위
- **WHEN** 의존성·빌드·검증 자료·중단 공간을 집계한다
- **THEN** 이를 포함하되 링크를 따라가지 않고 공유 저장분의 이중 합산을 피하며 미확인 범위와 예상 준비 크기를 표시한다

### Requirement: 확인 후 개별 공간 정리
시스템은 소유권·실행·미반영 결과를 검사하고 보존 기록과 삭제 대상을 제시한 뒤 사용자 확인으로만 개별 정리해야 한다(MUST). 강제 제거·루트 전체 삭제·일괄 prune·기간 경과에 따른 자동 삭제를 해서는 안 된다(MUST).

#### Scenario: 완료 공간 정리
- **WHEN** 정리 가능한 완료·보관 공간의 구체적 삭제 범위를 사용자가 확인한다
- **THEN** 완료 diff·요약 검증·통합 커밋을 먼저 장기 보존하고 정상 Git 등록 제거 후 소유 공간만 정리하며 운영 DB·설정을 유지한다

#### Scenario: 위험 상태 정리 차단
- **WHEN** 실행·서버·브라우저·질문·승인 대기·종료 불명·미커밋·미반영 커밋·미확인 ignored 파일 또는 소유 불일치가 있다
- **THEN** 일반 정리를 차단하고 구체적 이유를 표시하며 다른 폴더나 공통 런타임을 삭제하지 않는다

#### Scenario: 검증 자료 보존 기간 경과
- **WHEN** 사용자 확정 보존 기간이 지난 자료가 있다
- **THEN** 정리를 제안하고 확인 후 자료만 삭제하며 만료 증거를 남아 있는 링크로 표시하지 않는다

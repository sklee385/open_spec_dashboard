## 9. 결합 검증과 활성화 준비

- [ ] 9.1 실제 임시 Git 프로젝트의 A/B 동시 개발 → A 통합 → B 충돌 해결/후보 재검증 → 순차 반영을 실행한다. 각각의 diff·후보·검증·적용 HEAD와 원본 데이터 보존 증거를 남긴다.
- [ ] 9.2 설정 변경 중 기존 업무·질문 유지, 드라이브 유실, 용량 소진, 생성/반영/제거 중 장애를 결합 검증한다. 원본 대체 실행·중복 반영·강제 삭제가 없고 실제 상태 복구가 가능함을 기록한다.
- [ ] 9.3 앱 등록 시나리오로 업무/후보 데이터·화면 증거 격리, 정상 저장/새로고침, 의도적 실패, busy/금지 통신/중단을 검증한다. 설치·무설치 패키지에서도 런타임 준비/실행/종료 결과를 기록하고 수행 불가는 차단으로 남긴다.
- [ ] 9.4 `./scripts/npm.ps1 run test:run --workspace backend`, frontend의 test:run 및 두 workspace build를 실행한다. 실제 결과를 명세와 대조하고 필요한 경우에만 분할 회귀 사유와 범위를 기록한다.
  - Windows Git의 checkout child GIT_DIR 하드가드 때문에 정상 생성 fixture는 실행별 짧은 OS 임시 경로에서 검증한다. 기본 긴 TEMP에서의 미지원은 별도 사전 차단 회귀로 검증한다. CI에도 짧은 runner 임시 경로를 명시하며 전역 Windows 환경·ACL·실제 사용자 선택 폴더를 바꾸지 않는다.
- [ ] 9.5 Codex 내장 브라우저로 초기 설정부터 후보/정리까지 실제 사용자 동선을 확인한다. 접근 불가 시 미수행을 표시하고 성공으로 보고하지 않으며 사용자 최종 검토에 구체적 결과를 제공한다.
- [ ] 9.6 strict OpenSpec 검증과 명세/구현 대조 결과, 코드 버전·세션 서버 운영 반영 여부, 잔여 제한을 보고한다. 결합 검증 전 신규 워크트리 기본값을 활성화하지 않고 검증 결과 생성만으로 사용자 완료 확인을 대신하지 않는다.

- 실제 운영 서버 반영은 별도 시점에 수행한다. 모든 실행·질문·승인 대기가 끝나기 전 13003 세션을 재시작하지 않으며, 명시적 반영 후 실제 버전과 업무 복구를 확인한다.
- 보관이 만든 기준 명세·미커밋 변경을 사용자와 확인하고 다음 통합 전에 정리한다. 자동 커밋·stash·reset하지 않는다.

## 4.5 구현 중 확인 사항

- CLI 호출의 실제 쓰기 중지는 ‘신뢰 중계·실행 확인 보강’으로 확정했다. 근거는 2026-10-27 복구된 `cli_verification_write_handoff`의 명시적 선택이며 `design.md`에 결정·재현 근거를 보존한다. 확인되지 않는 시작을 차단하고 같은 대화·status/cancel을 유지한다. 현재 AI 턴 중단 후 검증으로 자동 전환하지 않는다.
- 4.5는 미완료이며 신뢰 중계·실제 실행 소유·쓰기 중지 확인과 변조 CLI/래퍼·임의 런타임 거부 검증 후에만 완료한다. 기존 정상 fixture 18개 통과는 이 보강의 완료 근거가 아니다.

- 2026-10-27 복구된 `review_cli_trusted_handoff_plan`에서 사용자가 “문서 검토 완료”를 선택해 신뢰 중계 결정을 반영한 네 문서의 검토 완료를 확인했다. 이는 별도 구현 재개 지시가 아니며 4.5 완료나 진행률 변경으로 계산하지 않는다.

- 2026-10-27 복구된 `review_cli_plan_completion_record`에서 사용자가 “기록 반영본 검토 완료”를 선택해 앞선 검토 완료 답변의 기록 반영본 재검토를 마쳤음을 확인했다. 앞선 문서 검토 완료 기록을 보존하며 이번 답변을 구현 재개 지시로 해석하지 않는다.

현재는 재검토 완료 답변을 추가로 기록한 최신 반영본의 사용자 검토 대기 단계다. proposal.md의 최신 기록 반영본 검토 항목을 기준으로 사용자 검토를 받은 뒤 별도 구현 재개 지시가 있어야 4.5부터 계속한다. 이번 계획 문서 수정으로 제품 코드를 구현하거나 23/54 진행률을 변경하지 않는다.

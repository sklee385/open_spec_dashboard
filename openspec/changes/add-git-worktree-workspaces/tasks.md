# Tasks

현재는 계획 단계다. 아래 체크박스는 향후 구현 작업이며 아직 수행하지 않았다. `design.md` Open Questions의 답변 반영과 사용자 문서 검토 완료, 별도 구현 시작 지시가 선행돼야 한다. 제안 수치는 확정값으로 구현하지 않는다.

각 항목은 약 1~2시간 단위의 독립적으로 확인 가능한 결과를 목표로 한다. 번호 순으로 진행하고 각 그룹의 검증이 통과한 뒤 다음 그룹으로 넘어간다. 초기 설정 기능부터 시작하며 도입 자체는 병렬 코드 수정하지 않는다. 기존 광범위한 미커밋 변경은 보존하고 구현 시작 때 변경 파일을 다시 대조한다.

## 1. 초기 위치 설정·경로 검사·저장

- [ ] 1.1 `work/workspace-settings.service.ts`와 기존 `LegacyService` 설정 타입에 공간 키·profileId·rootId·설정 버전을 추가한다. 기존 설정 읽기/저장 및 공간 설정 왕복 테스트로 프로젝트/도구 설정 보존과 원자 저장을 확인한다.
- [ ] 1.2 공통 경로 검사 모듈에 절대 로컬 경로·실부모·대소문자·보호 영역 양방향 포함·reparse 검사를 구현한다. 임시 폴더 테스트로 한글/공백 경로 허용과 UNC/루트/원본/DB/설치/링크 우회 거부를 확인한다.
- [ ] 1.3 고유 probe 파일 검사와 profile 관리 하위 폴더 소유 등록을 구현한다. 읽기 전용·타 소유·기존 파일 보존·검사 후 경로 교체 테스트에서 기존 내용이 바뀌지 않음을 확인한다.
- [ ] 1.4 settings controller와 `app.ts`에 조회·검사·저장 API를 연결한다. 요청 테스트로 검사 토큰/버전 불일치 거부, 환경 고정 시 편집 차단, 사용자 미확인 경로 생성 금지를 확인한다.
- [ ] 1.5 `WorkspaceSettings.tsx`를 `SettingsModal.tsx`에 연결하고 경로·출처·가용성·검사/저장·오류/초안 보존 및 번역을 제공한다. UI 테스트로 검사 전 저장 불가와 두 창의 충돌 표시를 확인한다.
- [ ] 1.6 데스크톱 폴더 선택 IPC와 비데스크톱 호스트 경로 입력을 연결한다. 취소/지원 불가 테스트와 실제 폴더 선택으로 경로 표시가 실행 호스트 기준임을 확인하고 사용자가 실제 저장 폴더를 선택할 수 있게 한다.
- [ ] 1.7 시작 스크립트·desktop/session의 WORKSPACE_ROOT 전달을 일치시킨다. 격리된 프로세스 설정 테스트로 우선순위와 재실행 유지, 저장 변경의 무재시작 적용을 확인하고 `docs/PROJECT-WORKSPACE.md`, `docs/API.md`에 초기 설정 절차를 기록한다.

## 2. 공통 공간 모델·기존 경로·용량 제한

- [ ] 2.1 `store.ts`에 copy/git-worktree 및 고정 rootId/workspaceId/path 기록을 추가하고 신규 workspace service를 만든다. 과거 baseline/isolated-baseline fixture에서 원래 executionPath와 threadId가 보존됨을 확인한다.
- [ ] 2.2 `file-results.ts`와 `recovery.ts`의 경로 판정을 공통 공간 서비스로 연결한다. `work-files`, 기존 복구·isolated-workflow 회귀로 복사 반영/완료와 공간 누락 시 원본 대체 금지를 확인한다.
- [ ] 2.3 루트 이력 조회와 참조 없는 루트 등록 해제를 구현한다. A 질문 대기 중 루트를 바꾸고 B를 준비하는 테스트로 A 경로/자료 유지와 B 신규 경로, 참조 루트 해제 차단을 확인한다.
- [ ] 2.4 용량 집계 모듈에 전체/루트/업무/후보·공유분·잔여·시각·부분 상태를 구현한다. 의존성/빌드/중단 공간 포함, 링크 미추적, 공유분 이중 합산 방지를 fixture로 확인한다.
- [ ] 2.5 확정된 동시 업무·최소 잔여·자료 기간 정책을 설정/API/UI에 연결한다. 한도 초과 대기, 미확인/부족 용량 준비 차단, 기존 실행 유지, 후보 별도 한도를 테스트한다.
- [ ] 2.6 생성·복사·설치·빌드 전후 용량 검사와 준비 실패 기록을 연결한다. 용량 소진 주입 테스트로 잔여 공간 보존·오류 표시·AI 미시작을 확인하고 용량 집계 한계를 사용 문서에 기록한다.

- [ ] 3.3 해당 변경 문서와 source-ideas manifest 수집·경계 검사·복사를 구현한다. 다른 업무 문서·미커밋 제품 코드 제외와 준비 중 HEAD/tip/문서 변경 시 중단을 실제 파일 비교로 확인한다.
- [ ] 3.4 가져온 문서만 명시적으로 커밋하고 baseCommit/workspaceBaselineCommit/검토 revision을 저장한다. 실제 diff로 제품 기준과 문서를 포함한 최종 통합 기준, tasks 진행 체크와 계획 변경 구분을 확인한다.

## 6. 후보 검증·순차 반영·실제 상태 복구

- [ ] 6.1 후보용 명령 검증을 실행 서비스에 추가하고 commit/실제 소스/계획/명령 버전에 묶는다. 후보 코드 수정과 workHead/targetHead 변경 시 필수 검증이 stale이 되는지 테스트한다.
- [ ] 6.2 사용자 확정 API에 원본 브랜치·HEAD·index·파일·진행 작업·타 worktree checkout 사전 재검사를 구현한다. dirty의 비겹침 파일까지 차단하고 stash/reset/자동 브랜치 전환이 없는지 실제 Git으로 확인한다.
- [ ] 6.3 통합 잠금 아래 ff-only 반영과 적용 HEAD 저장을 구현한다. 두 업무 순차 반영, 검사 후 대상 변경, 반영 전/후 실패 주입으로 안전 실패와 실제 상태 판정을 확인한다.
- [ ] 6.4 재시작/응답 유실의 실제 상태 확인 API를 구현한다. 적용됐지만 응답이 유실된 경우 중복 반영 없음, 미확인 상태 차단, 취소 후 결과 보존·자동 역병합 없음이 확인돼야 한다.
- [ ] 6.5 후보 검증/반영 가능/오래된 결과/복구 UI와 완료 조건을 연결한다. 업무 통과만으로 후보 확정 불가·원본 반영과 완료 별도 동작을 UI/API 회귀로 확인하고 복구/확정 절차를 문서화한다.

- [ ] 7.2 browser service/runner의 FileResults 직접 의존을 공통 공간 resolver로 바꾸고 환경별 새 서버/데이터/증거를 연결한다. 기존 시나리오 JSON과 고정 URL 회귀, 포트 점유·13001~13003 거부·다른 origin 차단을 확인한다.
- [ ] 7.3 테스트 서버 준비에 빌드/환경 식별 계약을 연결한다. 최신 빌드 성공·오래된 산출물·health만 응답·다른 서버 조합 테스트로 미확인 출처는 준비 불가임을 확인하고 프로젝트 테스트 스크립트 계약을 문서화한다.

- [ ] 8.2 공간 정리 사전 점검/미리보기 API를 구현한다. 실행·질문/승인·서버/브라우저·미반영/미커밋/미확인 ignored·소유 불일치가 모두 차단되는지 확인한다.
- [ ] 8.3 사용자 확인 토큰과 최신 상태 재검사로 정상 worktree 제거·확인된 컨테이너 정리를 구현한다. 실제 임시 공간으로 경로 교체/도중 실패/중복 요청을 확인하고 루트·운영 DB·공통 캐시·타 업무가 보존됨을 확인한다.
- [ ] 8.4 이전 루트별 용량/완료 공간/만료 자료 정리 UI를 제공한다. 제안 기간 경과만으로 삭제되지 않음·삭제 범위와 브랜치 처리 명시·취소 보존을 UI/API 테스트하고 수동 정리 절차를 문서화한다.
- [ ] 8.5 완료 확인·원본 보관 직렬화와 보관 후 dirty 검사를 연결한다. 기존 copy와 새 worktree 모두에서 반영 성공/보관 실패 분리·다음 통합 차단·완료/보관 자동 확정 금지를 회귀로 확인한다.

## 9. 결합 검증과 활성화 준비

- [ ] 9.1 실제 임시 Git 프로젝트의 A/B 동시 개발 → A 통합 → B 충돌 해결/후보 재검증 → 순차 반영을 실행한다. 각각의 diff·후보·검증·적용 HEAD와 원본 데이터 보존 증거를 남긴다.
- [ ] 9.2 설정 변경 중 기존 업무·질문 유지, 드라이브 유실, 용량 소진, 생성/반영/제거 중 장애를 결합 검증한다. 원본 대체 실행·중복 반영·강제 삭제가 없고 실제 상태 복구가 가능함을 기록한다.
- [ ] 9.3 앱 등록 시나리오로 업무/후보 데이터·화면 증거 격리, 정상 저장/새로고침, 의도적 실패, busy/금지 통신/중단을 검증한다. 설치·무설치 패키지에서도 런타임 준비/실행/종료 결과를 기록하고 수행 불가는 차단으로 남긴다.
- [ ] 9.4 `./scripts/npm.ps1 run test:run --workspace backend`, frontend의 test:run 및 두 workspace build를 실행한다. 실제 결과를 명세와 대조하고 필요한 경우에만 분할 회귀 사유와 범위를 기록한다.
- [ ] 9.5 Codex 내장 브라우저로 초기 설정부터 후보/정리까지 실제 사용자 동선을 확인한다. 접근 불가 시 미수행을 표시하고 성공으로 보고하지 않으며 사용자 최종 검토에 구체적 결과를 제공한다.
- [ ] 9.6 strict OpenSpec 검증과 명세/구현 대조 결과, 코드 버전·세션 서버 운영 반영 여부, 잔여 제한을 보고한다. 결합 검증 전 신규 워크트리 기본값을 활성화하지 않고 검증 결과 생성만으로 사용자 완료 확인을 대신하지 않는다.

## Workflow follow-up

- 사용자 최종 검토와 별도 원본 반영·완료 확인을 받은 뒤 기존 절차로 보관한다. tasks 완료율은 사용자 확인을 대체하지 않는다.
- 실제 운영 서버 반영은 별도 시점에 수행한다. 모든 실행·질문·승인 대기가 끝나기 전 13003 세션을 재시작하지 않으며, 명시적 반영 후 실제 버전과 업무 복구를 확인한다.
- 보관이 만든 기준 명세·미커밋 변경을 사용자와 확인하고 다음 통합 전에 정리한다. 자동 커밋·stash·reset하지 않는다.

# Tasks

사용자의 최신 문서 검토와 명시적 구현 시작 지시에 따라 구현을 진행한다. 구현·검증 근거는 [verification.md](verification.md)에 기록한다. 체크하지 않은 항목은 일부 코드가 있어도 해당 항목의 전체 검증까지 완료하지 않은 상태다. 사용자 결과 검토와 완료 확인은 별도로 필요하다.

- 제안서·설계·두 명세·작업 목록을 사용자에게 검토받고, 수정 의견을 같은 변경에 반영한다. 사용자 문서 검토 후 별도의 구현 시작 지시가 있어야 아래 작업을 시작한다.
- 데스크톱 구성은 사용자 수정 제안서의 Electron 권장안을 기준으로 한다. 배포 대상은 Windows x64, 배포 저장소는 `sklee385/open_spec_dashboard`다.
- 사용자 최신 지시에 따라 macOS 지원·배포·검증과 Edge 화면 검증은 범위에서 제외한다. Windows 앱 자체의 화면·설치·트레이·업데이트 검증은 유지한다.
- 저장소는 공개되어 있다. 2026-10-26 사용자가 인증서 없는 개인용 GitHub 업데이트를 승인했다. 개발·일반 검사 패키지와 업데이트 활성 개인용 배포를 구분한다. 인증서 준비·서명 검증은 범위에서 제외하고 해시·저장소·버전 확인과 실제 두 버전 업데이트 검증은 유지한다.

## 1. 데스크톱 실행 기반

- [x] 1.1 Electron 구성과 앱 식별자·버전·Windows NSIS x64 사용자별 설치 설정을 추가하고 Windows에서 빌드 및 패키지 생성이 가능한지 확인한다. 기존 macOS 패키징·업데이트·릴리스 검사·CI 설정과 관련 테스트를 제거하고 운영 문서도 Windows 전용 범위와 맞춘다. 프로젝트 전용 npm/Node 명령을 사용한다.
- [ ] 1.2 Windows x64 Node 런타임·백엔드·OpenSpec CLI와 의존성을 포함하고, 시스템 Node 및 소스 체크아웃 없는 Windows 환경에서 `node:sqlite` 초기화와 OpenSpec 조회를 검증한다.
- [x] 1.3 동봉 Node·CLI·리소스 절대 경로 해석을 연결하고 한글·공백 경로 테스트로 확인한다. 패키징 경로 계약을 개발 문서에 기록한다.

## 2. 로컬 서비스와 영속 데이터

- [x] 2.1 프런트 정적 빌드와 API·스트리밍을 앱 전용 loopback 게이트웨이로 연결하고, 실제 포트 bind·서비스 준비·실패 재시도를 통합 테스트한다.
- [x] 2.2 사용자 데이터 디렉터리에 DATA_DIR·CONFIG_PATH·로그를 분리하고, 재실행·프로젝트 미등록·읽기 전용 설치 폴더에서 데이터 생성과 복구를 검증한다.
- [x] 2.3 프로필별 단일 인스턴스와 세션 소유 잠금을 추가하고, 중복 실행·시작 실패 시 앱 소유 자식만 정리·기존 13001~13003 서버 공존을 검증한다.
- [x] 2.4 앱 전용 API 인증과 렌더러 격리·최소 IPC를 적용하고, 잘못된 인증·발신자·외부 탐색 요청 거절 및 정상 스트리밍을 테스트한다.
- [ ] 2.5 프로젝트 등록·AI CLI 준비·데이터 위치·기존 웹 환경과의 분리 안내를 작성하고, 설치 후 안내대로 첫 업무를 여는지 확인한다.

## 3. 창 종료와 세션 보호

- [x] 3.1 Windows 트레이·창 재열기·명시적 종료를 연결하고, 실행·연결·질문·승인 대기별로 창 닫기 후 세션 유지와 종료 보류가 동작하는지 테스트한다.
- [x] 3.2 전체 업무 상태 판정과 신규 실행 수락을 조정하는 설치 전환 잠금을 구현하고, 새 요청 경합·상태 조회 실패·종료 실패 시 설치 차단을 테스트한다.
- [x] 3.3 정상 종료·일관된 SQLite 백업·실패 복구 절차를 추가하고, 백업 복원으로 업무 및 대화 식별자가 유지되는지 검증한다. 종료와 복구 안내를 문서화한다.

## 4. GitHub 업데이트

- [x] 4.1 `sklee385/open_spec_dashboard`를 명시한 업데이트 소스와 버전 비교를 연결하고, OS·아키텍처에 맞는 높은 정식 버전만 선택하며 낮은 버전·초안·사전 릴리스를 제외하는지 테스트한다.
- [x] 4.2 시작·주기·수동 확인 및 자동 다운로드 상태를 연결하고, 진행률·오프라인·호출 제한·다운로드 실패·재시도를 테스트한다.
- [x] 4.3 개인용 미서명 배포 정책과 메타데이터·SHA-512 검증을 적용하고, 명시적 개인용 빌드만 업데이트를 활성화하며 변조 파일·다른 저장소·불완전 산출물을 차단하는지 테스트한다.
- [ ] 4.4 재시작 설치 선택과 업무 종료 대기 화면을 연결하고, 자동 종료 설치가 꺼져 있으며 사용자 요청과 유휴 상태가 모두 충족될 때만 설치되는지 검증한다. 업데이트 안내를 문서화한다.

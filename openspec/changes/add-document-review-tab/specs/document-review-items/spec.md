# Spec Delta

## Purpose

AI 또는 사용자가 변경 문서에 명시한 검토 항목을 한곳에 모아 요구사항의 가정과 미결정 사항을 확인하고 원문으로 이동하도록 한다. 문서가 갱신되어도 최신 항목을 확인하며 실제 검토 완료는 기존 업무 절차를 따른다.

## ADDED Requirements

### Requirement: 변경별 검토 항목 조회
시스템은 변경 상세의 문서 탭 옆과 업무 공간에서 사용자 검토 탭을 제공하고, 해당 변경의 제안서·설계·명세·작업 목록에 명시된 검토 항목만 표시해야 한다(SHALL). 항목은 문서 경로, 위치, 종류와 본문을 포함해야 한다(SHALL).

#### Scenario: 여러 문서의 항목 조회
- **WHEN** 사용자가 검토 탭을 연다
- **THEN** 해당 변경의 명시적 검토 항목이 문서별로 표시되고 다른 변경의 항목은 포함되지 않는다

### Requirement: 명시적 표기와 기존 문서 호환
시스템은 공개된 검토 항목 표기 규약에 따라 사용자 확인·가정·미결정·선택 항목을 추출해야 한다(SHALL). 작성 주체에 따라 추출 결과를 다르게 처리하거나 규약 없는 문장과 일반 작업 체크박스에서 항목을 추측해서는 안 된다(MUST).

#### Scenario: 규약 없는 기존 문서
- **WHEN** 문서에 일반 작업 체크박스만 있고 검토 표기가 없다
- **THEN** 시스템은 추측한 항목을 추가하지 않고 항목 없음과 표기 안내를 표시한다

#### Scenario: 코드 예제에 포함된 검토 표기
- **WHEN** 코드 블록 안에 표기 규약의 예제가 존재한다
- **THEN** 시스템은 예제를 실제 검토 항목으로 추출하지 않는다

### Requirement: 원문 연결과 최신 내용
시스템은 항목에서 해당 문서 위치로 이동할 수 있게 해야 하며(SHALL), 저장된 문서 변경 후 목록을 다시 조회하여 최신 상태를 표시해야 한다(SHALL). 미저장 편집을 이동 때문에 폐기해서는 안 된다(MUST).

#### Scenario: 원문 수정 후 항목 갱신
- **WHEN** 검토 항목이 저장된 문서에서 수정되거나 삭제된다
- **THEN** 목록에 수정된 내용이 반영되거나 해당 항목이 제거된다

#### Scenario: 미저장 편집 중 원문 이동
- **WHEN** 미저장 편집이 있는 사용자가 다른 문서의 검토 항목을 선택한다
- **THEN** 기존 저장·폐기·이동 취소 선택으로 초안을 보호한다

### Requirement: 빈 목록과 실패 구분
시스템은 조회 중·항목 없음·조회 실패를 구분하고 실패 시 재시도를 제공해야 한다(SHALL). 문서 일부를 읽지 못한 경우 완전한 빈 목록인 것처럼 표시해서는 안 된다(MUST).

#### Scenario: 일부 문서 접근 실패
- **WHEN** 검토 목록을 구성하는 문서 일부를 읽지 못한다
- **THEN** 시스템은 읽지 못한 문서를 알리고 재시도를 제공한다

### Requirement: 검토 절차 독립성
시스템은 검토 목록 조회와 원문 이동으로 업무의 검토 버전을 갱신하거나 구현을 시작해서는 안 된다(MUST). 초기 버전은 항목별 승인 상태를 저장하지 않고 문서 수정과 기존 질문·답변으로 검토를 진행해야 한다(SHALL).

#### Scenario: 검토 탭 열람 후 업무 상태
- **WHEN** 사용자가 항목을 모두 열람한 뒤 탭을 닫는다
- **THEN** 업무의 검토 완료 상태와 구현 실행 상태는 자동 변경되지 않는다

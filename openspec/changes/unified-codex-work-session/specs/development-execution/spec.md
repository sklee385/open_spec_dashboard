# Spec Delta

## Purpose

사용자가 업무 화면에서 Codex의 실제 개발 실행과 추가 지시, 검증 결과 및 완료 처리를 확인할 수 있게 하여 개발 전 과정에서 외부 도구로 이동해야 하는 불편을 해소한다.

## ADDED Requirements

### Requirement: 명시적 구현 시작
시스템은 필요한 OpenSpec 계획 문서의 준비 및 사용자 검토 완료 후 구현 시작 동작을 제공해야 한다(SHALL). 문서 생성 또는 아이디어 전환만으로 구현을 시작해서는 안 된다(MUST).

#### Scenario: 준비된 계획에서 구현 시작
- **WHEN** 사용자가 준비된 문서를 검토하고 구현 시작을 선택한다
- **THEN** 시스템은 연결된 프로젝트에서 기존 Codex 대화를 사용하여 구현을 실행한다

#### Scenario: 계획이 준비되지 않은 상태
- **WHEN** 필요한 계획 문서가 없거나 재검토가 필요한 상태에서 구현 시작을 요청한다
- **THEN** 시스템은 실행하지 않고 필요한 문서 또는 검토 상태를 표시한다

### Requirement: 실행 상태와 결과의 실시간 표시
시스템은 실행 중 메시지·도구 진행 상황·수정 파일·명령 결과를 업무 화면에 제공하고 성공·실패·중단 상태를 구분해야 한다(SHALL).

#### Scenario: 명령 실패
- **WHEN** 개발 중 실행한 명령이 실패한다
- **THEN** 시스템은 종료 상태와 오류를 표시하고 업무를 성공이나 완료로 자동 처리하지 않는다

### Requirement: 추가 지시와 중단 후 재개
시스템은 같은 업무에서 추가 지시를 전달하고 실행을 중단하거나 이후 재개할 수 있게 해야 한다(SHALL). 동일 업무에서 서로 충돌하는 실행을 동시에 시작해서는 안 된다(MUST).

#### Scenario: 실행 중 추가 지시
- **WHEN** 사용자가 진행 중인 업무에 추가 지시를 입력한다
- **THEN** 시스템은 같은 대화의 실행에 지시를 전달하거나 대기열에 넣고 처리 상태를 표시한다

#### Scenario: 중단 후 재개
- **WHEN** 사용자가 실행을 중단한 뒤 다시 진행을 요청한다
- **THEN** 시스템은 기존 변경 파일과 같은 대화를 유지한 채 후속 작업을 실행한다

### Requirement: 검증 근거와 완료 판정
시스템은 검증 항목마다 통과·실패·미검증 상태 및 실제 실행 결과를 제공해야 한다(SHALL). 모든 작업 완료, 미답변 필수 질문 없음, 계획 재검토 없음, 필수 검증 통과와 사용자 완료 확인을 충족해야 업무를 완료로 처리한다(MUST).

#### Scenario: 검증 실패 또는 미검증 존재
- **WHEN** 코드 작성이 끝났지만 필수 검증이 실패하거나 실행되지 않았다
- **THEN** 시스템은 완료 처리를 막고 남은 검증과 같은 세션에서의 수정·재검증 동작을 제공한다

#### Scenario: 최종 확인 후 완료
- **WHEN** 모든 완료 조건이 충족되고 사용자가 결과를 확인하여 완료를 선택한다
- **THEN** 시스템은 완료 상태와 근거를 저장하고 OpenSpec 보관 동작을 제공한다

### Requirement: 변경 이후 검증 무효화
시스템은 검증 후 관련 코드나 명세가 변경되면 기존 검증을 과거 결과로 표시하고 새 필수 검증을 요구해야 한다(MUST).

#### Scenario: 검증 통과 후 코드 추가 수정
- **WHEN** 통과한 검증 이후 코드가 다시 수정된다
- **THEN** 시스템은 이전 통과를 최종 완료 근거로 사용하지 않고 재검증 필요 상태를 표시한다

### Requirement: 보관 결과 확인
시스템은 사용자가 완료된 변경의 보관을 요청하면 OpenSpec 보관과 기준 명세 반영 결과를 확인해야 한다(SHALL). 실패 시 완료 상태와 보관 실패를 구분하고 재시도를 제공해야 한다(MUST).

#### Scenario: 보관 중 오류
- **WHEN** 완료된 업무를 보관하는 과정에서 OpenSpec 명령이 실패한다
- **THEN** 시스템은 보관 완료로 표시하지 않고 오류와 재시도 기능을 제공한다

### Requirement: Codex 준비 상태와 실행 경계
시스템은 Codex 설치·인증·연결 오류를 표시하고 복구 후 같은 업무를 재개할 수 있어야 한다(SHALL). 실행 위치는 연결된 프로젝트로 제한하고 Codex의 권한 승인 절차를 UI에 전달해야 한다(MUST).

#### Scenario: 인증 또는 연결 문제
- **WHEN** Codex를 사용할 수 없어 실행 요청을 처리하지 못한다
- **THEN** 시스템은 준비 필요 상태를 표시하고 업무와 기존 대화 연결을 유지한다

# Spec Delta

## Purpose

아이디어와 OpenSpec 변경을 하나의 업무 세션에 연결하여 사용자가 단계마다 도구를 옮기거나 맥락을 다시 설명하지 않고 개발 완료까지 진행하도록 한다.

## ADDED Requirements

### Requirement: 아이디어에서 업무 생성
시스템은 선택한 프로젝트의 아이디어를 업무 세션과 OpenSpec 변경에 연결하고 출처를 보존해야 한다(SHALL). 같은 전환 요청의 재시도는 동일한 업무를 반환해야 한다(MUST).

#### Scenario: 아이디어를 다음 단계로 전환
- **WHEN** 사용자가 프로젝트의 아이디어를 선택하여 업무 시작을 요청한다
- **THEN** 시스템은 아이디어 출처, 프로젝트, 변경, 업무 세션의 연결을 저장하고 작업 화면을 연다

#### Scenario: 전환 요청 재시도
- **WHEN** 이미 처리한 전환 요청을 다시 받는다
- **THEN** 시스템은 중복 변경이나 세션을 만들지 않고 기존 업무를 반환한다

### Requirement: 업무 전 과정의 동일 세션 유지
시스템은 아이디어 구체화, 질의응답, 문서 작성·수정, 구현, 검증·완료를 같은 업무 세션과 같은 Codex 대화로 진행해야 한다(SHALL). 단계 이동으로 대화를 새로 생성해서는 안 된다(MUST).

#### Scenario: 문서 작성에서 구현으로 이동
- **WHEN** 사용자가 문서 검토를 끝내고 같은 업무의 구현을 시작한다
- **THEN** 시스템은 기존 Codex 대화에서 결정 사항과 문서 맥락을 이어 사용하며 단계만 변경한다

#### Scenario: 검증 후 수정 요청
- **WHEN** 검증 결과를 확인한 사용자가 추가 수정을 요청한다
- **THEN** 시스템은 같은 업무와 Codex 대화에서 수정과 재검증을 진행한다

### Requirement: 모든 단계의 AI 문답과 반복 수정
시스템은 아이디어, 문서 작성·수정, 구현, 검증 및 완료 검토의 모든 단계에서 같은 AI 대화로 질문·답변·수정 요청을 주고받고 관련 문서 또는 결과물을 반복 수정할 수 있어야 한다(SHALL). 사용자 검토 전 생성 결과만으로 구현 시작이나 최종 완료를 확정해서는 안 된다(MUST).

#### Scenario: 문서 작성 중 문답으로 내용 수정
- **WHEN** 사용자가 문서 초안에 수정 의견을 전달하고 AI의 확인 질문에 답한다
- **THEN** 시스템은 같은 대화에서 답변을 문서에 반영하고 사용자가 결과를 확인한 뒤 다시 수정을 요청할 수 있게 한다

#### Scenario: 검증과 완료 검토 중 결과물 수정
- **WHEN** 사용자가 검증 결과 또는 완료 검토 화면에서 AI에 질문하거나 수정 의견을 전달한다
- **THEN** 시스템은 같은 대화와 업무에서 답변하고 결과물을 수정하며 필요한 재검토와 재검증을 거쳐 완료 확인을 받는다

### Requirement: 세션 재연결과 복구
시스템은 새로고침 및 서버 재시작 후 저장된 업무와 Codex 대화를 복원해야 한다(SHALL). 복원 실패 시 기존 연결을 보존하고 복구 오류와 재시도를 제공하며 새 대화로 조용히 대체해서는 안 된다(MUST).

#### Scenario: 서버 재시작 후 이어서 작업
- **WHEN** 사용자가 재시작 후 기존 업무를 연다
- **THEN** 시스템은 기존 대화를 재연결하고 대화·결정·문서·실행 상태를 복원한다

#### Scenario: 대화 복원 실패
- **WHEN** 연결된 Codex 대화를 찾거나 재개할 수 없다
- **THEN** 시스템은 복구 필요 상태와 재시도 기능을 표시하고 기존 대화 식별자를 유지한다

### Requirement: 통합 작업 화면
시스템은 같은 업무 화면 안에서 대화·질문, 관련 문서, 현재 단계, 실행 진행 상황, 코드 변경과 검증 결과에 접근할 수 있어야 한다(SHALL).

#### Scenario: 외부 도구 이동 없이 업무 진행
- **WHEN** 사용자가 아이디어를 구체화하고 문서를 수정한 뒤 개발 결과를 확인한다
- **THEN** 시스템은 해당 업무 화면 안에서 각 기능과 다음 단계 동작을 제공한다

### Requirement: 업무와 프로젝트 간 격리
시스템은 각 업무의 프로젝트 경로와 대화 연결을 고정하고 다른 업무의 문서·질문·실행 결과를 섞지 않아야 한다(MUST).

#### Scenario: 다른 프로젝트의 업무 열기
- **WHEN** 사용자가 다른 프로젝트의 업무로 이동한다
- **THEN** 시스템은 선택한 업무의 대화와 자료만 표시하고 실행 위치도 해당 프로젝트로 제한한다

### Requirement: OpenSpec 진행 정보와 다음 동작
시스템은 업무 화면에서 연결된 변경의 산출물 상태·의존성·차단 원인, 다음 작성 지침, 작업 진행률과 적용 워크플로 정보를 제공해야 한다(SHALL). 사용할 수 없는 CLI 기능이나 조회 오류는 숨기거나 정상 상태로 대체하지 않고 표시해야 한다(MUST).

#### Scenario: 다음 산출물이 차단됨
- **WHEN** 사용자가 아직 준비되지 않은 산출물을 확인한다
- **THEN** 화면에 미충족 의존성과 먼저 작성할 산출물 및 해당 작성 동작이 표시된다

### Requirement: OpenSpec 명세 비교와 진단
시스템은 업무 화면에서 기준 명세·변경 명세 및 요구사항별 차이를 확인하고 OpenSpec 검증과 관계 진단 결과를 조회할 수 있게 해야 한다(SHALL). OpenSpec 문서 검증 결과는 코드 실행 검증 결과와 구분해야 한다(MUST).

#### Scenario: 변경 검토 중 명세 차이와 오류 확인
- **WHEN** 사용자가 명세 비교·검증·관계 진단을 요청한다
- **THEN** 시스템은 해당 변경과 프로젝트 범위의 실제 결과와 오류를 표시하고 같은 대화에서 수정 요청을 이어갈 수 있게 한다
